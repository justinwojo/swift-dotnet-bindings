**Date:** 2026-04-14

**Master scope:** Everything from current state through NuGet publish. Consolidates

## 1. Executive summary

SDK 0.8.0 delivers Apple framework bindings (StoreKit 2, WeatherKit, TipKit,
CryptoKit, …) as NuGet packages for .NET iOS / MAUI apps. `Microsoft.iOS` is an
ObjC binding generator with no Swift-first story; that gap is what this release
fills.

Where we are as of 2026-04-14:

- **Apple-framework packaging infrastructure** (multi-TFM nupkg layout,
  SwiftBindings.Sdk `SwiftAppleFrameworkTarget`, second-slice wrapper compilation,
  forward-compat rule) is **built and validated**. StoreKit 2, SoundAnalysis,
  CoreSpotlight, AuthenticationServices, RoomPlan are at SHIP.
- **Generator hardening during 0.8.x introduced 6 regressions** across 7 Apple
  frameworks — 4 were previously shipping (Translation, ProximityReader,
  LiveCommunicationKit, FamilyControls). See §6 Phase 1.
- **Apple Swift-only types supplement** is **designed** (see companion doc) but
  **not implemented**. This is the Phase 2 initiative. Full SHIP for Translation /
  ProximityReader / LiveCommunicationKit / FamilyControls / WeatherKit / TipKit /
  CryptoKit depends on it.
- **Stripe suite** is ~18 SB0001 from complete closeout (3 products still BLOCKED:
  StripePayments 6, StripePaymentSheet 10, StripeIssuing 2).
- **BlinkID / BlinkIDUX** are non-functional — 21 items gated on actor-isolated
  method support.

Three phases get us to publish:

1. **Phase 1** — Round-2 generator hardening + SB0001 reductions (Sessions 1–4).
2. **Phase 2** — Implement the Apple Swift-only types supplement.
3. **Phase 3** — Final Apple-framework closeout, pack, validate, publish.

## 2. 1.0 thesis

**Bridge .NET MAUI to Apple's Swift-first platform APIs, plus select third-party
Swift SDKs that fill real gaps.** Measured by what shipping packages exist and
where they run, not by skip percentages.

Skip-rate reduction is over-indexed at the 15.4% range — further reduction has
diminishing returns. The headline is Apple framework coverage and multi-platform
proof.

## 3. Locked-in decisions

All of these are inputs, not options to revisit.

### 3.1 Versioning

- **Apple-framework packages:** `{SDK-major}.{SDK-minor}.{binding-rev}[-preview.N]`.
  Major.Minor mirrors the iPhoneOS SDK version (not Xcode). Patch is our binding
  revision lane. Example: `SwiftBindings.StoreKit2 26.2.0` → `26.2.1` (fix) →
  `26.3.0` (iOS 26.3 SDK) → `27.0.0-preview.1` (Xcode 27 beta).
- **Third-party packages:** version mirrors upstream (`SwiftBindings.Nuke
  12.8.x` = Nuke 12.8.x).
- **`SwiftBindings.Apple` supplement:** per Apple SDK train major (see
  `apple-swift-types-architecture.md` §Package-version invariant). Cross-major
  additive-only; breaking changes ship as a new package name (`SwiftBindings.Apple.v2`),
  not a breaking major.

### 3.2 `SwiftBindings.Runtime` pinning

Bounded `[0.8.0,0.9.0)` — patch releases must be ABI-compatible (no struct layout
changes, no P/Invoke signature changes). Avoids republish tax across every
Apple-framework package on every runtime patch.

### 3.3 TFM in generator-emitted csprojs

Explicit `--platform-version` CLI flag (e.g., `--platform-version 26.2` →
`net10.0-ios26.2` in both `<TargetFramework>` and `buildTransitive/`). Dynamic
`$(TargetPlatformVersion)` resolution was rejected — .NET 10 library projects
default to the oldest installed TPV, producing stale TFMs on multi-workload
machines.

### 3.4 Package layout (multi-TFM)

```
lib/net10.0-ios26.2/SwiftBindings.StoreKit2.dll
lib/net10.0-macos26.2/SwiftBindings.StoreKit2.dll
lib/net10.0-maccatalyst26.2/SwiftBindings.StoreKit2.dll
lib/net10.0-tvos26.2/SwiftBindings.StoreKit2.dll
buildTransitive/net10.0-ios26.2/SwiftBindings.StoreKit2.targets
buildTransitive/net10.0-macos26.2/SwiftBindings.StoreKit2.targets
...
runtimes/ios-arm64/native/StoreKitSwiftBindings.xcframework/...
runtimes/osx-arm64/native/StoreKitSwiftBindings.xcframework/...
...
```

### 3.5 Forward compatibility

Old nupkgs work on newer Apple workloads. Swift ABI stability since 5.0 + .NET 10
TFM precedence rules select older-versioned `lib/` entries + `runtimes/` is
RID-based not TFM-based. Verified with a `26.0 → 26.2` consumer repro.

### 3.6 Naming — framework packages vs. Swift-only-types supplement

Two distinct lanes. Do NOT conflate.

- **Framework packages** keep their current names: `SwiftBindings.StoreKit2`,
  `SwiftBindings.WeatherKit`, `SwiftBindings.TipKit`, `SwiftBindings.CryptoKit`,
  etc. One package per Apple framework. Namespace e.g. `StoreKit2` (NOT `StoreKit`,
  to avoid collision with Microsoft.iOS's ObjC types).
- **Swift-only types supplement** is a separate package: `SwiftBindings.Apple`.
  It hosts newly-generated Apple Swift-only value types that multiple framework
  packages consume (`Foundation.Locale.Language`, `ManagedSettings.Application`,
  `CryptoKit.P256.Signing.ECDSASignature`, etc.). See companion architecture doc.
- **`SwiftBindings.Runtime`** stays SDK-agnostic. Existing legacy canonical types
  (`Foundation.Date`, `Foundation.URL`, `Foundation.Decimal`,
  `Foundation.Measurement<T>`, `ManagedSettings.Token<T>`, `SwiftUI.Text`) remain
  in Runtime indefinitely. Supplement does NOT re-emit them. No `[TypeForwardedTo]`
  migration now — see architecture doc Q2.
- Framework packages reference the supplement via `TypeOwnerRegistry`-driven
  transitive `PackageReference`, pulled only when a consumer actually references
  a supplement-owned Swift identity.

## 5. Testing layers (required per session)

Every session must produce evidence at all three layers before sign-off.

1. **Unit tests** (`nuke test`, ~2 min). Exercise the exact code path changed.
   Focused, fast, assert behavior (not exact strings). Use `[Theory]`/`[InlineData]`
   for input variants.
2. **BindingTests** (`nuke runtime-tests-simulator`, ~3 min; `nuke runtime-tests-device`
   when calling conventions / marshalling change, ~5 min). Swift fixture in
   `BindingTests/Sources/SwiftBindingsTestLib/` (domain-organized, not "phase-N"
   files) + C# runtime test in `BindingTests/RuntimeTestsApp/`. **Only layer that
   catches ABI / calling-convention / marshalling bugs unit tests can't.**
   Mandatory when the change touches generator output or runtime marshalling.
3. **Generator regeneration against the real library.** The generator CLI is the
   final arbiter — unit + BindingTests can pass while a real framework still
   breaks. Mechanism:
   - **Existing smoke opt-ins** (CryptoKit, WeatherKit, TipKit, ProximityReader,
     LiveCommunicationKit, MusicKit, StoreKit, WorkoutKit, RoomPlan):
     `nuke binding-tests --Enable<Name>Smoke`. Dev-loop only; being retired per
     `project_smoke_tests_temporary.md` — **do not add new smoke opt-ins.**
   - **Third-party validation corpus** (`build/validation-libraries.json`):
     `nuke validate --filter <Name>`.
   - **Primary end-to-end gate:** rebuild SDK in place (`nuke pack --version 0.8.0`,
     wipe old same-version nupkgs), drop into `swift-dotnet-packages/local-packages/`,
     clear NuGet caches, rebuild all of swift-dotnet-packages. Automated via
     `reference_build_validate_script.md`.

Zero-regression policy: `.validation-baseline.json` `cs_compile` and `swift_compile`
pass counts, BindingTests runtime pass count, and unit test pass count must all
be equal-or-better than baseline BEFORE committing. No exceptions.

## 6. Phase 1 — Round-2 close-out + generator hardening

**Goal:** Clean up the generator regressions, close out the Stripe suite, unblock
BlinkID/BlinkIDUX, mop up StoreKit2/MusicKit/polish items. After Phase 1, the 7
regressed Apple frameworks **compile with Swift-only-type members *skipped***
(known interim state, documented). Full SHIP comes in Phase 3.

### Step 0 — Revert Fix A's bogus XML entries

Commit `ee2e9598` added DB entries under `Foundation.FoundationDatabase.xml`
mapping `Foundation.Locale.Language` → `Foundation.LocaleLanguage` and
`Foundation.Locale.Region` → `Foundation.LocaleRegion`. Those C# types don't exist
in the iOS workload; emission now references nonexistent types and fails 22 CS0234
errors per consumer. Revert the entries. Baseline behavior becomes "members
skipped" (which matches the other Locale nested types like `Locale.Currency` that
are valueTypes-only in `apple-frameworks.json`). The real fix lands in Phase 3
via the supplement.

### Session 1 — Generator regressions B, C, D, E, F

**Skipped from original scope:** Fix A (deferred to Phase 3 via supplement);
SIMD alias wiring (resolved by c28e532a); all 6 code-review correctness items
(resolved by c28e532a — `git show c28e532a` confirms).

Unblocks the *compilation* of Translation, ProximityReader, LiveCommunicationKit,
FamilyControls, WeatherKit, TipKit, CryptoKit. Swift-only-type members stay
skipped at end of Session 1; Phase 3 brings them back via the supplement.

#### Regression B — Cross-module imports + underscore-SPI filter

**Subsystem:** Swift wrapper emitter.

Two halves:

1. FamilyControls wrappers reference `ManagedSettings.{ApplicationToken,
   ActivityCategoryToken, WebDomainToken, Application, ActivityCategory,
   WebDomain}` (10 distinct) but the wrapper file only imports
   `FamilyControls, Foundation, Combine, SwiftUI`. Error: `cannot find type
   'ManagedSettings' in scope`. **Fix:** wrapper emitter walks every type reference
   in the generated file and adds each referenced module's root name to the
   `import` list.
2. WeatherKit wrapper emits `_LocationEssentials.CLLocation` — `_LocationEssentials`
   is an underscore-prefixed SPI module not exported from CoreLocation's public
   headers. **Fix:** filter underscore-prefixed module names during type
   resolution; fall back to the public module (`CoreLocation.CLLocation`).

**Example (FamilyControls.Wrapper.swift):**

```swift
resultPtr.initializeMemory(as: Swift.Set<ManagedSettings.ApplicationToken>.self, repeating: result, count: 1)
// Compile error — no `import ManagedSettings`
```

#### Regression C — `Self.AssocType` in `@_cdecl` wrapper (TipKit)

**Subsystem:** Swift wrapper emitter.

`Self.Action` / `.Rule` / `.Status` inside protocol-extension wrappers don't
resolve in `@_cdecl` context. Error: `'Action' is not a member type of type 'Self'`.

Preferred fix: rewrite `Self.AssocType` → `any Tip.AssocType` when emitting inside
a protocol-extension wrapper. Fallback: skip the member (adds SB0001). Start with
preferred; fall back if `any Tip.Action` doesn't type-check across all three
associated types.

**Example (TipKit.Wrapper.swift:212):**

```swift
public var actions: Swift.Array<Self.Action> {
    get {
        var selfProto: TipKit.Tip = self
        let resultPtr = _tip_vtable.func_actions_get!(_tip_vtable.csVTHandle, &selfProto)
        return resultPtr.assumingMemoryBound(to: Swift.Array<Self.Action>.self).pointee
    }
}
```

#### Regression D — `@available` propagation onto wrappers

**Subsystem:** Swift wrapper emitter.

CryptoKit `SHA3_256Digest` (iOS 26+) and TipKit `Tips` (iOS 17+) wrappers don't
carry `@available` attrs, so they fail at the library's deployment target.

**Fix:** propagate `@available(...)` from Swift source onto the emitted `@_cdecl`
wrapper. The parser already carries availability (used for `[UnsupportedOSPlatform]`
on the C# side) — plumb the same into wrapper Swift-side emission.

**Example (CryptoKit.Wrapper.swift:1191):**

```swift
extension CryptoKit.SHA3_256Digest : CryptoKit.Digest { }
// SHA3 types require iOS 26.0+; deployment target is iOS 15.0
```

#### Regression E — Async multi-return overload scope (WeatherKit macOS/maccatalyst)

**Subsystem:** C# emitter. 424 `CS0246: The type or namespace name 'TT1' could not
be found` per TFM.

Emitter interleaves `WeatherAsync<TT1, TT2, ...>` helpers between single-`T` and
non-generic declarations, putting tuple type params out of scope.

**Fix:** group generated overloads by method signature so the generic-param
declaration and its consumers stay contiguous. Investigate `MethodHandler` /
`AsyncMethodEmitter` ordering. iOS is masked by Regression B (fails first) —
fixing B will expose this there too.

#### Regression F — `.SwiftHandle` on nested non-`ISwiftObject` structs (CryptoKit macOS)

**Subsystem:** C# emitter. 38 `CS1061: 'P256.Signing.ECDSASignature' does not
contain a definition for 'SwiftHandle'` per TFM.

`P256/P384/P521.Signing.ECDSASignature` are nested blittable structs.

**Fix:** the nested-struct marshal path must check `implementsISwiftObject` before
emitting `.SwiftHandle`. Without conformance, use the frozen-struct marshal path
(pass by value / `fixed` pointer).

#### Session 2 — Done (Patterns A + B)

Commit `eed2a1c0` — 11 files, +517/−156. Landed through the MethodClosureBridge
(MCB) `IsClosureArgSupported` / `IsEligible` gate + the Swift-side `@_cdecl`
emission branch. No changes to `ClosureHandler` or `AsyncMethodEmitter`.

**Pattern A — `(any Error)?` as a closure argument.**
Matches `PaymentSheet.FlowController.update(…, completion: ((any Error)?) -> Void)`
and the trailing slot of multi-arg completions like
`(Int32, Int32, (any Error)?)` (stand-in for
`(STPIssuingCardPin?, STPPinStatus, (any Error)?)`; Optional-class/Optional-Int
in closure args are a separate follow-up).

**Pattern B — `Result<T, any Error>` as a closure argument.**
Matches `(Result<PaymentSheet.FlowController, any Error>) -> Void`. The Swift
adapter wraps the `Result` enum with `withUnsafePointer(to:)`; the C# side
heap-copies via `SwiftResult<T, ExistentialContainer1>.NewFromPayload(IntPtr)`
owned by a `SafeHandle`.

Key implementation notes for future patterns:

- **Helpers added in `MethodClosureBridge.cs`:**
  - `IsAnyErrorExistential(TypeSpec)` — pre-existing, reused
  - `IsOptionalAnyErrorExistential(TypeSpec)` — new
  - `IsSwiftResultWithAnyErrorFailure(TypeSpec)` — new, checks
    `named.Name == "Swift.Result"`, `GenericParameters.Count == 2`, failure arg
    is `any Error`
- **Gate site:** both `IsClosureArgSupported` and `IsEligible` must accept the
  new shape *before* the `TryGetTypeRecord` gate (existentials have no TypeRecord).
- **Swift-side emission for Optional existential:**
  ```swift
  if let __val0_0 = __p0_0 {
      withUnsafePointer(to: __val0_0) { __ptr0_0 in
          cdecl(UnsafeMutableRawPointer(mutating: __ptr0_0), callbackContext)
      }
  } else {
      cdecl(nil, callbackContext)
  }
  ```
  Factored into `EmitCdeclInvocation(baseIndent, optOverrides)` local helper so
  the two branches share a single invocation template.
- **C# marshal branches in `EmitArgMarshal`:**
  ```csharp
  else if (IsOptionalAnyErrorExistential(argType))
      csWriter.WriteLine($"global::Swift.AnyError? __a{index} = __p{index} == IntPtr.Zero "
          + $"? null : new global::Swift.AnyError(*(global::Swift.Runtime.ExistentialContainer1*)__p{index});");
  else if (IsSwiftResultWithAnyErrorFailure(argType))
      csWriter.WriteLine($"var __a{index} = SwiftMarshal.MarshalFromSwift<{csharpType}>(__p{index});");
  ```
  **Use `MarshalFromSwift` — NOT `MarshalBorrowedFromSwift` — for Result.**
  `SwiftResult(IntPtr)` constructor heap-allocates and runs
  `metadata.ValueWitnessTable->InitializeWithCopy`, so the `SafeHandle` owns a
  fresh buffer. Suppressing finalization (what `Borrowed` does) would leak that
  buffer. This distinction matters and tripped review.
- **`SwiftBuilder.GetSwiftCdeclParamType`** — added `Optional<any Error>` →
  `UnsafeMutableRawPointer?` so the Swift `@_cdecl` signature uses the
  Optional-pointer-nil ABI (caller passes `nil`, C# sees `IntPtr.Zero`).
- **Multi-Optional<any Error> gate (Codex feedback).** `IsEligible` counts
  `Optional<any Error>` closure args and early-rejects `count >= 2`. Without this,
  the emitter accepts the signature in the gate but throws `InvalidOperationException`
  mid-emission. Unit test: `IsEligible_ClosureWithMultipleOptionalAnyErrorArgs_ReturnsFalse`.
  `NamedTypeSpec` has `params TypeSpec[]` — construct as
  `new NamedTypeSpec("Swift.Optional", errorExistential)`, not a `List<TypeSpec>`.

BindingTests added in `BindingTests/RuntimeTestsApp/ErrorHandling/AnyErrorDescriptionTests.cs`
and the matching fixture `AnyErrorCallbackFixture.swift` — Pattern A success /
failure, Pattern A 3-arg `(Int32, Int32, (any Error)?)` success / failure,
Pattern B success / failure. All read `LocalizedDescription` *inside* the
callback — borrowed-container lifetime is the callback duration only.

Gates passed at commit time: `nuke test`, `nuke validate` 95/95,
`nuke runtime-tests-simulator` 1413/1413. Device gate still owed.

#### Session 2 — Done (Patterns C / D / E + outlier)

Branch `sb-worktree`, 9 commits on top of `eed2a1c0`. Closed the remaining 14
Stripe SB0001 items plus NativeAOT device-test regressions surfaced by the
device gate.

**Pattern C — `Swift.String` as a non-closure MCB param** (commit `11926fc9`).
Extended `MethodClosureBridge.ClassifyParam` with a new `Utf8Slice` category.
C# pins the UTF-8 bytes via `fixed (byte* __ptr = …)` and passes `(IntPtr, nint)`;
the Swift `@_cdecl` adapter rebuilds the `String` via `UnsafeBufferPointer`.
No payload buffer allocation.

**Pattern D — `Func<Task<T>>` async factory initializers** (commit `d2eaa6ea`).
Root cause: `WrapperValidation.HasNonBlittablePInvokeTypes` checked TypeSpec
blittability on the source signature, but async methods always route through a
Swift-side wrapper (`@_silgen_name` or `@_cdecl`) that converts non-blittable
params to `UnsafeRawPointer`. The emitted C# P/Invoke is uniformly blittable
(`callback / errorCallback / taskId + IntPtr + delegate*`), so CallConvSwift is
ABI-stable on both Mono and NativeAOT. Fix: `if (env.MethodDecl.IsAsync) return false;`
early-return at the top of the predicate.

**Pattern E — protocol existential params in async methods** (commit `c4a97cdb`).
`MethodHandler`'s `asyncCdeclEligible` was rejecting any param that hit
`CdeclParamMapper.IsProtocolExistentialType`. Lifted that rejection — the async
wrapper marshals existentials as `UnsafeRawPointer` to the `ExistentialContainer1`
heap allocation. `WrapperEmitter.Async.cs` reconstruction-line detection was
also loosened to match both `let nameVal ` and `let nameVal:` (existential path
emits the typed form).

**Outlier — `EmbeddedPaymentElementWillPresent` + simple-enum / Optional<Class>
closure args** (commit `4f71b89d`). Extended MCB `IsCdeclCompatibleClosureArgType`
to admit `Optional<Class/ObjC>` (nil-pointer ABI) and simple enums with numeric
raw values (passed as underlying scalar via `.rawValue`). `EmitArgMarshal` got
matching C# callback-side branches.

**Supporting gate fixes** that fell out during the work:

- `576abb76` — `@_silgen_name` free-function wrappers exempted from SB0001:
  C# calls them with CallConvSwift matching the wrapper's swiftcc, not a
  mismatch.
- `6fd48e5f` — SB0001 skipped when every P/Invoke type is already blittable
  (CallConvSwift on blittable signatures is ABI-stable).
- `f34a9288` — `GetSafetyObsoleteAttribute` (propagated onto completion-handler
  Async overloads) now uses the same AND-gate as the main emitter, so async
  overloads of blittable methods don't reattach spurious SB0001.
- `b53090f5` — NativeAOT device-test regressions: `Measurement<T>` field
  offsets corrected (`{ unit; value }`, not `{ value; unit }`), generic unit
  metadata routed through `swift_getObjCClassMetadata`, bound-generic
  `NewFromPayload` factory registered via new `TypeMetadata.RegisterAndGetSize`
  helper so `MarshalFromSwift` is trim-safe without reflection fallback.

#### Key takeaways for future sessions

- **SB0001 is an AND-gate, not an OR-gate.** A method only has real Mono JIT
  risk when it has no wrapper AND its P/Invoke signature contains non-blittable
  types. Any new gate site must check both; there are three sites (main emitter,
  async-cdecl eligibility, completion-handler propagation) — keep them in sync.
- **Async always has a wrapper.** Any future SB0001 logic should short-circuit
  on `IsAsync` — the async wrapper always normalizes param types.
- **MCB two-layer gate** (`IsSupportedClosureParameterType` + `IsCdeclCompatibleType`)
  still applies; extend both when adding a new supported shape.

### Session 3 — Actor-isolated methods (BlinkID, BlinkIDUX)

**Fixes:** Wrappers for methods on Swift `actor` types (not just `nonisolated`
members — round-1 Fix 13 covered those).

**Unblocks:** BlinkID (10→0), BlinkIDUX (11→1 — defer `BlinkIDEventStream.stream`).
Both libraries are non-functional without this. **Standalone session** — new
infrastructure, don't pile more on.

#### Architecture

Session 3 (round 1, Fix 13) unblocked only `nonisolated` actor members. The 21
remaining BlinkID/BlinkIDUX items are **isolated** — they must hop onto the
actor's executor before executing, so from any non-actor caller they are
semantically async. Implementation:

1. **Detect:** `ClassDecl.IsActor && !method.IsNonisolated && !method.IsMainActorIsolated`
   → actor-isolated method.
2. **Swift wrapper:** emit `@_cdecl` whose body is
   `Task { await self.method(...); callback(result) }`. Reuses the callback-based
   async surface.
3. **C# side:** `Task<T>` wrapper awaits the callback (already exists from async
   pipeline).
4. **`@MainActor` methods:** dispatch through `Task { @MainActor in ... }`. Check
   existing `MainActorTests.cs` — likely partial coverage; extend rather than redo.

#### Risks

- **Actor instance lifetime across the async gap.** Retain in the wrapper via
  `SafeHandle` — existing pattern.
- **Deferred: `ActorIsolatedAsyncStream` — BlinkIDUX `BlinkIDEventStream.stream`.**
  A plain (non-async) getter on a Swift `actor` returning `AsyncStream<[UIEvent]>`.
  Session 3's Fix 13 (round 1) unblocked explicit `nonisolated` members only.
  Actor-isolated stream properties need async-dispatch-through-executor wrapping
  (new infrastructure beyond Session 3's scope). Log as post-ship.

## 7. Phase 2 — Apple Swift-only types supplement

**Goal:** Implement the supplement architecture per
[`apple-swift-types-architecture.md`](apple-swift-types-architecture.md). After
Phase 2, the generator can emit references to `SwiftBindings.Apple` for Swift-only
Apple types that today force member skips.

No hard 0.8.0 deadline on this phase — pace for correctness. The design doc is
the authoritative spec; this section only enumerates the implementation milestones.

### 7.1 Implementation milestones

1. **Metadata manifest format.** Design the JSON/binary schema for the third
   artifact (accessor symbols, size/alignment, VWT pointers, conformance descriptor
   names, availability). Store under `src/Swift.Bindings.Sdk/tools/apple-types-manifest/`.
   Design schema so it can later migrate to a standalone `SwiftBindings.Apple.Metadata`
   data package without format changes.
2. **Manifest generator.** Build the Apple-SDK ABI-JSON → manifest pipeline.
   Driven by the same ABI JSON the generator already consumes for framework packages.
3. **`SwiftBindings.Apple` package skeleton.** New project under
   `src/Swift.Bindings.Apple/` emitting a monolithic assembly targeting all four
   Apple TFMs. CI builds the assembly from the manifest on every commit.
4. **VWT-backed opaque storage emission.** Extend the emitter to produce
   VWT-backed storage by default for supplement-owned types. Per-type
   sequential-layout whitelist behind a gated flag (requires size/alignment
   validated, copy/destroy trivial, runtime round-trip test passing).
5. **`TypeOwnerRegistry` with per-type override precedence.** Implementation:
   1. Per-type owner override first (legacy canonical types pinned to
      `SwiftBindings.Runtime`).
   2. Module default second (Apple modules → `SwiftBindings.Apple`; third-party
      → their generated binding package).
   3. Same-module-being-generated → local.
6. **Generator integration.** Type DB resolver consults `TypeOwnerRegistry`.
   Consumer csprojs emit `PackageReference` to `SwiftBindings.Apple` when the
   registry resolves any referenced type to it.
7. **Demand-driven prototyping mode.** SDK MSBuild targets emit a supplement
   project into `obj/` for prototyping; referenced as a project dependency
   (NOT compiled as duplicate types into each consumer assembly — identity
   must stay canonical).
8. **Cross-module type identity test.** Permanent regression guardrail: two
   consumer assemblies reference the supplement, instantiate a Swift-only type
   in one, pass to the other, assert `typeof(T)` matches.
9. **Framework-linkage blast-radius smoke test.** NativeAOT single-framework
   app — does referencing one framework package pull in other framework binaries
   it doesn't use? If yes, mitigate (lazy P/Invoke, per-module conditional
   symbols, runtime probing) before Phase 3 ship.
10. **CI validation against live SDK.** Smoke test that supplement metadata
    accessor symbols exist on the current Apple SDK, size/alignment match,
    VWT copy/destroy works, optional/container round-trip works.
11. **Bootstrap supplement against the 7 target frameworks.** Discover every
    Swift-only type referenced by Translation, ProximityReader, LiveCommunicationKit,
    FamilyControls, WeatherKit, TipKit, CryptoKit. Populate the manifest.
    Regenerate all 7 — members that Phase 1 skipped should now bind.

### 7.2 Phase 2 deliverable

`SwiftBindings.Apple` package builds, passes CI gates, is referenced by the 7
target Apple framework packages. Generator's demand-driven prototyping mode works
for local iteration.

## 8. Phase 3 — Ship & publish

**Goal:** Close out the 7 Apple frameworks to full SHIP, pack all packages,
validate, publish to nuget.org.

### 8.1 Steps

1. **Regenerate the 7 Apple frameworks.** Against the supplement-aware generator.
   Verify every previously-skipped Swift-only-type member now binds. `nuke validate`
   SB0001 counts for these frameworks should reach their floor (permanent-limit
   items only).
2. **Wire `apple-frameworks/` into swift-dotnet-packages Nuke pipeline.**
   `Build.Xcframework.cs:DiscoverLibraries` extension to handle SDK-sourced
   multi-TFM projects. `BuildLibrary`, `Pack`, `PackValidate`, `BuildAndPackRelease`,
   `ListChangedLibraries` must all see apple-framework packages.
3. **Stripe hardening.** NativeAOT validation across all Stripe sub-products,
   sample app polish, any residual test-coverage gaps.
4. **Pack all packages.** `nuke pack --version 0.8.0` (or `0.9.0` — see §8.2) →
   `SwiftBindings.Sdk`, `SwiftBindings.Runtime`, `SwiftBindings.Templates`,
   `SwiftBindings.Apple`, plus every framework package.
5. **Local-feed regression validation.** Drop nupkgs into
   `swift-dotnet-packages/local-packages/`, clear NuGet caches, rebuild all of
   swift-dotnet-packages on both sim and device. Run the `regression-validation`
   skill (end-to-end Mono JIT simulator + NativeAOT device).
6. **Publish to nuget.org.** All packages.
7. **Commit swift-dotnet-packages.** Only AFTER nuget.org publish succeeds, per
   `feedback_no_commit_packages.md`.

### 8.2 Version-number review

At end of Phase 3, decide 0.8.0 vs 0.9.0:

- **Stay at 0.8.0** if cumulative changes are compatible with 0.8.0's already-
  published lane (runtime ABI unchanged, no framework-package breaking changes).
- **Bump to 0.9.0** if cumulative churn is large enough to warrant it: a new
  `SwiftBindings.Apple` package shipping for the first time, generator internals
  significantly refactored (`TypeOwnerRegistry`, supplement emission),
  runtime ABI touched. Note that 0.8.0's `SwiftBindings.Runtime` pinning
  `[0.8.0,0.9.0)` means any runtime ABI change forces 0.9.0 anyway.

Default bias: bump to 0.9.0. The supplement is a genuinely new artifact and
`Runtime` may pick up non-ABI-trivial changes during Phase 2. Cheaper to bump
than to over-constrain what can land.

## 11. Historical context — what 0.8.x delivered prior to this plan

For context on how we arrived at this state. Not an action list.

### Generator & SDK

- **Apple-framework target mode** — auto-detects when the target module matches a
  built-in dependency database and bypasses it. `swift-api-digester` ABI dumps are
  the metadata source, not wrapper packages.
- **`SwiftAppleFrameworkTarget` MSBuild item** in `SwiftBindings.Sdk` — drives
  ABI dump, generator invocation, wrapper compilation, and NuGet packaging for
  system frameworks.
- **Multi-TFM support** — single nupkg with `lib/`, `buildTransitive/`, and
  `runtimes/` for iOS, macOS, Mac Catalyst, tvOS.
- **`NamespacePattern` metadata** — prevents namespace collision with Microsoft.iOS's
  ObjC types (e.g., `StoreKit` → `StoreKit2`).
- **Second-slice wrapper compilation** — iOS/tvOS xcframeworks get both device and
  simulator slices merged via `xcodebuild -create-xcframework`.
- **Mac Catalyst framework path fallback** — frameworks not in the iOSSupport
  overlay (WeatherKit, CryptoKit) fall back to regular macOS
  `System/Library/Frameworks/`.
- **Foundation `Unit*` → `NSUnit*` remaps** — 24 mappings.
- **Enum helper `@available` annotations** — synthesized `@_cdecl` wrappers inherit
  availability from parent type chain.
- **Availability propagation — property accessors** — `CreatePropertyDecl` /
  `CreateSubscriptDecl` propagate `decl.AvailabilityAnnotations` to every accessor's
  `MethodDecl`. WeatherKit CA1416 warnings 152 → 0.
- **`UnsafeRawBufferPointer` in `@_cdecl` wrappers** — methods with these params
  now skipped with `UnsupportedSignature` (tractable subset). Unblocked CryptoKit
  SHA3/SHA256.
- **Struct/class misclassification for newer ObjC types** — `TryEmitParameterConversionViaProjection`
  no longer emits `.Handle` for `Optional<T>` where `T` is a Swift-native
  struct/enum misclassified as ObjC under AutoBridge. Unblocked AuthenticationServices
  `ASImportableEditableField.Passport`.
- **Duplicate member emission from nested-type collisions** — `FrozenStructHandler`,
  `NonFrozenStructHandler`, `EnumHandler` include sibling nested type names in
  collision set. Unblocked TipKit `Tips.ConfigurationOption` factories.
- **Optional-pointer wrapper with method-own generics** — `MethodHandler` no
  longer routes method-own generics through `OptionalPointerWrapperEmitter`.
  Unblocked CryptoKit `ChaChaPoly.seal`.
- **`Optional<String>` in simple enum extensions** — `EnumHandler.SimpleEnum`
  accepts `Swift.Optional<Swift.String>` returns, emits `string?` with
  `IntPtr.Zero → null` guards. Unblocked `LocalizedError` on simple enums
  (WeatherKit `WeatherError.GetErrorDescription` et al.).
- **TipKit unblock** — PAT/Self-requirement protocol handling, nested-type
  parser guard, BCL delegate/task qualification, per-element `SwiftOptional`
  composition in containers.
- **Runtime tests on non-iOS platforms** — macOS, Mac Catalyst, tvOS Simulator
  runners all operational. NSRunLoop pump fix resolved macOS async timeouts.

### Validated frameworks (as of entering Phase 1)

StoreKit 2, SoundAnalysis, CoreSpotlight, AuthenticationServices, RoomPlan all at
SHIP. WeatherKit, TipKit, CryptoKit at "validated and ready to publish" prior to
the round-2 regressions — Phase 1 restores that state, Phase 2+3 reach full SHIP
with Swift-only-type members bound.

### Foreign value-type metadata

`@_cdecl` accessors for UUID/Date/Decimal in `SwiftBindingsRuntime.swift`.
Co-gater cross-scope stripping fix resolved ~210 orphaned P/Invoke declarations
across Transaction, Storefront, Product.
