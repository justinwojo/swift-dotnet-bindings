# 0.8.0 — Apple Framework Bindings

**Updated**: April 10, 2026

The headline of 0.8.0: bind Apple's Swift-first frameworks (StoreKit 2, WeatherKit, TipKit, etc.) and publish them as NuGet packages for .NET MAUI / .NET iOS apps. These APIs have no .NET binding today. `Microsoft.iOS` is fundamentally an ObjC binding generator and has no story for Swift-first frameworks.

---

## What's done

All generator/SDK/runtime work for the first Apple-framework package is complete:

- **Apple-framework target mode** in the generator — auto-detects when the target module matches a built-in dependency database and bypasses it. `swift-api-digester` ABI dumps are the metadata source, not wrapper packages.
- **`SwiftAppleFrameworkTarget` MSBuild item** in `SwiftBindings.Sdk` — drives ABI dump, generator invocation, wrapper compilation, and NuGet packaging for system frameworks.
- **Multi-TFM support** — single nupkg with `lib/`, `buildTransitive/`, and `runtimes/` for iOS, macOS, Mac Catalyst, and tvOS.
- **`NamespacePattern` metadata** — prevents namespace collision with Microsoft.iOS's ObjC types (e.g., `StoreKit` namespace → `StoreKit2`).
- **Second-slice wrapper compilation** — iOS/tvOS xcframeworks get both device and simulator slices merged via `xcodebuild -create-xcframework`.
- **StoreKit 2 validated end-to-end** — 68 types bound, wrapper compiles, C# compiles, runtime smoke tests pass on iOS Simulator (`AppStore.CanMakePayments`, `Transaction.unfinished` AsyncSequence iteration, `AppStore.DeviceVerificationID` UUID resolution).
- **Foreign value-type metadata** — `@_cdecl` accessors for UUID/Date/Decimal in `SwiftBindingsRuntime.swift`.
- **Co-gater cross-scope stripping fix** — resolved ~210 orphaned P/Invoke declarations across Transaction, Storefront, Product.
- **Mac Catalyst framework path fallback** — frameworks not in the iOSSupport overlay (WeatherKit, CryptoKit) now fall back to the regular macOS `System/Library/Frameworks/` path.
- **Foundation Unit type remaps** — 24 `Unit*` → `NSUnit*` mappings (UnitTemperature, UnitLength, etc.) so generated C# references the correct Microsoft.iOS types.
- **Enum helper `@available` annotations** — synthesized `@_cdecl` wrappers (InitWithRawValue, CaseByIndex) now inherit availability from the enum's parent type chain.
- **SoundAnalysis + CoreSpotlight validated** — build + pack across all 4 TFMs (iOS, macOS, Mac Catalyst, tvOS), ready for NuGet publish.

- [x] **Struct/class misclassification for newer ObjC types** — `TryEmitParameterConversionViaProjection` no longer emits `.Handle` for `Optional<T>` where `T` is a Swift-native struct/enum misclassified as an ObjC type under AutoBridge modules. ## Locked-in decisions

### Versioning

- **Apple-framework packages**: `{SDK-major}.{SDK-minor}.{binding-rev}[-preview.N]`
  - Major.Minor mirrors the iPhoneOS SDK version (not Xcode)
  - Patch is our binding revision lane (bug fixes, generator fixes, runtime bumps)
  - Preview suffix for beta SDKs and pre-release cuts
  - Example: `26.2.0` → `26.2.1` (fix) → `26.3.0` (iOS 26.3 SDK) → `27.0.0-preview.1` (Xcode 27 beta)
- **Third-party packages**: unchanged — version mirrors upstream (e.g., `SwiftBindings.Nuke 12.8.x` = Nuke 12.8.x)

### SwiftBindings.Runtime pinning

Bounded `[0.8.0,0.9.0)` — patch releases must be ABI-compatible (no struct layout changes, no P/Invoke signature changes). Avoids republish tax across every Apple-framework package on every runtime patch.

### TFM in generator-emitted csprojs

Explicit `--platform-version` CLI flag (e.g., `--platform-version 26.2` → `net10.0-ios26.2` in both `<TargetFramework>` and `buildTransitive/`). Dynamic `$(TargetPlatformVersion)` resolution was rejected — .NET 10 library projects default to the oldest installed TPV, which produces stale TFMs on multi-workload machines.

### Package layout (multi-TFM, via SwiftBindings.Sdk)

```
lib/net10.0-ios26.2/SwiftBindings.StoreKit2.dll
lib/net10.0-macos26.2/SwiftBindings.StoreKit2.dll
lib/net10.0-maccatalyst26.2/SwiftBindings.StoreKit2.dll
lib/net10.0-tvos26.2/SwiftBindings.StoreKit2.dll
buildTransitive/net10.0-ios26.2/SwiftBindings.StoreKit2.targets
buildTransitive/net10.0-macos26.2/SwiftBindings.StoreKit2.targets
...
runtimes/ios-arm64/native/StoreKitSwiftBindings.xcframework/...
runtimes/osx-arm64/native/StoreKitSwiftBindings.xcframework/...
...
```

### Forward compatibility

Old nupkgs work on newer Apple workloads — Swift ABI stability since 5.0, .NET 10 TFM precedence rules select older-versioned `lib/` entries, `runtimes/` is RID-based not TFM-based. Verified with a `26.0 → 26.2` consumer repro.

### Naming

`SwiftBindings.StoreKit2` (not `SwiftBindings.Apple.StoreKit2`). Namespace is `StoreKit2` to avoid collision with Microsoft.iOS's ObjC `StoreKit` types.

## 1.0 thesis

**Bridge .NET MAUI to Apple's Swift-first platform APIs, plus select third-party Swift SDKs that fill real gaps.** Measured by what shipping packages exist and where they run, not by skip percentages.

The skip-rate metric is over-indexed at 15.4% — further reduction has diminishing returns. The headline is Apple framework coverage and multi-platform proof.
