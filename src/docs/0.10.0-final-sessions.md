## How to run a session

1. Open a fresh Claude Code session in `/Users/wojo/Dev/swift-bindings` on `main`.
2. Hand it this doc + "do Session N."
3. Claude reads CLAUDE.md, this doc, and every in-scope per-bug doc in full.
4. Implement the fix plus BindingTests at the right layer (per CLAUDE.md "BindingTests are the real end-to-end gate").
5. Run the session-end gates listed below.
6. One codex-review pass — fix High / Medium inline, surface Low for accept-or-fix, commit. Do not loop codex-review.
7. `git mv` any newly-resolved docs to `src/docs/Resolved/` in the same commit.
8. Ratchet `.validation-baseline.json` if numbers improved; ratchet `runtime_pass_count_*` baselines if `--sim` / `--device` deltas are positive. Baseline bumps in a separate commit.

## Standard session-end gates

Match gates to what changed (per CLAUDE.md "Final validation gates"):

| Change locus | Required gates |
|---|---|
| Generator / emitter / parser | `nuke compile`, `nuke test`, `nuke validate`, `nuke binding-tests` (sim). Add `--device` if calling conventions or marshalling changed. |
| Runtime (`Swift.Runtime`) | `nuke compile`, `nuke test`, `nuke binding-tests --skip-regen`. Add `--device` if marshalling changed. |
| Test infrastructure only | The targeted test classes only. |

Pipe slow gates to `/tmp/<name>.txt` with `tee` and `Read` the file — never re-run a slow command to see a different slice of output.

## Session 3 — Closure-handle helper (narrow scope)

**Sizing:** ~1 week.

### Background

The 0.10.0 push closed five lifetime bugs that were all "we forgot the matching release on one of N paths":

- `Resolved/bug-0.10.0-callback-trampoline-gchandle-leak.md`
- `Resolved/bug-0.10.0-swift-wrapper-payload-buffer-leak.md`
- `Resolved/bug-0.10.0-equals-and-setter-missing-dangerousaddref.md`
- `Resolved/bug-0.10.0-swiftui-bridge-session-missing-finalizer.md`
- `Resolved/bug-0.10.0-bridged-nsarray-retain-leak-from-passretained.md`

The generator has 33 `GCHandle.Alloc` sites across ~13 emitter files. Each independently encodes "is this closure escaping, does Swift own the box, does C# need a `finally`." `src/Swift.Bindings/src/Emitter/StringEmitter/Handler/MethodClosureBridge.cs:1220-1224` openly documents a still-shipping leak: *"non-escaping closures the trampoline is invoked synchronously inside the call; the handle becomes unreachable on return — a known small leak, not introduced here."*

`DeferredSafeHandleRelease` in `src/Swift.Runtime/src/Swift/Runtime/AsyncHelpers.cs:37-53` is the right shape: refcount in constructor, release on dispose. The emitter has no equivalent.

### Scope (deliberately narrow)

- Ship a new runtime helper `Swift.Runtime.ClosureHandle` modeled on `DeferredSafeHandleRelease` — `GCHandle.Alloc` in constructor, `Free` on dispose.
- Policy enum: `Escaping` (Swift takes lifetime via the `_SBClosureCtx` box from completed Session B) vs `NonEscaping` (handle freed in C# wrapper's `finally`).
- Fix the documented leak at `MethodClosureBridge.cs:1220-1224` by migrating its single site to the helper.
- Make the helper available to emitters via the runtime reference path that Session B established.
- **Do NOT** sweep the existing 33 `GCHandle.Alloc` sites. Migration is opportunistic in future work, as those sites are touched for other reasons.

### Why now (before Session 4)

`src/docs/gap-0.10.0-everyprotocol-and-existentials.md:220-223` explicitly says the proxy machinery is *"the same pattern as the closure trampoline ... but per-protocol-member rather than per-closure-arg."* Session 4 will add roughly 10–20 new closure-shape emit sites (one per protocol method × proxy shape). With the helper in place, those sites use it from day one. Without it, Session 4 adds sites 34–53 of the same pattern and bakes in another tranche of the debt the retrospective just identified.

### Out of scope

- Migrating any of the existing 33 `GCHandle.Alloc` sites beyond the one documented leak at `MethodClosureBridge.cs:1220-1224`. Opportunistic only.
- Refactoring the `_SBClosureCtx` Swift-ARC box from Session B. The helper wraps that infrastructure, doesn't replace it.

### Tests

- **Layer A:** unit test for both helper policies (escaping registers with `_SBClosureCtx`, non-escaping frees on dispose). Confirm double-dispose is safe.
- **Layer B:** BindingTests fixture exercising both policies. A lifetime-tracking test that reproduces the `MethodClosureBridge.cs:1220` non-escaping shape and asserts no leak — this is the regression-prevention test for the fixed site.

### Gates

Full set + `--device`. Lifetime changes touch the runtime and the calling-convention path; both NativeAOT and Mono need to pass.

## Session 4 — EveryProtocol proxy forward dispatch

**Sizing:** 1–2 weeks. Re-audit at the start of implementation; split into 4a / 4b if scope exceeds ~1.5 weeks active work (suggested split below).

### Background

**Doc:** `src/docs/gap-0.10.0-everyprotocol-and-existentials.md`. Cases 1 and 2 (Swift→C# direction: `any Foo` existentials project to `IFoo`) are resolved. Case 3 is the remaining open gap.

When a C# consumer implements `IFoo` and passes the instance back to Swift, the generator emits a proxy class that bridges Swift's protocol witness table to C# virtual dispatch. Today, the proxy's methods are stubs that `throw new NotSupportedException("EveryProtocol proxy stub: ...")`. So a managed implementation of Nuke `ImagePipelineDelegate`, BlinkIDUX `ICameraModel`, Stripe delegate protocols, or Lottie value providers compiles fine and crashes at runtime on first witness dispatch.

The retrospective (`src/docs/post-0.10.0-retrospective.md`) flagged this as a worse failure mode than most of the 46 bugs we just closed: it's a known runtime-throw on a common Swift API pattern.

### Built on

- Session 2's wrapper-symbol contract — proxy emits one wrapper per protocol method.
- Session 3's `ClosureHandle` helper — proxy-method dispatch is the same closure-trampoline shape per the gap doc.
- Session B's existing `_SBClosureCtx` Swift-ARC box — proxy storage hooks into the same lifetime infrastructure.

### Scope

1. **Runtime existential-container infrastructure.** Proxy-storage that holds the C# instance and the Swift-side type metadata; reachable from the Swift witness-table thunks.
2. **Codegen per protocol method.** For each method on the proxied protocol, emit a forward-dispatching wrapper that:
   - Takes Swift's `SwiftSelf` argument as the proxy's storage.
   - Looks up the corresponding `IFoo` member (matched by Swift name/signature).
   - Marshals arguments C#-side using the same marshalling the existing closure trampoline does.
   - Invokes the C# member.
   - Marshals the return value back across.
3. **Per-member marshalling breadth.** Cover the parameter / return shapes the existing closure trampoline handles: value types, classes, optionals, throws, async, generics where lowered.

### Suggested split (if implementation re-audit calls for it)

- **Session 4a — Runtime infra + minimal dispatch.** Proxy-storage container, witness-table plumbing, wrapper-emit skeleton, and one round-trippable protocol shape end-to-end (e.g. `func foo(_ x: Int) -> Int`). Validates the architecture before broadening.
- **Session 4b — Per-member marshalling breadth + production coverage.** Closures, optionals, generic methods, throws, async. Coverage tests for Nuke `ImagePipelineDelegate` and BlinkIDUX `ICameraModel`.

Decide the split during the first implementation hour, not in advance.

### Coverage targets

- Nuke `ImagePipeline.IDelegate` — consumer-side implementation runs without `NotSupportedException`.
- BlinkIDUX `ICameraModel` — consumer-side implementation runs without `NotSupportedException`.
- Synthetic BindingTests fixture covering the matrix: void return / value-type return / class return, optional return, throws, async-throws. Locks in the matrix so future regressions surface at unit time, not validation time.

### Tests

- **Layer A:** emitter unit tests for the per-method wrapper shape and the witness-table registration.
- **Layer B:** the matrix fixture above plus a "real consumer" test that implements one Nuke protocol from C# and exercises a Swift API that calls back into it.
- Removal of the `"EveryProtocol proxy stub:"` `throw` text from emitted code is a regression-test target — assert it no longer appears in any generated binding under validation.

### Gates

Full standard set + `--device`. Runtime + generator both touched; calling-convention path exercised on every proxy invocation; both Mono and NativeAOT must pass.

## Session 5 — BindingTests audit + backfill

**Sizing:** ~1 week.

### Background

Per the retrospective, the durable end-to-end gate is BindingTests, not `nuke validate` (`feedback_bindingtests_durable_gate`, `feedback_validate_is_opt_in`). Every 0.10.0 bug needs a regression-prevention test in BindingTests so a future change that re-introduces the bug surfaces at unit-time, not validation-time. The risk this session closes: a refactor on `main` silently un-fixes a 0.10.0 bug, and we don't find out until the next `nuke validate` sweep (which is opt-in and may not run for weeks).

### Audit baseline (as of this plan)

Across the 46 docs in `src/docs/Resolved/bug-0.10.0-*.md` and `gap-0.10.0-*.md`:

- **18 docs** have explicit `bug-0.10.0-X` / `gap-0.10.0-X` references in BindingTests source. Definitively covered with a back-traceable regression test.
- **28 docs** have no explicit reference. Two categories:
  - **Shape-covered, not annotated:** Sessions B / α1 / β / D2 added fixtures for the shape without naming the originating bug doc. Spot-checked examples include cross-module extension shapes (Session β), multispec methods (Session α1), and lifetime tests (Session B). These need a comment reference + `Resolved/` doc annotation, not a new test.
  - **Genuinely uncovered:** estimated ~10–15 docs. Examples flagged by spot-check: Sendable annotation propagation, async-toplevel-objc-container-return, swift-mangled-symbol-with-cdecl-callconv (the Session 2 contract will likely cover this), bridged-nsarray-retain-leak.

Run the audit script as step 1 to get exact numbers fresh:

```bash
for f in src/docs/Resolved/{bug,gap}-0.10.0-*.md; do
  slug=$(basename "$f" .md)
  grep -rq "$slug" BindingTests/Sources/SwiftBindingsTestLib/ BindingTests/RuntimeTestsApp/ \
    --include="*.swift" --include="*.cs" \
    && echo "COVERED: $slug" || echo "MISSING: $slug"
done | sort
```

Sessions 2, 3, 4 will each add their own BindingTests coverage as part of their own commits, so the "MISSING" list at the start of Session 5 will be smaller than the baseline above.

### Scope

For each "MISSING" doc:

1. Determine actual coverage status by inspecting `BindingTests/` for the underlying shape (not just the slug):
   - **Coverage exists shape-wise:** add a `// Regression coverage for bug-0.10.0-X.md` comment to the existing fixture/test, then add a `BindingTests coverage:` line to the `Resolved/` doc naming the fixture file and test class.
   - **Coverage is partial:** add the missing assertion to the existing fixture.
   - **Coverage is genuinely missing:** write a minimal regression test — Swift pattern in `BindingTests/Sources/SwiftBindingsTestLib/` under the matching domain (Lifetime/, Protocols/, Types/, etc.) plus C# test in `BindingTests/RuntimeTestsApp/`.
2. Same audit pass for Sessions 2, 3, 4's own work — every fix landed during those sessions should also have a `BindingTests coverage:` annotation on its `Resolved/` doc.

### Why last

Sessions 2, 3, 4 will themselves add BindingTests for their work, and Session 4 in particular adds a large coverage matrix (the proxy forward-dispatch matrix). Auditing once at the end means one sweep instead of three. The cost of waiting is small: these regressions can't surface in the interim because the underlying fixes are already on `main` and gated by `nuke validate`.

### Out of scope

- Building new categorical fixtures beyond what specific 0.10.0 docs require. The retrospective recommendation (R4) is narrower than "expand BindingTests" — it's "every fixed bug has a permanent regression test."
- Sweeping the 33 `GCHandle.Alloc` sites or other non-0.10.0 debt — that's separate from this session.
- Adding BindingTests coverage for shapes not represented in the 0.10.0 doc set.

### Gates

`nuke compile`, `nuke test`, `nuke binding-tests --sim --device`. `nuke validate` only if a fixture addition surfaces an unexpected regression (unlikely — these are reproductions of already-fixed bugs).

### Definition of done

- Every `Resolved/bug-0.10.0-*.md` and `Resolved/gap-0.10.0-*.md` has a `BindingTests coverage:` line naming its fixture file and test class.
- The audit script's "MISSING" list is empty.
- BindingTests pass count on sim + device ≥ pre-Session-5 baseline (every annotation either uses an existing test or adds a new passing one).
