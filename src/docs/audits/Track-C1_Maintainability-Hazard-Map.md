# Track C1 — AI-Maintainability & Hotspot Hazard-Map

**Scope:** Read-only audit of the generator's mega-files (EveryProtocolEmitter 5595, SwiftInterfaceAccessParser 5250, SwiftUIBridgeEmitter 3962, SwiftABIParser 3481, Swift5Demangler 3239) plus top churn hotspots (ModuleEmissionContext, ConcreteProtocolSpecializationEmitter, ModuleHandler, WrapperEmitter.Async, MethodClosureBridge, ClassHandler), looking for latent defects and structural patterns that make the codebase fragile for future AI maintainers.

**Overall risk rating: 4 / 5** — confidence: high for the confirmed set (each item was probe-demonstrated end-to-end or driven through the real emitter and compiled), medium for the breadth claim (the per-track cap left a large set of same-shape candidates unprobed; see Deferred). The dominant, repeated hazard is **unguarded identifier emission**: the generator projects user-derived Swift parameter names verbatim into C#/Swift output and then declares synthetic locals/parameters with hardcoded names in the same scope, with no collision guard. This is not one bug — it is a *pattern* replicated across at least six emitter families, each independently capable of turning a legal Swift API into non-compiling generated code. The blast radius is "any user who happens to name a parameter `handle`, `result`, `session`, `tcs`, `self_`, `resultPtr`, …" — common identifiers, so the latency is real but the trigger is plausible.

### Per-item notes

**SwiftUIBridgeEmitter.AsyncPattern.cs:906 (P0).** The only P0. The async `_Create` emitter appends `onReady`/`onError`/`onResult`/`userData` after the user-derived `{param.Name}` params on three surfaces (C# P/Invoke :906–912, Swift `@_cdecl` :688–694, and the public `CreateAsync` factory :1124). `AsyncFlatParam.Name` flows verbatim from the Swift init label with no reserved-name guard anywhere on the path. The realized failure is a hard compile error (Swift redeclaration + `CS0100`), not silent mis-dispatch, because the duplicate-declaration error fires before body name-resolution. The remaining unverified piece is realistic-trigger frequency: reaching this end-to-end additionally requires `InferAsyncPattern()` to admit a real async View whose init has a bridgeable param labelled exactly one of the four reserved names — `userData` is a realistic SwiftUI/UIKit-style label, so plausible but not measured. Fix must cover all three surfaces consistently.

**MethodClosureBridge.cs:385 (P1).** The `@_cdecl` wrapper for non-generic instance methods appends `_ self_: UnsafeMutableRawPointer` and declares body locals `selfObj` (447/449), `cdecl`/`cdecl{N}` (432), `_box_{N}` (436). Non-closure passable params go through `NameProvider.EscapeSwiftKeyword`, which guards only Swift keywords — none of these five synthetic names are keywords. MCB activates on a closure arg that is bound-generic/complex-enum/Error-existential, which coexists with a plain primitive non-closure param. The fix needs a dedicated reserved-synthetic-name guard covering all five (`self_`, `selfObj`, `cdecl`, `cdecl{N}`, `_box_{N}`), not just `self_`. The same `EscapeSwiftKeyword`-only pattern appears in `NestedClosureBridge.cs` and `GenericClosureBridgeEmitter.cs` — check those for the same hazard.

**ConcreteProtocolSpecializationEmitter.AsyncGenericParent.cs:895 (P1).** `EmitParentOnlyAsyncCSharpExtension` correctly `__`-prefixes the byte-pinning locals but leaves the four control-flow locals (`tcs`, `resultPtr`, `holder`, `handle`) bare. The path is live: `BindingTests/.../Generics/PatParentStringMethods.swift:72` (`TaggedBag<Item>.measure(_ value: String) async -> Int32`) routes through it; the committed output `BindingTests/output/SwiftBindingsTestLib.cs:62111-62116` shows the exact emission. It only compiles today because the fixture chose the safe contextual-keyword name `value`. Rename that Swift param to `handle` and the generator emits byte-for-byte the `CS0136`-failing shape. Fix: `__`-prefix the four control locals (matching the already-safe pin convention) and add a regression fixture whose String async param is `handle`.

**ConcreteProtocolSpecializationEmitter.cs:1585 / WrapperEmitter.Return.cs:565 (P1).** This is the *family* version of the per-emitter local-collision hazard: hardcoded `resultPtr`/`swiftResult` locals replicated across 20+ emitter files (ConstructorWrapperEmitter, CollectionProjectionEmitter, EnumHandler.*, NativeThunkEmitter, ProtocolProxyEmitter.*, …). `NameProvider.GetCSharpParameterName` → `SanitizeForCSharp` only escapes C# keywords/illegal chars/leading digits, so `resultPtr`/`swiftResult`/`result` project verbatim. The probe also exposed a *distinct, second* defect: the existing partial parameter-dedup renames the P/Invoke declaration and call argument to `{name}_1` but leaves the **public parameter** declared as `{name}` → `CS0103` referencing a name that doesn't exist. Two NativeThunk-path methods compiled cleanly only because their hardcoded local name happened to differ from the param — confirming the hazard is per-branch and fragile.

**ModuleEmissionContext.cs:82 (P1).** `QualifyForWrapperSource` runs the whole wrapper file string through `\b<Module>\.(\w+(?:\.\w+)*)`. The `\b` is satisfied after a preceding `.`, so a NON-leading dotted segment equal to the colliding module name is matched and the prefix-up-to-and-including the module token is dropped. Single-module output is accidentally shielded by .NET's leftmost-greedy non-overlapping matching (the leading `Module.` match consumes the whole tail in one go). The real corruption surface is **cross-module qualified references** (`DepKit.Reachability.Inner` → `DepKit.Inner`), plus any comment/string literal of shape `X.<Module>.Y` (silent). Trigger requires (a) a module that exports a public type named identically to itself (common: Reachability/Valet/SwiftyBeaver/GTMSessionFetcher) AND (b) a cross-module path carrying that name mid-path. The existing test `Collision_DoesNotMatchPartialIdentifier` only covers intra-identifier boundaries, not the dotted-segment case. Fix: anchor the rewrite to a leading-only position (e.g. `(?<![.\w])` instead of `\b`) or match on parsed type references, not whole-file substrings.

**EveryProtocolEmitter.cs:1857 vs :1455 (P1).** The "should we skip this EveryProtocol conformance" decision exists in three near-identical copies (prescan `WillSkipConformance`, emission ladder `EmitProtocolConformance`, and the `ModuleHandler` suitability `.Where` chain) and has already drifted: `HasNoncopyableMember` is only in the emission ladder. Because `PreScanProtocols` Pass-2 transitive propagation keys off `_skippedProtocols`, a `~Copyable` protocol never seeds that set, so the order-independence guarantee the prescan was built to provide does not extend to noncopyable-driven skips. When a genericSig-constrained child sorts before its noncopyable parent, both the Swift wrapper and the C# proxy reference a conformance that was never produced. Fix: add the `HasNoncopyableMember` gate to `WillSkipConformance` so the prescan is order-independent. The comment at line ~1983 claiming the inline ladder "mirrors `WillSkipConformance` exactly" is, at minimum, misleading here. Note `ModuleHandler.IsEmittable` (1217) *does* check `HasNoncopyableMember`, but it keys off the same gap-afflicted `_skippedProtocols`, so it does not save the dependent.

**SwiftUIBridgeEmitter.cs:2776 (P1).** The sync `Create` factory declares hardcoded `handle` (2776/2878/2893), `session` (2779/2881/2896), `closureHandles` (2665), and `h` (2686) while user params are emitted raw via `{type} {param.Name}` (2648/2650). `BridgeParameter.Name = param.Name` (InitAnalyzer.cs:143) with zero sanitization — the SwiftUI bridge family contains **no** `EscapeSwiftKeyword`/`Sanitize` call anywhere. Result for a View init param `handle`: `CS0136` + `CS0841` (the latter because `var handle = …Create(handle)` resolves the argument to the not-yet-initialized local). C# forbids the shadow outright (safer than silent masking), but it's still a hard build break for any View whose init uses one of these common identifiers.

## 2. Inconclusive / needs deeper probe

These had a verified *mechanism* but a contested or unreached *consequence*; verdicts split between voters. Treat as real fragility worth a defensive fix, but do not claim a current production failure without the missing probe.

- **`ModuleEmissionContext.cs:23` — `Default` singleton accumulates dedup state with no `Reset`; `ctx ??= Default` fallback.** Mechanism confirmed against the real DLL: re-registering a symbol on `Default` returns `false` (suppressed); 49 `??= Default` sites (claim said ~30); no Reset/Clear exists. The split: one voter **refuted** the production-harm claim because the generator emits exactly one bound module per process (`Program.cs:405/468`, `BindingsGeneratorCommand.cs:654`), so `Default` never accumulates across bound modules in production and the documented `MethodHandler` threading is correctly honored; the other voter **confirmed** the silent-failure mechanism for the narrower set of *module-agnostic infra symbols* (`SBW_CreateEveryProtocol`, `SBW_Utf8Slice_Free`, …) if a future caller forgets to thread context. Repo's own `Utf8SliceEmitterTests.cs:140-145` documents this as a historical real bug ("can't reset the Default singleton"). **Net: latent AI-maintainability footgun, not a demonstrable current production defect.** Needs a multi-module-in-one-process probe to settle, which the current single-module pipeline can't naturally produce.

- **`SwiftABIParser.cs:2259` — `DetectAsyncFromMangledName` misfires for sync methods/ctors with an async-closure parameter.** Unit-level bug is **true** (confirmed both voters): a sync function whose only `Ya` comes from a nested async-closure type (`() async -> Void`) returns `IsAsync=true`; the sole guard is a preceding ASCII digit. The split is on reachability: for **methods**, the in-repo `Swift5Demangler.Run` succeeds and returns a `FunctionReduction` with correct `IsAsync=false`, so the buggy `?? DetectAsyncFromMangledName(...)` fallback is never consulted (one voter showed the literal example emits a correct synchronous `Register` with a `Tj` sync thunk). For **constructors**, the demangler returns a `ReductionError`, so the fallback *is* reached and computes a wrong `IsAsync=true` for a sync ctor with an async closure — but `ConstructorWrapperEmitter.cs:165-177` rejects all async closures on constructors *before* any wrong-ABI emission. **Net: real latent heuristic defect, but the wrong-ABI consequence is currently blocked on every reachable path.** Worth a defensive fix (structural mangling check, or trust the swiftinterface `async` keyword); the probe needed is an exotic/new mangling the demangler can't reduce that *isn't* a constructor.

## 4. Checked & refuted

Brief, so future agents don't re-chase:

- **`EveryProtocolEmitter.cs:3155` — conformance body locals collide with user params → "Swift redeclaration error, whole wrapper fails to compile."** **Refuted.** The premise (collision exists, no escaping) is true, but the consequence is wrong: a body `var`/`let` shadowing a function *parameter* is legal Swift shadowing, not a same-scope redeclaration. Driven through the real generator (params literally `selfProto`/`resultPtr`/`slice`/`str`/`buffer`) and `swiftc` compiled to a working dylib with zero errors. A genuine *different* defect remains (silent value-aliasing for `selfProto` and `x`/`xCopy` pairs) — captured in Deferred. (Two independent votes, high confidence.)
- **`EveryProtocolEmitter.cs:3182` — same as above, "redeclaration breaks compile, drops conformance."** **Refuted**, same reason (shadowing ≠ redeclaration), confirmed by running the real generator and compiling. Same residual value-aliasing hazard noted.
- **`ProtocolProxyEmitter.cs:194` — `_setVtableEmitted`/`_witnessGetterEmitted` forced true under `Default` masks a missing vtable/witness symbol in production.** **Refuted.** The `== Default` override mechanism is real (probe-confirmed it diverges from a real-but-unmarked context), but no production path reaches the proxy emitter with `Default`/null: `Program.cs:405/468` always threads a fresh per-module context, every `context with {…}` clone preserves `EmissionContext`, and within one `ModuleHandler.Emit` the EveryProtocol emitter and the proxy share the *same* context instance. The `== Default` branch is a documented unit-test affordance. Latent fragility for a *future* caller, not a current defect. (Two votes, high confidence.)

## 5. Coverage gaps (what this track did NOT reach)

- **No end-to-end inference-path confirmation for the SwiftUI async P0.** The emitters were driven directly with a hand-built `AsyncViewPattern`; whether `InferAsyncPattern()`/`KnownAsyncPatterns` actually admits a real async View with a reserved-named init param was not exercised. The generator-correctness defect (no de-dup once such a param flows in) is verified; realistic-trigger frequency is plausible-but-unmeasured.
- **The full Deferred list (~30 candidates) is unprobed.** Each is the same shape as a confirmed item, but no compile probe was run; they could individually be shadowing-not-error (like the refuted EveryProtocol items) or blocked on a reachability gate (like the inconclusive `DetectAsyncFromMangledName` constructor path). Do not treat them as confirmed.
- **Swift5Demangler.cs (3239 lines) was not probed at all** beyond its role as the success/fallback gate for `DetectAsyncFromMangledName`. Demangler-internal correctness (which manglings it reduces vs errors on) directly controls whether several parser fallbacks fire; this is an under-examined hotspot.
- **`SwiftInterfaceAccessParser.cs` (5250 lines) parser hazards are all Deferred (P2), none probed.** The brace/scope-tracking duplication (23 loops) and comment/string-literal gaps feed negative-space public/internal classification — a wrong classification silently drops or exposes members, which is hard to notice and high-impact. This is the largest unverified surface.
- **No runtime/BindingTests-layer probing.** All probes were compile-time (`swiftc -typecheck`/`-emit-library`, `dotnet build`). Silent-wrong-value defects (the EveryProtocol `selfProto` aliasing, the BoundEnum force-unwrap trap, the SwiftUI trampoline crash-on-throw) need a *running* harness to demonstrate the wrong behavior, which this track did not run.
- **Churn-vs-defect correlation was not formally measured.** The "top churn hotspots" were audited for defects, but no claim is made that high churn *predicts* the confirmed defects; the dominant pattern (unguarded identifier emission) cuts across both high- and low-churn files.

## 6. Recommended BindingTests fixtures

Swift shapes that would permanently lock down each confirmed defect. (Shapes only — no fix proposed.)

1. **Async SwiftUI View with a reserved-named init param (locks the P0).** A bridgeable async View whose initializer has a parameter labelled exactly `userData: Int` (and a sibling fixture for `onError`/`onResult`/`onReady`), of a bridgeable type, that `InferAsyncPattern()` admits. Gate: the generated `*.SwiftUIBridge.cs` and `*.SwiftUIBridge.swift` must compile. (Add a control View with a non-reserved param to prove the harness compiles.)

2. **Closure-bearing instance method with `self_` param (locks MethodClosureBridge).** `public final class C { public init(){}; public func run(self_: Int, _ cb: @escaping (Result<Int, Error>) -> Void) }` — the Error-existential closure activates MCB; the `self_` param collides with the synthetic self. Add sibling params named `selfObj`, `cdecl`, and `_box_0` to cover all five synthetic names.

3. **Generic-parent async String method with a control-local-named param (locks AsyncGenericParent).** Mirror the existing `PatParentStringMethods` fixture but rename the String async param from `value` to `handle` (and siblings `tcs`/`holder`/`resultPtr`): `func measure(_ handle: String) async -> Int32` on a generic type. Gate: generated C# compiles.

4. **Legal Swift API with `resultPtr`/`swiftResult`/`result`/`errorPtr` params (locks the hardcoded-local family).** A struct/class exposing a struct-returning method `f(resultPtr: Int)`, a string-returning `g(resultPtr: Int)`, an `init(resultPtr: Int)`, and a throwing `h(errorPtr: Int) throws -> T`. Gate: generated csproj builds (catches both the `CS0136` collision and the `CS0103` partial-dedup bug).

5. **Cross-module collision corruption (locks the regex).** Module `Reachability` exporting a public type also named `Reachability`, consuming a dependency `DepKit` whose public type path is `DepKit.Reachability.Inner`; emit a wrapper that references `DepKit.Reachability.Inner`.
