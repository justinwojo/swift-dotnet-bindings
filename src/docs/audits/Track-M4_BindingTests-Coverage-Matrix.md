# Track M4 — BindingTests Skip-Taxonomy & Coverage Matrix Audit

**Scope:** Audit of the BindingTests skip taxonomy, coverage-matrix authority, and the docs/rules that describe them — `BindingTests/README.md`, `BindingTests/output/binding-report.json`, `BindingTests/RuntimeTestsApp/**`, `BindingTests/Sources/SwiftBindingsTestLib/**`, `.claude/rules/bindingtests.md`, plus the generated `output/SwiftBindingsTestLib.cs`/`.Wrapper.swift` and `build/scripts/coverage-report.py`.

**Overall risk rating: 4 / 5 (high). Confidence: high for the 7 confirmed items (each is multi-vote probe-demonstrated and re-verified here against current source).** The headline risk is that the BindingTests gate — the project's designated end-to-end safety net — has a systematically unreliable skip taxonomy: at least one P0 wrong-ABI binding ships as a live, non-`[Obsolete]` public API behind a `[Skip]`, several `[SkipOnSimulator]` skips misattribute our own bugs (or stale-passing tests) to a structurally-impossible "upstream Issue 1," the macOS/Catalyst gates skip Mono-only tests on the CoreCLR runtime where the limitation cannot fire, and the coverage matrix that the README presents as the authority cannot detect missing runtime coverage at all. Rating is 4 not 5 because no confirmed item is a shipped-product silent miscompile that escapes *all* gates — they are coverage/governance defects plus one P0 that is masked but at least nominally tracked by a skip.

### Per-item detail

**P0 — `AsyncGenericContainer.ProcessAsync`/`FetchOrThrowAsync` ship as live wrong-ABI bindings.** Re-verified against current source: `ProcessAsync` (cs:169460) is `public virtual Task<int> ProcessAsync(...)` with no `[Obsolete]`/SB0001/`[UnsupportedSwiftType]`. Its PInvoke (cs:169927-169929) is `[UnmanagedCallConv(CallConvSwift)]` / `[LibraryImport("SwiftBindings", EntryPoint="$s20SwiftBindingsTestLib21AsyncGenericContainerC07processE0s5Int32VyYaF_async")]` with 5 params `(callback, errorCallback, handle, TMetadata, _selfClass)`. The Swift wrapper declares 4 (self in swiftself, no `_metadata0`) — unlike the sibling constructor wrapper which uses `_SBW_GSF` type-erasure with `_metadata0`. The generator's `MissingWrapperSymbol`/`GenericTypeCallback` suppression catches `fetchPair`/`mapAsyncThrowing` (return type references parent `T`) but lets `processAsync`/`fetchOrThrow` through. **Correction to original claim, important for the fixer:** the `@_silgen_name` symbol on the generic-class extension *does* link (confirmed via `nm`/swift-demangle on the shipped dylib and a minimal probe) — the failure mode is a swiftself/parameter-count register ABI mismatch that crashes, not `EntryPointNotFound`. The `[Skip]` reason ("`@_silgen_name` … stripped … cannot export a fixed symbol") is factually wrong on Swift 6.2.4.

**P1 — Stale `[Skip]` hides working failable-init feature.** Both `TryCreate` methods are fully emitted (allocate Optional metadata buffer, call failable init via CallConvSwift indirect-result PInvoke, read enum tag, return false on None, else `InitializeWithCopy` + class-projected construct). The generator's `WrapperEmitter.FailableFactory.cs` has an explicit non-frozen branch; the comment at cs:262575 documents it deliberately ("CS8625 fix"). All 5 skip bodies are vacuous (`TestLogger.Info` only). Frozen `RangedInt`/`SafeDiv` failable-init tests already run live through the same emission path. **Caveat:** verification proved the path compiles and all native symbols resolve; the non-frozen branch calls VWT through CallConvSwift function pointers (which the emitter's own comments flag as Mono-risky), so the fix is to write real round-trip assertions and run `nuke binding-tests` (sim + device) rather than assume green. (Note: the original claim's paths for two of the five sites were under `Marshalling/`; they are actually `ErrorHandling/ThrowingMethodTests.cs:737,743` and `Initializers/InitializerTests.cs:96,102`. Line numbers/content otherwise match.)

**P1 — Three throwing-closure success tests misattributed to Issue 1 (CallConvCdecl path).** Two independent angles confirm this (the "cannot be Issue 1" structural angle and the "Issue 1 is only a secondary masking assertion" doc angle). The decisive internal contradiction: `TestThrowingWithParamSuccess` (:234, `(Int32) throws -> String`, same `SwiftError*` cdecl callback) is NOT skipped and runs on the simulator. ~35 structurally-identical throwing siblings run unskipped through the same cdecl + `SwiftError*` machinery. The skip text's mechanism contradicts both `RuntimeLimitations.cs:25-31` and the retraction in `upstream-issue-01-...md:104`. Note `RuntimeLimitations.cs:26-28` still carries the stale `swift_getExistentialTypeMetadata` framing in its doc comment — worth correcting in passing.

**P1 — macOS/Catalyst gates lose CoreCLR coverage.** `--platform simulator` for the macOS (`:1849`) and Catalyst (`:1968`) gates maps to `TestPlatform.Simulator`, which skips every `[SkipOnSimulator]` test. macOS/Catalyst run on CoreCLR (`IsMonoRuntime=False`), where Issue 1 cannot fire. The `[SkipOnCatalystX64]` attribute proves the codebase *can* discriminate runtimes when it chooses to. **Nuance:** the leak-fallback `[SkipOnSimulator]` skips cite `IncludeSwiftBindingsRuntimeNative=false`; one vote found the macOS/Catalyst builds *inject* the dylib post-build (so the premise is genuinely absent there), while the other vote found both Mac csproj files do set that flag (so the premise holds). The closure/Issue-1 group is unambiguously mis-skipped on CoreCLR; the leak group is at least riding the wrong (sim) channel even where its reason is correct.

**P1 — Returned-throwing-closure dead cdecl thunk + raw CallConvSwift invoker.** The generator emits a complete throwing-aware CallConvCdecl invoke path and then never wires it in — `EmitThrowingClosureReturnMarshalling` (`ClosureEmitter.Throwing.cs:171-285`) accepts `invokeThunkPInvokeName` and ignores it, always emitting the inline CallConvSwift lambda, even though `EmitCSharpInvokeThunkHelper` already builds a working throwing cdecl invoker and the non-throwing emitter (`ClosureEmitter.cs:256-272`) correctly uses it. The A/B Mono-simulator probe is decisive: the dead thunk passes, the emitted path SIGSEGVs. This is the cleanest "self-inflicted skip" in the set — wiring the existing cdecl thunk obsoletes the `[SkipOnSimulator]`.

## Checked & refuted

There are no findings that were checked and found to be entirely correct code (the JSON `refuted` array is empty). The only refutations are *sub-claims within confirmed/inconclusive findings*, recorded here so future agents don't re-chase them:

- **AsyncGenericContainer is NOT `EntryPointNotFound`/"symbol stripped."** The `@_silgen_name` symbol on the generic-class extension compiles and exports as a single fixed symbol (verified via `nm`/swift-demangle on the shipped dylib and a minimal probe). The defect is a register/parameter-count ABI mismatch that crashes, not a link failure.
- **`Permission.Execute=3` is NOT necessarily a wrong-ABI miscompile.** For tag-based simple-enum marshalling, `3` is the correct in-memory tag (the raw value `4` lives only in the `.rawValue` getter). The wrong-value concern is real only on the `init(rawValue:)` param path — hence the item is inconclusive, not confirmed P0.
- **ReturnedThrowingClosure runtime path is NOT CallConvCdecl.** The cdecl invoke thunk is emitted-but-dead; the live `_invoker` is genuinely CallConvSwift. The claim's "it's cdecl, so the CC attribution is wrong" premise is refuted (the CC attribution is the *correct* calling convention; the root-cause attribution is what's wrong).
- **`MethodLevelGenericTests` does NOT exercise the `[Obsolete]` CallConvSwift fallback.** Overload resolution binds to a concrete CSM CallConvCdecl overload; the `#pragma warning disable CS0618` is dead. The proposed `[SkipOnSimulator]` fix is wrong.

## Recommended BindingTests fixtures

These describe the Swift shapes that would lock down each confirmed defect as a durable in-repo gate. No code-fix proposals — only the fixture shape and the assertion intent.

1. **Generic-class async member (P0 ABI mismatch).** Swift: `public final class GBox<T> { public init(_ v: T); public func processAsync() async -> Int32; public func fetchOrThrow(shouldFail: Bool) async throws -> Int32 }`. Fixture intent: generate bindings, then a runtime test that `await`s `ProcessAsync()` and asserts the returned value, run on both sim and device. The test must NOT be `[Skip]`'d — if the binding is wrong-ABI it should fail/crash visibly, and the fix is either correct metadata-forwarding `@_cdecl` emission or generator-side suppression with `[Obsolete]`/`[UnsupportedSwiftType]` so no live public method ships. A companion compile/unit assertion: the emitted PInvoke arg count must equal the wrapper arity, and self must be wrapped in `SwiftSelf`.

2. **Non-frozen failable init round-trip (P1 stale skip).** Swift: `public struct ValidatedName { public let name: String; public init?(name: String) }` and `public struct NonEmptyString { public let value: String; public var length: Int { value.count }; public init?(_ s: String) }` (no `@frozen`). Fixture intent: real assertions — `TryCreate("ok", out var v)` returns true with `v.Name == "ok"`; `TryCreate("", out _)` returns false. Run sim + device (the non-frozen VWT-through-CallConvSwift path is the risk). Replaces the 5 vacuous skipped bodies.

3. **CallConvCdecl throwing-closure success paths (P1 misattribution).** Swift: `public func callThrowingClosure(_ f: () throws -> Int32) rethrows -> Int32`, plus `() throws -> Void` and `(Int32) throws -> Bool` variants (the `(Int32) throws -> String` variant already exists unskipped). Fixture intent: success-path tests asserting the returned value, NOT skipped on simulator. These lock in that a pure-cdecl `SwiftError*` callback does not trip Issue 1.

4. **Returned throwing closure invoked via the cdecl thunk (P1 self-inflicted skip).** Swift: `public func makeAlwaysThrowingIntClosure() -> () throws -> Int32 { return { throw E() } }` and a success variant. Fixture intent: a runtime test that invokes the returned delegate and asserts `SwiftResult.IsFailure` (and the success variant returns its value), NOT `[SkipOnSimulator]`. This is the durable guard that the throwing-return path routes through the cdecl invoker rather than the crashing inline CallConvSwift lambda.

5. **CoreCLR-runtime skip discrimination (P1 macOS/Catalyst gate).** Not a Swift fixture — a harness-level fixture: a `[SkipOnSimulator]`-tagged test plus an assertion (or a meta-test) that on the macOS/Catalyst gate the test actually *runs* (status != skip), proving the gate distinguishes CoreCLR from the Mono simulator. Pair with a `TestPlatform` value for macOS/Catalyst so the leak-fallback skips can be gated on a "dylib-absent" predicate instead of a sim proxy.

6. **Issue-1 attribution invariant (P1 doc/taxonomy).** A unit/meta assertion over the test corpus: any test whose skip reason mentions "Issue 1" / "!ji->async" must have at least one CallConvSwift PInvoke on its call path; flag any `[SkipOnSimulator(... Issue 1 ...)]` whose generated path is pure CallConvCdecl. This statically prevents re-introducing the misattribution.

7. **Non-sequential raw-value enum param round-trip (inconclusive P0/P1).** Swift: `public enum Permission: UInt32 { case none=0; case read=1; case write=2; case execute=4 }` plus `public func roundTripPermission(_ p: Permission) -> UInt32 { p.rawValue }` AND a method on a type taking `Permission`. Fixture intent: assert `RoundTripPermission(.Execute)` surfaces `4` (or the binding faithfully reproduces Swift semantics), and that passing `.Execute` into a Swift function does not trap. This is the fixture that would settle the tag-vs-rawValue inconclusive split.

8. **Coverage-matrix runtime-awareness (P1 coverage authority).** Not a Swift fixture — a check that the coverage report distinguishes "Swift source + emission present" from "live runtime assertion present, not `[Skip]`'d." A feature with a Swift source file but only a vacuous `[Skip]`'d C# test must report as *uncovered at runtime*, not `passing`/`implemented`.
