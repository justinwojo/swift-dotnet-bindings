# Track A5 Audit — Existentials / Protocol Proxies / Witness Dispatch

**Scope:** ARC, ABI layout, and marshalling correctness across the existential/protocol-proxy/witness-dispatch surface — both directions of the boundary (Swift-vends `any P` to C#; C# implements a Swift protocol the EveryProtocol vtable dispatches into). Files audited: `EveryProtocolEmitter.cs`, `ProtocolProxyEmitter.InterfaceImpl.cs`, `ProtocolProxyEmitter.Receivers.cs`, `ProtocolProxyEmitter.SwiftObject.cs`, `WitnessDispatchEmitter.cs`, `Emitter/StringEmitter/Handler/ExistentialBypassEmitter.cs`/`ModuleHandler.cs`, `Marshaler/ExistentialHandler.cs`, `Marshaler/Projection/ExistentialProjection.cs`, and `Swift.Runtime/.../ExistentialContainer.cs`.

**Overall risk rating: 5 / 5 (high confidence).** Eight findings confirmed, including two independent probe-backed P0 use-after-free / double-release defects on the opaque (`any P`) owned-return path, two correctness defects that silently drop or corrupt data (optional-existential receiver returns `nil`; class-bound `[any P]` array writes at the wrong stride), and three P1 leaks/throws. The boundary is heavily exercised by real-world libraries (factory-returns-existential is the canonical RxSwift/Swinject/SwiftyBeaver shape), yet BindingTests has *zero* coverage on the specific member-return witness-dispatch path where the worst defects live. Confidence in the confirmed set is high: the two P0s and the class-bound stride bug were reproduced with standalone Swift/C probes that crashed with the predicted signatures (SIGSEGV exit 139), and the silent-drop defects are visible in committed generated output.

### Notes per item

**P0 — Opaque `any P` owned-return double-release (`InterfaceImpl.cs:1857`, `WitnessDispatchEmitter.cs:1901`).** This is the headline defect and it was confirmed by *four independent probe votes* (two on each framing). For an opaque (non-class-bound) `any P` / composition method or property return, `BuildExistentialHeapCellReadAndConstruct` (`InterfaceImpl.cs:1833-1859`) emits — for the opaque branch only — `var container = Unsafe.Read<ExistentialContainerN>((void*)resultPtr); new {Proxy}(container, ownsContainer: true)` with **no retain**. `Unsafe.Read` is a pure bitwise copy. The method body wraps the read in `try { ... } finally { NativeMethods.{free}(resultPtr); }`, and the free function (`WitnessDispatchEmitter.cs:1898-1903`) runs `ptr.assumingMemoryBound(to: (any P).self).deinitialize(count: 1)` — a value-witness Destroy (−1). Later `Proxy.Dispose`/finalize runs `DestroyWireBufferRetains` (`SwiftObject.cs:84-100` → `SwiftMarshal` `ValueWitnessTable->Destroy`) on the bitwise copy — a *second* Destroy (−1). ARC ledger: Swift returns at +1; free → 0 (freed); Dispose → −1 (over-release). The class-bound sibling branch (`InterfaceImpl.cs:1845-1848`) is correct precisely because it takes `Arc.UnknownObjectRetain(container.ClassRef)` before adopting. `ExistentialHandler.IsOwnedExistentialContainerType` (`ExistentialHandler.cs:57-70`) returns true for `ExistentialContainer1..8`, so this fires for every opaque single-protocol return and every composition return whose payload has nontrivial value witnesses (class conformer or boxed-value conformer). The fix must take a balancing +1 on read — but because the payload may be inline-class, boxed-value, or ObjC, it should route through the existential's value-witness `InitializeWithCopy` (a control probe confirmed `InitializeWithCopy`-on-read yields exactly one deinit, exit 0), not a bare `ClassRef` retain.

**P1 silent-drop — optional-existential receiver returns nil (`Receivers.cs:931`).** Confirmed three times, including by inspecting *committed* generated output. The early-return at `Receivers.cs:931-945` (`if (hasOptionalExistentialReturn) { ... return (IntPtr)NativeMemory.AllocZeroed(containerSizeBytes); return; }`) fires before the impl-dispatch that begins at line 947, AND before the real return-marshalling at line ~1132. The justification comment ("needs type metadata + witness table … isn't accessible from C#") is **factually false**: the identical capability is already present and exercised by the non-optional branch (`GetReceiverExistentialGetterConversion` Optional<existential> arm at `Receivers.cs:1570-1574`, plus `ExistentialProjection.GetParameterElementConversion`/`GetOwnedReturnElementConversion`). Git archaeology: the stub was added in `6746b0d6` (2026-02-11); the working Optional<existential> `NewSome`/`NewNone` path landed *later* in `c5b62569` (2026-02-20) but never removed the earlier short-circuit, so the dead stub still wins. There is no `[Obsolete]`, exception, or `#warning` — a C# impl returning a real value silently delivers `nil` to Swift. The fix is to delete the early-return and let the existing optional marshalling run.

**P1 leak — EveryProtocol value-type returns leak (`EveryProtocolEmitter.cs:2311/2537/3219`).** Confirmed twice. The getter, subscript-getter, and method-return fan-outs each have three branches; the String and ObjC-bridgeable branches call `resultPtr.deallocate()`, but the value-type `else` branch is bare `return resultPtr.assumingMemoryBound(to: T.self).pointee`. The buffer is C#-allocated via `MarshalToSwiftBuffer<T>` → `NativeMemory.Alloc`, and the Swift thunk is the documented owner. **Important amplification of the original claim:** the probe found a THIRD site at `2537` (subscript getter, also tracked separately in the deferred list) — any fix and regression matrix must cover all three sites, not just the two cited.

**P1 correctness — `ExistentialContainer0` int→long drift (`ExistentialContainer.cs:88`/`155`).** Confirmed twice. `Box(int)` and `Box(long)` both stamp `typeof(nint)` (Swift.Int) metadata; `Unbox` has a single nint arm returning `(long)`. Boxing `Swift.Int` as a 64-bit `long` is the *correct* value-witness mapping (Swift `Int` is 64-bit), so the real defect is that the public `Box(object)` API accepts `int` and cannot honor an `int` round-trip — it should either reject `int` loudly or preserve origin type. In-repo `DictionaryAnyTests` deliberately uses `42L` (comment: "Swift Int = 64-bit, use long"), so the natural `{ "count", 42 }` consumer call is untested.

**P1 throw — bare-`Any` parameter cannot box non-primitives (`ExistentialContainer.cs:128`).** Confirmed twice. Distinct from the int/long item: this is the *parameter* direction (and `[String:Any]` element direction), surfacing as a hard `NotSupportedException` at runtime for any class/struct/array/enum/most-numeric-types argument, with no compile-time gate (the member emits with public type `object`). `ExistentialContainerFactory.CreateAny<T>` is the natural fix path but is dead code from the generator's perspective.

**P1 leak — owned collection-element existential returns (`ExistentialProjection.cs:156`).** Confirmed twice (one full static+SIL trace, one with a native LIVE-count repro). `GetReturnElementConversion` emits the non-owning `({_publicType})new {Proxy}({elementVar})`. The owning `GetOwnedReturnElementConversion` (`:176-179`, passing `ownsContainer:true`) is wired only at `OptionalProjection.cs:395`; `ArrayProjection`/`DictionaryProjection`/`SetProjection` all fall through to the leaking path. The in-code comment (`:148-155`) explicitly flags this as a deferred gap. One caveat noted by a voter: a *live* `AssertLiveCount(0)` BindingTests harness was not executed; the leak is certain by static+SIL+native-repro but the end-to-end deinit-count gate is the missing durable proof.

**P1 ABI corruption — class-bound `[any P]` array wrong stride (`Receivers.cs:1580`/`1519`).** Confirmed twice with crashing probes. The two receiver-getter write sites consult `ExistentialProjection.PInvokeType` (always 40-byte `ExistentialContainer1`) instead of `ArrayElementCarrierType` (16-byte `ClassExistentialContainer1` for class-bound arity-1) — the carrier accessor built *for exactly this case* and already used by every READ-direction site. One generated property emits contradictory strides (READ correct, WRITE wrong). **Fixer caveat flagged by a voter:** this is NOT a one-token type swap — the `.Select` element lambda's `ExistentialContainerFactory.GetOrCreate<IMarker>(...)` yields `ExistentialContainer1`, and the implicit operator (`ExistentialContainer.cs:273`) is `ClassExistentialContainer1 → ExistentialContainer1` (wrong direction for a `FromEnumerable` element), so the element conversion must change alongside the carrier type. The same 40-byte bug also exists in the **parameter** direction (`ArrayProjection.cs:61/247` via `SwiftContainerGenericType`), so the fix spans both directions and must register `ClassExistentialContainer1` metadata for the write/param sites.

## 2. Inconclusive / needs deeper probe

Two findings split the verifiers (one `confirmed`/one `refuted` each) and are recorded as genuinely contested, not silently resolved.

- **Closure-returning protocol method: C# impl returning `null` delegate → Swift `fatalError` → process abort** (`EveryProtocolEmitter.cs:3625`; receiver `Receivers.cs:485-489`). The *mechanism* is real and was reproduced (Swift probe: `fatalError` "returned nil function pointer", SIGTRAP exit 133/139). The dispute is over whether the trigger is a "valid managed return": the generated C# interface return type is **non-nullable** `Action` (under `#nullable enable`), so returning `null` is a CS8603-flagged contract violation — the Swift analog of force-unwrapping a non-Optional. The "refuted" vote argues there is no contract-conformant managed value that reaches the abort; the "confirmed" vote argues a runtime-legal `null!`/default still crosses the FFI as an uncatchable whole-process abort where a catchable `NullReferenceException` would be expected, and a safer `Optional<()->Void>` representation was available but excluded by the gate. **Open question for a deeper probe:** is a hard `fatalError` the right failure mode for a contract violation, or should the receiver throw a managed exception / the gate reject the shape? The in-repo `ReturnNullHandler` flag exists but is never set true, so the abort path ships uncovered either way.

- **ObjC-bridgeable protocol getter/method return uses `takeUnretainedValue` on a C#-owned handle → potential UAF** (`EveryProtocolEmitter.cs:2306/2532/3210`; producer `Receivers.cs:1222`). Code shape confirmed: C# hands Swift the bare `.Handle` (+0, carrier `IntPtr`, `Unsafe.Write` no retain), Swift adopts via `takeUnretainedValue()`. The dispute hinges on `takeUnretainedValue` semantics: the "refuted" vote's SILGen probe shows it lowers to `strong_copy_unmanaged_value` (an adopt-time +1 retain), so a +0 borrow held alive across the *synchronous* native receiver call is balanced — and a UAF would require the C# wrapper to be finalized in the sub-microsecond native gap, which it could not reproduce. The "confirmed" vote's probe (modeling the producer dropping its sole owner before the consumer read) crashed with SIGSEGV/abort and the +1/+1 control survived. **Reconciliation:** both are consistent if the real risk is narrow — a freshly-constructed wrapper getter return with no other strong owner, collected concurrently between C# return and Swift's adopt-time copy. This is a timing-dependent UAF, not deterministic; the A3 ARC/Ownership audit covered this file and did not flag it. Needs a live BindingTests harness with `GC.Collect()`+`WaitForPendingFinalizers()` forced between handoff and Swift use to settle.

## 3. Deferred (candidate, unverified)

Real candidates not probed due to the per-track verification cap — listed so none are silently dropped:

1. **Witness-dispatch drops `inout` parameter semantics on the C# (calling) side** (`ProtocolProxyEmitter.InterfaceImpl.cs:1193`). Swift-vended `any P` method with an `inout` param emits a by-value C# parameter (no `ref`/`out`) and never reads the mutated buffer back. The C#-implements-Swift (EveryProtocol) direction *does* handle `inout` — asymmetric. No `IsInOut` reference anywhere in the `ProtocolProxyEmitter` family. **P1, high plausibility** (Swift side at `WitnessDispatchEmitter.cs:2331/2345/2386` binds `var` + `&`, proving end-to-end intent; only the C# half is missing).

2. **EveryProtocol C#-implemented subscript value-type getter leaks the buffer** (`EveryProtocolEmitter.cs:2537`). **NOTE: this was incidentally CONFIRMED** by the value-type-leak probe (see §1, finding 4) — it is the same omission class at a third emission site. Listed here only because the original claim packaged it separately; treat it as confirmed.

3. **Swift-vended composition existential (`any A & B`, EC2+) proxy is a dead receiver** (`ModuleHandler.cs:2026`). `EmitCompositionMemberStubs` emits every getter/setter/method as `throw new NotSupportedException("Cannot … member on Swift-backed composition existential.")`. The proxy is a live, owned, returned object with no working dispatch — callers can re-pass it but cannot read any member. **P1, high plausibility** (matches the "dead receiver returning a structurally-valid-but-inert carrier" category).

4. **Class-bound existential proxy `MarshalToSwift` over-copies 40 bytes for a 16-byte slot** (`ProtocolProxyEmitter.SwiftObject.cs:208`). `MarshalToSwift(ref Span<byte>)` always copies `_swiftContainer.SizeOf` (40 bytes) with no class-bound branch, unlike `NewFromPayload`/ctor/`ReleaseAdoptedSwiftContainer` which all branch on class-boundedness. If a class-bound proxy is marshalled into a 16-byte `any P` parameter slot, either a 24-byte overrun or an `ArgumentException` size-guard throw. **P2** — manifestation depends on whether the param-marshal site's destination span reaches this method for class-bound proxies (unconfirmed; closely related to the confirmed §1 stride bug, which is the parameter-direction analog).

5. **`int`→`long` Any round-trip type drift** (`ExistentialContainer.cs:155`). **NOTE: CONFIRMED** as the P1 finding in §1 (item 5). The P2 duplicate is the same defect at a lower severity framing — keep the P1 record.

6. **Composition proxy member-stub leading-`I` strip heuristic can silently drop a protocol's members** (`ModuleHandler.cs:1973`). `interfaceName.StartsWith("I") ? Substring(1) : interfaceName` + exact-name `FirstOrDefault` + `continue` on miss → a protocol whose interface name doesn't round-trip through the single-`I` strip has its entire member set omitted (compile-time absent, no diagnostic). Compare `:1362` which uses the authoritative `NameWithoutModule`. **P2, lower confidence** (standard `I`+name convention usually round-trips; needs a constructed naming edge case).

7. **Swift-side `inout` writeback emitted as unreachable dead code in non-void/non-throwing accessors** (`WitnessDispatchEmitter.cs:1884`). For value-returning non-throwing witness accessors, `EmitInoutWriteback` is emitted *after* the early `return` (also `EmitClassReturnMethodAccessor:2004`, `EmitBlittableMethodAccessor:1556`). Throwing variants correctly place writeback inside `do` before `return`; the void struct-return variant is reachable — proving the others are misplaced. **P2** — secondary to deferred item 1; would still drop the Swift-side mutation even after the C# side is fixed.

8. **Bare-`Any` parameter throws (`ExistentialProjection.cs:84`).** **NOTE: CONFIRMED** as the §1 throw finding (item 7); the P2 entry is the same defect.

## 4. Checked & refuted (do not re-chase)

- **`ExistentialContainer0.Unbox` throws `NotSupportedException` for any non-primitive `Any` *return*** (`ExistentialContainer.cs:179`). **Refuted.** A direct `func produce() -> Any` returning a class/struct does NOT throw and does NOT call `Unbox` — the @_cdecl indirect-result path (`WrapperEmitter.Return.cs:715-743`/`944-950`) emits `return existentialResult;` (the raw `ExistentialContainer0` boxed to `object`), and `GetReturnPlan`'s `Unbox` branch (`ExistentialProjection.cs:113`) is dead code for scalar returns because existential returns always force `IndirectResult` under @_cdecl (`MarshallingHelpers.IsCdeclIndirectResultRequired`). The `Unbox`-throws behavior only fires via the *element* path (`ExistentialProjection.cs:158`, `[Any]`/`[String:Any]`/`Any?` elements) — that is a real but **different** defect (and the int→long element drift is captured in §1). The scalar-return case has a separate, milder usability issue (caller receives an opaque container struct, no crash), not the claimed asymmetric throw.

## 5. Coverage gaps (what this track did NOT reach)

- **No live runtime execution of a built BindingTests app.** All P0/P1 proofs are standalone Swift/C/C# probes replicating the emitted ABI, plus inspection of committed/freshly-generated output. The owned-collection-element leak (§1 item 8) and the ObjC-bridgeable UAF (§2) specifically lack a `LifetimeTracker.AssertLiveCount(0)` / `GC.Collect` end-to-end gate.
- **`ExistentialBypassEmitter.cs` was named in scope but not deeply probed** — the audit's existential work concentrated on `ModuleHandler`/`WitnessDispatchEmitter`/`ProtocolProxyEmitter`. A targeted pass on the bypass emitter's interaction with the owned-return paths is unverified.
- **The seven §3 deferred candidates** (inout drop, composition dead-receiver, `MarshalToSwift` over-copy, leading-`I` strip, dead-code writeback) are unprobed beyond source reading.
- **Multi-protocol composition (EC2..EC8) ARC paths** were touched only via the P0 (which fires for compositions too) and the dead-receiver candidate; the composition release mechanism (`ModuleHandler` empty-Dispose proxies) was not independently ARC-audited.
- **Setter direction for existentials** (C# sets a Swift-vended `any P` property) was not probed.

## 6. Recommended BindingTests fixtures

One fixture per confirmed defect. Describe the Swift shape that locks it down (no fix code).

1. **Opaque `any P` owned-return double-release (P0).** Swift `protocol P { func tag() -> Int }` (non-class-bound) + `protocol Factory { func make() -> any P; var current: any P { get } }`, with a Swift **class** conformer that increments a static deinit counter, AND a separate **boxed-value** conformer (a struct with ≥4 embedded class refs, exceeding the 3-word inline buffer). From C#: call `make()`/`current`, `Dispose` the returned proxy, `GC.Collect()`+`WaitForPendingFinalizers()`, assert deinit count == 1 (today: double-deinit / SIGSEGV). Add a class-bound control (`protocol P: AnyObject`) which must pass — isolates the missing opaque retain.

2. **Optional-existential receiver returns nil (P1 silent).** Swift `protocol Maker { func make() -> (any Shape)?; func makeNonOptional() -> any Shape }` consumed by a Swift function `func ask(_ m: Maker) -> Bool { m.make() != nil }`. C# implements `Maker` returning a real non-null `Shape` from `Make()`. Assert Swift sees the value (today: always nil). The non-optional method is the in-fixture control proving the infra works.

3. **EveryProtocol value-type return/subscript/getter leak (P1).** Swift `protocol Counter { var n: Int { get }; func compute() -> Int; subscript(i: Int) -> Int { get } }` (value-type, non-String, non-ObjC). Implement in C#; from Swift call each member in a tight loop (e.g. 1M); assert native RSS / a custom-allocator counter stays flat (allocs == deallocs). Include a String-returning member as the flat control. **Must cover all three: getter, method, AND subscript.**

4. **`ExistentialContainer0` int→long drift (P1).** Runtime unit test (Swift.Runtime layer) plus a BindingTests `[String: Any]` round-trip: place `{ "count", 42 }` (a C# `int`, not `42L`) into a Swift `func echo(_ d: [String: Any]) -> [String: Any]`-style API; assert the round-tripped value is recoverable as `int` (today: boxed `long`, `(int)` throws). Pair with the existing long-only test to document the asymmetry.

5. **Bare-`Any` parameter throws on non-primitive (P1).** Swift `protocol Sink { func accept(_ x: Any) }` (or a free `func consume(_ x: Any)`) consumed by Swift. From C#, call with (a) an `int` (must succeed) and (b) a generated Swift class instance and a Swift struct (today: `NotSupportedException`). Documents the gap and the desired class-via-handle / value-via-`allocBox` round-trip.

6. **Owned collection-element existential leak (P1).** Swift `func makeAll() -> [any P]` returning N freshly-allocated class conformers at +1 (also `[K: any P]` and `Set<any P>` variants). From C#: consume/`Dispose` the returned collection, `GC.Collect()`+`WaitForPendingFinalizers()`, assert each conformer's deinit ran exactly once (`LifetimeTracker.AssertLiveCount(0)`). Compare against the optional-existential return which balances — isolates the array/dict/set element gap. **This is the missing live deinit-count harness §5 calls out.**

7. **Class-bound `[any P]` array wrong stride (P1 ABI).** Swift `protocol Marker: AnyObject { func id() -> Int }` + `protocol MarkerProvider { var markers: [any Marker] { get } }` implemented in C# returning a 3-element list of class-bound conformers, passed to a Swift consumer `func sumIds(_ p: MarkerProvider) -> Int` that iterates `markers` and touches element[1] and element[2] (calls `id()` on each). Today: corruption/SIGSEGV at element[1]. Add a non-class-bound `[any Describable]` control (correctly 40B both directions) and a `func count(_ xs: [any Marker])` parameter-direction variant (same 40B param bug).
