# Track A6 — Concrete Specialization (CSM) / Generics / PAT

Scope: CSM specialization engine + emitters, bound-generic translation, conformance graph, and method-generic-bridge result-pointer marshalling.

**Overall risk: 4 / 5** (confidence: high). Two distinct families of confirmed memory-safety defects on the generic-specialization paths — one shipping/reachable (the CSM class-conformer carrier-wrapping use-after-free), one latent-but-unguarded (the `MethodGenericBridgeEmitter` fixed-256-byte result buffer that double-frees / heap-overflows for non-frozen-struct and >256-byte returns). The shipping one is rated P0 because it is reachable through plain ABI conformance with no hint, was reproduced end-to-end with the generator, and corrupts the returned handle on first use. Several of the higher-severity *inconclusive*/*deferred* candidates (CS0305 bound-generic arity, sugar-canonicalization false-rejects, Self-rooted associated-type leaks) point at real fragility but either split on a different mechanism than originally claimed or were not decisively probed within the per-track cap.

### CSM class-conformer carrier-wrapping use-after-free (`ConcreteProtocolSpecializationEmitter.cs:1715`)

The decisive defect of this track. When a CSM-specialized method returns its generic parameter and that parameter resolves to a Swift **class** conformer, the emitted Swift wrapper stores the class object reference *into* the result carrier buffer (`resultPtr.initializeMemory(as: (C).self, repeating: _result, count: 1)`), so the object pointer lives at `*resultPtr`. The C# side then calls `SwiftMarshal.MarshalFromSwift<C>(resultPtr)` — passing the carrier **address**, which `NewFromPayload` stores directly as the Swift object pointer (`SwiftClassHandle` holds the pointer with no buffer indirection). The carrier is then freed at line 1767 (`Marshal.FreeHGlobal(resultPtr)`). The returned object's handle therefore aliases freed memory; the genuine reference stored inside the carrier is leaked. Reachability is confirmed: `CanEmitConcreteOverloadForPairing` admits `ConformerCategory.Class` indirect returns (2113-2116), and the Class branch is neither ownership-transfer (1560 only sets `returnTypeIsDirectWrap` for `NonFrozenStruct`) nor wire-destroy, so it falls into the bare alloc-then-`FreeHGlobal` path. The correct emission is `MarshalFromSwift<C>(*(IntPtr*)resultPtr)`. Both reviewers independently reproduced this; the second triggered it from plain ABI conformance with **no specialization hint**, which makes it a shipping-path defect, not a hint-only edge case. The source comment at 1526-1532 already acknowledges it as a known latent bug deferred alongside the `MethodGenericBridge` fix (roadmap item 60). A secondary over-allocation (line 1600 sizes the carrier with the class **instance** size when it only needs one pointer word) is benign.

### MethodGenericBridgeEmitter result-pointer triple defect (`MethodGenericBridgeEmitter.cs:733 / 837 / 861`)

The generic-method bridge's indirect-result path has three compounding flaws in a single undiscriminated branch, all confirmed by compiled probes:

1. **Heap overflow** — `Marshal.AllocHGlobal(256)` is a magic constant; the Swift wrapper (`MethodGenericBridgeEmitter.cs:496`) writes the full Swift `stride` via `initializeMemory`. A 320-byte `@frozen` struct overruns by 64 bytes (guard-page SIGBUS confirmed; matched control returned cleanly). `CdeclReturnMapping.Classify` routes **all** structs, non-empty tuples, and complex enums to `IndirectResult`/`needsResultPtr=true` with **no size gate**, and `TryEmit`/`IsEligible` reject only generic-param-bearing and metatype returns — so `func makeBig<T: P>(_:T) -> BigStruct` is fully eligible.
2. **Double-free + allocator mismatch** — for a non-frozen struct, `MarshalFromSwift<T>` adopts the wire pointer into a `SwiftSafeHandle` (freed via `NativeMemory.Free`), then `finally { Marshal.FreeHGlobal(resultPtr); }` frees it again with a different allocator.
3. **+1 ARC leak** — for a frozen-with-memory return, the wire buffer keeps its +1 retains on inner ref fields and the bare `FreeHGlobal` reclaims the bytes without VWT-destroying them; the CSM emitter fixed exactly this with `needsResultPtrDestroyWireRetains` (`ConcreteProtocolSpecializationEmitter.cs:1706-1711`), never ported here.

Both reviewers noted the path is **latent** in the normal pipeline: the CSM emitter (`ConcreteProtocolSpecializationEmitter`) shadows `MethodGenericBridgeEmitter` for method-level generics, so no `_XM` symbols appear in current BindingTests output and the broken `needsResultPtr` branch is exercised by no test (the one emit-test uses a void return). It is real, present, wired into the dispatch table (`IMethodBridgeEmitter.cs:207`), and documented as roadmap item 59 — it corrupts the heap the moment any caller routes a non-frozen-struct or >256-byte struct return through it. The correct fix mirrors the sibling CSM emitter: size via `GetSwiftTypeSize<T>()`, discriminate ownership-transfer vs copy-out vs pure-value, and skip / scope the free accordingly.

## Inconclusive / needs deeper probe

### BoundGenericsHandler arity reconciliation → CS0305 on nested bound generics (`BoundGenericsHandler.cs:824`, real fault at `:821-822`)

Status: **inconclusive** (one reviewer refuted the *stated mechanism*, one confirmed a real CS0305 via a *different* mechanism — they agree on the conclusion). The claim was that `TranslateBoundGenericTypeToCSharp` over-appends args at line 824 (too many → `Foo<A>` against `Foo<X,Y>`). Both probes showed:

- **Typealias sugar does NOT trigger it** — Swift fully desugars typealiases before the handler sees them; `IntPair<String>` arrives as `Pair<Int,String>` with full arity and compiles correctly.
- **A real CS0305 exists via the opposite mechanism** — for nested bound generics encoded via the `InnerType` chain (`Outer<Int>.Inner<String>`), the parser puts the outer args on `namedTypeSpec.GenericParameters` and the leaf's own args on `InnerType.GenericParameters`. The early return at `BoundGenericsHandler.cs:821-822` (`if (namedTypeSpec.InnerType != null && outerArgsPlaced) return typeName;`) returns the outer-qualified name with the leaf segment **bare**, dropping the leaf's generic args (too **few**). Reproduced: generator emitted `public Outer<nint>.Inner MakeInner()` against `partial class Inner<C>`, compiling with `error CS0305: ...Inner<U>... requires 1 type arguments`. `binding-report.json` showed the method emitted as fully bound, not gated. `Outer<Int>.Leaf` (non-generic leaf) compiled fine.

The root absence (nothing in `TranslateBoundGenericTypeToCSharp` reconciles the typespec's per-segment arg count against each segment's declared C# arity) is genuine and matches roadmap item 22. The cited line (824) is the wrong line and the cited trigger (typealias sugar) is wrong, so the claim **as written** is refuted, but a real defect lives one early-return up. Treat as a confirmed CS0305 bug whose exact site needs to be re-pinned at 821-822, then probed for a fix. `TryValidateGenericTypeConstraints` (line 1183) iterates `Math.Min(decl, spec)` and cannot flag the shortfall either.

## Checked & refuted

Recorded so future agents don't re-chase. Each was probed (compiled Swift + ABI dump + generator run, or direct reflection invocation), not merely read.

- **Cross-depth generic aliasing: parent `τ_0_0` overwrites method-own `τ_1_0` in `SubstitutePairingGenericsInTypeSpec`** (`ConcreteProtocolSpecializationEmitter.cs:568` / `Async.cs:254`). The symmetric match in `SubstituteTypeSpec` (no precedence, parent-first pairing) is real **in isolation**, but **unreachable**: every substitution call site is gated by `CanEmitConcreteOverloadForPairing`, which rejects (2068-2073) any composite return whose raw typespec contains a `τ_`-named generic (`ContainsAnyGenericParam`, 2757). Five compiled probes plus a direct reflection probe confirmed the ABI digester always emits method-own generics as `τ_1_0` in composite-return positions → always rejected at the gate → the symmetric clobber is dead-path behavior. Worth hardening (add exact-match-first to the substitution path) but fixes no reachable defect.
- **Protocol-composition conformance constraint `T : P & Q` stored as one opaque target** (both the parent-level `ConcreteSpecializationEngine.cs:1063` and per-method `:1481` variants, and the `CollectAllProtocolConstraints` variant). **Refuted across four independent probes.** Swift canonicalizes every protocol-composition constraint into separate comma-separated atomic requirements **before** serializing `genericSig`; `where T: P & Q` arrives as `<τ_0_0 where τ_0_0 : P, τ_0_0 : Q>` (byte-identical to the separate spelling). `SplitTopLevelCommas` then yields one single-protocol target per clause. The missing `Split('&')` is a harmless no-op because the input never contains `&` in a constraint position. Confirmed across where-clause, inline-decl, method-level, 3-protocol, stdlib-mixed, and cross-module shapes; end-to-end generation produced `csmConformerRejections: []`. Roadmap item 29's revisit trigger structurally cannot fire from real ABI.
- **SameType method constraint ordinal compare without sugar canonicalization** (`ConcreteSpecializationEngine.cs:1266`). The code asymmetry is **real** (SameType branch uses ordinal `string.Equals`; dependent-member branch normalizes), but the **impact is refuted**: ABI-sourced conformers structurally cannot carry a sugared/Optional `SwiftQualifiedName`. `swift-api-digester` attaches conditional conformances to the **bare** generic (never a concrete `Foundation.Data?` witness); `SwiftTypeName.FromModuleQualifiedName` throws on a `<`-bearing generic name; and every Array/Optional/Dictionary **hint** conformer in `specialization-hints.json` carries a matching `SwiftLiteral`, so the line-1270 fallback fires. Real-library generation dropped nothing. A latent robustness gap (a future hint omitting `swiftLiteral`), not active lost API surface.
- **ResolvePublicCSharpType bare-leaf fallback → CS0246/CS0305 on CSM signatures** (`ConcreteProtocolSpecializationEmitter.cs:2891`). **Refuted.** The fallback is unreachable on the CSM emitting path: `MethodClosureBridge.ClassifyParam` only returns a passable category inside a successful `TryGetTypeRecord` block (no-record params → `Unsupported` → rejected by `AreNonGenericParamsCompatible`); no-record returns fall to `CdeclReturnMapping`'s `IndirectResult` fallback → rejected because `indirectReturnIsSwiftObject` is false. `CSharpTypeName.FromNamespaceAndName` throws on `<`, so the appended args always match the faithful Swift typespec arity. Compile probes emitted fully-qualified, correct-arity signatures (`Probe.Box<Probe.Coin>`); a foreign no-record param caused the method to be **skipped**, not mis-emitted. The cited roadmap items (22/23/24) implicate `BoundGenericsHandler` and the `Self`-substitution path, not this method.

## Recommended BindingTests fixtures

Swift shapes that would lock down each confirmed defect (and the highest-value candidates). No code fixes proposed — these are the durable end-to-end gates.

1. **CSM class-conformer `returnsGenericParam` round-trip** (locks P0 `:1715`, roadmap 60).
   `protocol P {}; final class C: P { let n: Int32 }; struct Box { func make<T: P>(_ t: T) -> T }`. Register/allow `C` as a `P` conformer (or rely on bare ABI conformance — the probe showed it fires without a hint). C# test: call the emitted concrete overload returning `C`, read `n`, assert == the stored value (not 0/garbage), and assert object identity survives a second use. Run on **both** Mono and NativeAOT — the carrier-vs-object aliasing and the freed handle behave differently across runtimes. A non-generic class return is the negative control (already works).

2. **MethodGenericBridge non-frozen-struct return** (locks the P0 double-free + leak, roadmap 59).
   `final class Holder {}; protocol P: AnyObject {}; extension Holder: P {}; struct NonFrozenBox { var r: SomeRefField } /* non-frozen */; struct Box { func make<T: P>(_ x: T) -> NonFrozenBox }`. The bridge overload (`Make(ISwiftObject)`) must coexist with any CSM overload — pass a protocol/`ISwiftObject`-typed argument so binding routes to the bridge. Call in a tight loop under `LifetimeTracker`; assert no double-free crash and live-object count returns to baseline (currently the SafeHandle adopts then `FreeHGlobal` double-frees, and frozen-with-ref leaks +1/call).

3. **MethodGenericBridge >256-byte return** (locks the P0 heap overflow).
   `@frozen struct Big { /* 40 × Int64 = 320 bytes */ } ; struct Box { func makeBig<T: P>(_ x: T) -> Big }` where `Big` does not mention `T`. C# test: call via the bridge overload and assert the **tail** fields (e.g. field 39) read back correctly — truncation/overflow corrupts bytes past offset 256. Run under guard-malloc / ASan if available; even without a crash, a tail-field mismatch fails the assertion.

4. **CSM frozen-with-ref-field return leak** (locks the missing `DestroyWireBufferRetains` on the bridge path; already correct on the CSM path — this fixture proves the bridge regression once it's reachable).
   A method-generic-bridge method returning a `@frozen` struct with a String/class field, called in a loop under `LifetimeTracker`; assert the field's live count returns to baseline.

5. **Nested bound-generic member return** (locks the inconclusive CS0305, roadmap 22).
   `struct Outer<A> { struct Inner<B> {} } ; func makeInner() -> Outer<Int>.Inner<String>`. Compile-gate only: assert the generated `MakeInner()` return type carries **both** segments' args (`Outer<nint>.Inner<Swift.SwiftString>`), not the bare `Outer<nint>.Inner` that currently emits and fails CS0305. Negative control: `Outer<Int>.Leaf` (non-generic leaf) already compiles.

6. **Renamed/lowercase generic parent CSM** (locks deferred candidate #3/#6 if confirmed).
   `struct box<T: SomeProto> { func append<D: DataProtocol>(_ d: D) {} }` (lowercase-leading) with a registered conformer. Compile-gate: the emitted CSM extension receiver must reference `Box<Conformer>` (the pascalized class), not `box<Conformer>` → otherwise CS0246.
