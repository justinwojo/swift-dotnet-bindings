# Regression Audit R1 — TypeDatabase Truth Refactor (Session 9)

**Scope:** Regression hunt over commit `b297b66f` ("Make TypeDatabase the single source of ABI truth") — `TypeDatabase.cs` / `ModuleDatabase` / `TypeResolver.cs` / `TypeDatabaseExtensions.cs`, the `IsSynthesizedAccessor` migration, ABI ingestion gates (SWIFTBIND033 format-version, SWIFTBIND034 unknown-kind, missing-`mangledName` drop SWIFTBIND046, AssociatedType consumption), and `Register(record, ConflictPolicy)` + the `Freeze()` point.

**Overall risk: 3 / 5** (confidence: high — both confirmed defects were probe-demonstrated end-to-end against real validation libraries with a freshly rebuilt Debug generator). The risk would be 4/5 if the strict gate were on a consumer path, but the blast radius is bounded to `--strict-inputs` invocations (the CI/release gate) and to report/reconciliation accounting; functional emission of the affected bindings is unaffected.

**Confirmed: 2 findings, BOTH regressions** introduced by `b297b66f`. They are two faces of the *same* root cause (the new bindable-kind missing-`mangledName` gate has no ObjC/C-interop exemption): one face hard-fails generation under `--strict-inputs`; the other corrupts the reconciliation tally + `InputResolutionReport` on **every** ObjC-touching binding in normal (non-strict) mode. No pre-existing-unaudited confirmed defects.

### Finding 1 — Strict-inputs hard-fail for ObjC-rooted Swift classes (Quick / Firebase / BRLMPrinterKit)

`SwiftABIParser.cs:1256-1260` introduces, in `b297b66f`, a bindable-kind gate that throws `AbiRecordDroppedException` whenever a `Struct`/`Enum`/`Class`/`Protocol` node has an empty `MangledName`. The author correctly exempted the non-bindable `Module` container (test `ParseModule_NonBindableModuleNodeMissingMangledName_IsSkippedNotDropped`) but **not** ObjC-rooted classes, whose identity is the ObjC USR (`c:objc(cs)…`) with `declAttributes` containing `ObjC`/`Dynamic` and no Swift mangled name — the *expected* ABI shape, not digester drift.

The throw is caught in `HandleNode` (`SwiftABIParser.cs:1070-1087`), which sets `droppedWithError` **and** calls `InputResolutionReport.RecordDegradation(AbiJson,…)`. Under `--strict-inputs`, `ShouldFailClosedOnDegradedInputs` / `EmitStrictInputsFailureIfDegraded` (`BindingsGeneratorCommand.cs:1669-1700`) escalate any `AbiJson` degradation to **SWIFTBIND027** and return failure. The strict path is wired into CI/release: `build/Build.BindingTests.cs:357-358` adds `--strict-inputs` whenever `strict` is set, and `--compile-only`'s fail-closed default implies `strict`.

Probe (generator dll built `-c Debug --no-incremental`):
- `--xcframework .libraries/Quick/Quick.xcframework -o /tmp/quick-strict --strict-inputs` → **EXIT 1** (SWIFTBIND046 ×2 + SWIFTBIND027), reduced output (1 `.cs`, no `ApiDefinition.cs`, no compiled `.o`).
- same without `--strict-inputs` → **EXIT 0**, full output.
- `BonMot.xcframework` + `--strict-inputs` → EXIT 1 (15× SWIFTBIND046 on `UIApplication`/`NSAttributedString`/`UIImage`/`UIFont`/`UILabel`/…). These foreign types survive the foreign-reexport gate because `IsSystemReexportAllowedModule` (`AppleFrameworkRegistry.cs:634`) returns true for UIKit/Foundation, so they fall through into the `moduleNameOverride` path and hit the same throw.

A repo-wide ABI scan confirmed the shape across **BonMot, RichTextKit, SnapKit, RxSwift, Kingfisher, Parchment, Stripe, SwiftyGif, DifferenceKit, SwipeCellKit, Quick, Firebase (Analytics/RemoteConfig/DatabaseReference/DataSnapshot/RemoteConfigValue/…), BRLMPrinterKit (BRLMPrinterDriver)** — essentially any third-party Swift module that references ObjC/UIKit/Foundation types. (Note: Swift-defined `@objc` classes such as `AsyncSpec`/`QCKConfiguration` carry `usr 'c:@M@Quick@objc(cs)…'` *with* a real `$s…` mangled name and bind fine — only the pure `c:objc(cs)` nodes with no mangled name trip the gate.)

The regression test `ParseModule_BindableTypeMissingMangledName_DropsLoudly` (`AbiIngestionContractTests.cs:187-215`) codifies the drop using a synthetic `Ghost` node with **no** USR and **no** ObjC `declAttributes` — i.e. it locks in the drop for a non-ObjC node and does not guard the real ObjC case.

**Scoping caveat (does not refute):** neither `nuke validate` nor the consumer-facing SDK `dotnet build` passes `--strict-inputs`, so a normal consumer build of a Quick/BonMot binding still succeeds with only SWIFTBIND046 warnings. The hard failure manifests specifically under any `--strict-inputs` invocation — the documented `nuke binding-tests --strict --compile-only` CI/release gate. Defect and mechanism are real and reproduced; practical blast radius is bounded to whatever modules flow through a `--strict-inputs` run.

### Finding 2 — Always-on reconciliation/report corruption for ObjC/C-interop decls in NON-strict mode

Same gate (`SwiftABIParser.cs:1256-1259`), different damage surface that Finding 1 does **not** cover. In the pre-`b297b66f` code the identical null-`mangledName` condition logged a warning and `return null` → counted `SkippedWithReason` (benign), with no degradation recorded. The Session-9 change converts these benign skips into `DroppedWithError` + an `AbiJson` degradation on every ObjC-touching binding, **regardless of `--strict-inputs`**.

Probe: `Swift.Bindings.dll --xcframework .libraries/BonMot/BonMot.xcframework -o /tmp/bonmot-probe/out` (exit 0, no strict). Persisted `binding-artifact-manifest.json`:
- `Generation/ParseReconciliation/DroppedWithError = 15` — the "silent-failure channel" that Finding 14a's `DroppedWithError` bucket exists to make trustworthy is now full of false positives.
- `InputResolution/Status = Warning`, `DegradationCount = 15`, each an `AbiJson` "ABI declaration dropped" `Degradation`.

Every one of the 15 is a foreign ObjC class (`usr 'c:objc(cs)…'`, `declAttributes` contains `ObjC`) or a C-typedef struct (`Foundation.Key`, `usr 'c:@T@NSAttributedStringKey'`). Emission is unaffected: `BonMot.cs` references `UIKit.UIFont` / `Foundation.NSAttributedString` etc. (53 refs) resolved via the Apple supplement — the dropped digester re-export nodes were never needed. The damage is confined to the reconciliation accounting, the `InputResolutionReport`, and (when strict) the SWIFTBIND027 hard-fail of Finding 1.

**Shared root-cause fix (do not implement here):** scope the missing-`mangledName` drop to NON-ObjC-rooted bindable kinds — skip cleanly (`return null` → `SkippedWithReason`) when `declAttributes` contains `ObjC` or `usr` starts with `c:objc(` / `c:@T@`, restoring the pre-refactor silent-skip semantics for ObjC-identity types. The parser already detects ObjC via `node.DeclAttributes` `"ObjC"` (used at ~`SwiftABIParser.cs:1457`, `:2169`, `:2990`) and the `Node` model carries `usr`/`DeclAttributes`/`MangledName`, so the guard is idiomatic and local.

## 3. Deferred (candidate, unverified)

These are genuine candidates that were *not* driven to a decisive probe (per-track cap). Each is recorded with enough detail to resume.

- **`ITypeDatabase.ApplyEmissionResult` default is a silent no-op** — `src/Swift.Bindings/src/TypeDatabase/ITypeDatabase.cs:122`. Session 9 routes both the nested-type collision rename and all emission facts (`EmittedClassMethods`/`EmittedMemberCount`/`EmittedMetadataPInvoke`) **exclusively** through `ITypeDatabase.ApplyEmissionResult`, whose interface body is `{ }` (empty default, confirmed at line 122 — "No-op default for test mocks"). Any `ITypeDatabase` implementation other than the concrete `TypeDatabase` (test doubles, future alternate DBs) now silently swallows every rename + every stamp, with no diagnostic. Pre-Session-9 the rename was an in-place mutation of the record returned by `TryGetTypeRecord`, so a mock returning a real record still observed it. *Probe to resume:* a minimal `ITypeDatabase` mock that overrides `TryGetTypeRecord` to return a real record but not `ApplyEmissionResult`; run `NameProvider.PrecomputeNestedTypeRenames` on a TypeDecl with a known nested-type/property collision; assert the record's `CSharpTypeName` is unchanged → rename vanished. (P2, regression.)

- **`ApplyEmissionResult` silent no-op for module-alias / `@_implementationOnly` umbrella-resolved records (latent)** — `src/Swift.Bindings/src/TypeDatabase/TypeDatabase.cs:745`. The write side (`_modules[name.Module]` exact + `_outOfModuleTypes[name]` exact) does not consult the `_moduleAliases` (CoreFoundation→CoreGraphics) or `GetCompileImportSourceModules` umbrella (RealityKit→RealityFoundation) fallbacks that the **read** side `TryGetTypeRecordInternal` (`TypeDatabase.cs:866-911`) honors. Several stamp sites guard with the *broad* `TryGetTypeRecord` then stamp via the *narrow* `ApplyEmissionResult`. Three separate refutations below (nested-rename, class-methods ×2) each found this divergence **real in isolation but unreachable today** because the producer key equals the storage key in the real pipeline. Flagged P2 as a **latent foot-gun**: if any future change lets an umbrella/alias-qualified decl reach a stamp site, the fact is lost with no diagnostic. *Cheap hardening:* route `ApplyEmissionResult` through the same cascade as the read, or assert/log when the exact-key write misses a key the cascade resolves. (P2, latent.)

- **`json_format_version` gate (SWIFTBIND033) reads only the root `ABIRoot` node** — `src/Swift.Bindings/src/Parser/SwiftABIParser.cs:887`. `GateAbiFormatVersion` reads `_moduleRoot.ABIRoot.json_format_version` only; the new field is populated on any node but consulted only on that one root. If a future digester stamps the version on a non-`ABIRoot` node (or vice-versa), the gate reads `null`, emits a spurious SWIFTBIND033 `AbiJson` degradation, and fails closed under `--strict-inputs` on valid input. Marked **not** a current regression (all 818 repo ABI files are v8 on `ABIRoot`), but unaudited new surface. *Probe to resume:* unit-test `ParseModule` with an `ABIRoot` whose `json_format_version` is null and a child carrying 8; assert a degradation is recorded (confirming root-only read). (P2, not a regression.)

- **`IsSynthesizedAccessor` lost the `required` compile guard** — `src/Swift.Bindings/src/Model/TypeDecl/MethodDecl.cs:70`. Migration replaced `public required Visibility Visibility` with `public bool IsSynthesizedAccessor { get; set; } = false;` (non-required, confirmed at line 70). The b297b66f migration is value-correct at all existing sites (4 parser `Visibility.Private` sites → `IsSynthesizedAccessor = true`; readers `ClassHandler:688` and `ConstrainedExtensionEmitter:1086` map `Public ↔ !IsSynthesizedAccessor`), and `Visibility.Internal` was never assigned, so its loss is benign. The smell: a **future** synthesized-accessor construction that forgets the flag silently defaults to `false` → `GetAccessModifier` (`NameProvider.cs:849`) returns `"public"`, producing a public accessor that collides with the public property/indexer (CS0111 or an inadvertently-public helper) with no compile error. *Resume:* restore `required` on the bool, or add a guard test asserting every `CreatePropertyGetter`/`Setter`/`SubscriptAccessor` product has `IsSynthesizedAccessor == true`. (P2, maintainability regression — no live bug today.)

## 4. Checked & refuted (brief)

- **`ApplyEmissionResult` drops the nested-type collision rename for alias/umbrella/Ref-variant/type-alias-keyed records (CS0102/CS0542)** — `TypeDatabase.cs:745`. *Refuted (medium).* The exact-key-write vs cascade-read asymmetry is real in isolation (a /tmp probe reproduced the no-op), but **unreachable**: the parser registers every type under its own `structDecl.SwiftTypeName` (`ModuleProcessor.cs:412`), exactly the key `ApplyNestedTypeRenames` walks; `moduleNameOverride` sets the type's own canonical module and children inherit the parent prefix, so registration key == rename-walk key. The asymmetric storage shape needed to reproduce the loss does not arise in real generation; no faithful end-to-end CS0102/CS0542 could be constructed.

- **`ApplyEmissionResult` no-ops the protocol `EmittedMemberCount` stamp for supplement-resolved protocols** — `ProtocolHandler.cs:503`. *Refuted (high).* Mechanism real in isolation, defect unreachable: the Apple supplement owns **zero** protocols (manifest is 14 entries, all `kind:struct`; `AppleSupplementResolver`'s kind switch has no `protocol` case), supplement-owned types are emission-suppressed before dispatch (`IHandler.HandleBaseDecl:251-262`), and any protocol that reaches the stamp was parsed into `_modules` (`ModuleProcessor.cs:1424-1425`) before `EmitModule`, so the exact-key write hits. The no-op-on-unknown is intentionally contract-tested (`RegistryContractTests.ApplyEmissionResult_UnknownType_IsNoOp`).

- **`CollectAndStampClassMethods` loses `EmittedClassMethods`/`EmittedMetadataPInvoke` for umbrella/`@_implementationOnly` classes** — `ClassHandler.cs:590`. *Refuted (high), twice independently.* The umbrella read/write divergence is real in isolation, but at the ClassHandler call site the read key, write key, and storage key are the **same** `classDecl.SwiftTypeName` value (registered at `ModuleProcessor.cs:856`; `SwiftTypeName.FromTypeSpec` does no umbrella/compileImport remap). The umbrella name only ever appears as a cross-module *reference*, never planted into a `ClassDecl.SwiftTypeName.Module`. Additionally: the old `UpdateTypeRecord` used the identical exact-key strategy (no key-resolution change across the refactor), and even a lost stamp would not produce CS0115 — the verifier treats a null `EmittedClassMethods` as a fail-safe "trust Swift's `IsOverride` bit" legacy fallback (`WrapperEmitter.Signature.cs:493-511`).

- **Broad sweep of ConflictPolicy migration, freeze point, supplement double-consult removal, AssociatedType/OperatorDecl allowlist, `TryGetTypeRecordWithoutSupplement`** — `TypeDatabase.cs:178` / `Program.cs:417`. *Verified clean.* Every `RegisterType → Register(…, KeepExisting)` conversion is behind a `!IsTypeProcessed` guard (dead-equivalent to old last-write-wins); unguarded conversions use `Overwrite` (= old last-write-wins). `Freeze()` runs after all structural writes; every post-freeze pass writes only via `ApplyEmissionResult` (whole Emitter/Marshaler tree grepped — no `UpdateTypeRecord`/`RegisterType`). Live probe: BonMot/Alamofire/CodeScanner/AMPopTip generate with **zero** SWIFTBIND045 freeze violations. AssociatedType was already consumed in `CreateProtocolDecl` pre-commit; the HandleNode reclassification only retires false `DroppedWithError` noise (an improvement). The supplement double-consult removal is behavior-preserving (`TypeOwnerRegistry` Level-4 claims Apple-module identities before Level-5; `AppleSupplementStrategy` precedes `DatabaseLookupStrategy`).

## 5. Coverage gaps

- **No test feeds an ObjC-rooted node (USR `c:objc(cs)…` + `ObjC` `declAttributes`, no `mangledName`) through `ParseModule`.** The only mangled-name-drop tests use a synthetic non-ObjC `Ghost` node (`AbiIngestionContractTests.cs:187`) and a `Module`-kind exemption (`:282`). The real-world case — a pure-ObjC class that legitimately has no Swift mangled name — has **no** guard, which is precisely why the regression shipped. Any fix must add a positive test that such a node is `SkippedWithReason` with **no** `AbiJson` degradation and **no** `DroppedWithError` increment.
- **No `--strict-inputs` end-to-end gate over a real ObjC-class-exporting library.** `nuke binding-tests --strict --compile-only` runs the strict path but its fixtures evidently do not include a pure-`c:objc(cs)` no-mangled-name class, or this would have been caught. The strict gate needs a fixture that exercises the foreign-ObjC ingestion path.
- **`RegistryContractTests` has no alias/umbrella `ApplyEmissionResult` case.** The exact-key-write vs cascade-read asymmetry (refuted as unreachable today, deferred as latent) is entirely untested; a contract test asserting either parity or a loud miss would prevent a future reachable regression.
- **No test asserts `ABIRoot` is the canonical `json_format_version` carrier** across shipped digester outputs (incl. the project's own supplement artifacts).
- **No compile-time guard re-enforces "synthesized accessor ⇒ private"** now that `required` is gone from the migrated field.

## 6. Recommended BindingTests fixtures (Swift shapes only — no fixes proposed)

1. **ObjC-rooted Swift class with no Swift mangled name (Finding 1 + 2, primary lock-down).** Add a Swift source shape that produces a pure `c:objc(cs)…` ABI node: an `@objc` class (or, more faithfully, a module that re-exports an imported ObjC class such as a UIKit/Foundation type) whose ABI declaration carries `mangledName: null`, `declAttributes: ['ObjC','Dynamic']`. Gate it under the strict ingestion path and assert (a) generation succeeds, (b) the node is `SkippedWithReason` (not `DroppedWithError`), (c) no `AbiJson` degradation is recorded. This is the durable end-to-end equivalent of the Quick/BonMot probes.

2. **Swift module that references UIKit/Foundation ObjC types (Finding 2, reconciliation lock-down).** A binding source that touches `NSAttributedString` / `UIFont` / a `…Key` C-typedef struct, asserted under non-strict generation to produce a `ParseReconciliation` with `DroppedWithError == 0` for those foreign references and `InputResolution/Status == Healthy` (no false-positive degradations) while the functional members still emit and round-trip.

3. **Swift-defined `@objc` class WITH a real mangled name (negative control).** A class that genuinely carries `usr 'c:@M@…@objc(cs)…'` + a `$s…` mangled name (like `AsyncSpec`/`QCKConfiguration`) — assert it binds normally and is unaffected by any ObjC exemption, so the fix's exemption stays scoped to *mangled-name-less* ObjC-identity nodes only.

4. **Stored property / subscript accessor round-trip (`IsSynthesizedAccessor` lock-down).** A type with a public stored property and a subscript whose synthesized getter/setter must emit as `private` C# helpers behind the public surface — asserting `GetAccessModifier == "private"` at the accessor level, so any future regression of the non-`required` default to `public` (CS0111 / inadvertently-public accessor) is caught end-to-end.
