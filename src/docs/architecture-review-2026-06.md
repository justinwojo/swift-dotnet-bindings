# Architecture Review — June 2026

Read-only architectural review targeting **decade-scale maintainability and reliability**, with
the explicit lens that this codebase is maintained by AI agents (memory:
`user_project_ownership`). Findings are limited to *major* overhauls — changes that remove a
whole class of future bugs or a whole category of ongoing maintenance burden. Minor cleanups are
deliberately excluded.

**Method.** Two passes. *Part I (breadth):* seven parallel subsystem explorations (generator
core, emitter, parser, runtime, SDK/packaging, Nuke harness, test landscape), followed by
first-hand verification of every load-bearing claim — each Part I citation was read directly
unless marked *(reported)*. *Part II (depth):* four top-model deep-audit agents over the
interiors the breadth pass only sampled (emitter hairy corners, emitter core/infrastructure,
Marshaler/TypeDatabase/orchestration, Swift.Runtime lifetime semantics), each primed with
Part I's findings so they hunted only for what was *not* already found, and barred from
re-proposing roadmap-rejected work. Part II's flagship claims were then spot-verified
first-hand (5 of 5 confirmed, including one live defect in shipped generated artifacts);
verification status is stated per finding. Existing decisions in `roadmap.md` were honored
throughout — the rejected async-emitter merge and the deferred capability-typed projection
model are **not** re-proposed; where a finding is adjacent to one of those, the distinction is
stated.

**Headline sizes** (measured): generator `src/Swift.Bindings/src` ≈ 204k LOC across 389 files
(Emitter alone 126k); unit tests ≈ 271k LOC / ~10,458 tests; `Swift.Runtime` ≈ 18.9k LOC;
Nuke build ≈ 19.3k LOC; `Sdk.targets` 3,211 lines / 43 targets; BindingTests ≈ 30k Swift LOC +
2,583 runtime test methods.

## Finding 1 — `Sdk.targets`: move real logic out of escaped shell, into the generator CLI

### Evidence (verified)

`Sdk.targets` is 3,211 lines with 43 targets and **zero** compiled tasks (no `UsingTask`
anywhere). All non-trivial logic runs as `<Exec>` shell strings inside MSBuild XML. The three
worst artifacts:

- **`_SynthesizeAppleFrameworkConsumerTargets`** (`Sdk.targets:2880–2991`): a single `<Exec>`
  whose shell builds two heredoc fragments and `cat`s a third heredoc to generate the consumer's
  `$(PackageId).targets` — MSBuild XML generated by shell embedded in MSBuild XML. The block
  navigates **three escaping regimes simultaneously**: XML entities (`&quot;`, `&lt;`) for the
  MSBuild parser, `%24` for `$` that must survive MSBuild evaluation into the shell, and `\%24`
  for `$` that must survive both MSBuild *and* heredoc expansion to reach the consumer's build
  (`Sdk.targets:2929` vs `:2907` show the two `$`-escape levels side by side).
- **`_ComputeSwiftFingerprint`** (`Sdk.targets:572–639`): two parallel ~33-line
  `find | shasum | sort | shasum` shell pipelines (xcframework mode and Apple-framework mode).
  The generation-affecting property list is **manually echoed** into each hash
  (`Sdk.targets:602`, `:635`) — and `constraints.md` rule 46 records an actual shipped bug from
  exactly this: `$(SwiftTargetArchitectures)` had to be added to *both* echo strings or a stale
  arm64-only wrapper was silently reused.
- **`_ResolveSwiftAutoDetectedDependencies`** (`Sdk.targets:1836–1870`): an in-line POSIX-shell
  parser (`pctdec()` + `tr ';' '\n' | while IFS='|' read`) implementing a pipe-delimited,
  percent-encoded data protocol across the MSBuild↔shell boundary, decoded on the way back by
  `$([System.String]::Copy(…).Split('|')[2])` property functions.

Two **parallel implementations of the same consumer-facing output** exist: the consumer
`.targets` file is emitted by the shell heredoc above for Apple-framework mode and by
`ConsumerTargetsEmitter.cs` (C#) for xcframework mode — same content shape (NativeReference
items, catalyst-x64 workaround, `SwiftBindingFramework` item, module-database item), maintained
twice *(structure reported, heredoc half verified directly)*. A smaller acknowledged mirror:
`NativePackagingPolicy.ShouldIncludeSourceXcframework` (C#, truth-table-tested,
`NativePackagingPolicy.cs:73`) vs the `_ComputeSwiftBindingSourceXcframeworkInclusion` MSBuild
property — the C# doc comment itself explains the MSBuild side "cannot share this C# helper
directly" (`NativePackagingPolicy.cs:56–62`).

Testing this surface currently requires **copy-pasting the shell strings into the test file**:
`SdkTargetsBehaviorTests.cs:182–191` carries `SwapCommand`/`WrapperRecoveryCommand` marked
"verbatim from Sdk.targets". Nothing checks the copies still match the targets file — if the
`<Exec>` is edited, the test keeps green against the *old* string.

### Why this is decade-risk

`Sdk.targets` runs on **consumer machines** — it is the single most outward-facing reliability
surface in the product, and it is written in the least testable, least greppable, least
AI-legible dialect in the repo (triple-escaped shell). Every bug class documented around it
(constraint 45's "exists now vs will-be-produced" trap, constraint 46's four-trap wrapper-arch
dance, the fingerprint echo-list omissions) is a direct consequence of logic living where it
cannot be unit-tested or shared with the C# implementations of the same decisions.

### Overhaul shape

The repo already has the right pattern — the SDK shells out to the generator for real work in
seven places (`--slice-xcframework`, `--compile-wrapper-only`, `--compile-bridge-only`,
`--detect-apple-cross-module-deps`, `--emit-apple-types-manifest`, …). **Finish that pattern:**

1. Every multi-line `<Exec>` becomes a generator CLI subcommand (or, where startup cost matters,
   a compiled MSBuild task DLL shipped in the SDK's `tools/`):
   `fingerprint` (owns the property list in one place, kills the dual echo strings),
   `emit-consumer-targets` (collapses the heredoc into `ConsumerTargetsEmitter` — one
   implementation, both modes), `resolve-auto-deps` (returns a JSON/items file instead of a
   pipe-delimited stdout protocol), `commit-slice-swap` (the park-aside/recovery dance).
2. `Sdk.targets` shrinks to what MSBuild is good at: discovery, conditions, item wiring,
   diagnostics. Target count stays; `<Exec>` bodies become one-liners.
3. `SdkTargetsBehaviorTests`' copy-pasted shell strings become ordinary unit tests of the
   subcommands; the existing end-to-end MSBuild tests (stub generator + real `dotnet msbuild`)
   remain as the integration layer.

### What it deletes / retires

The three escaping regimes; the duplicated consumer-targets emitters; the hand-maintained
fingerprint echo lists; the verbatim-copy test invariant. Roughly half of `Sdk.targets` by
volume.

### Risk & migration

Medium. Behavior must be preserved exactly (consumer builds depend on it). Migrate one `<Exec>`
at a time; for each, land the subcommand + unit tests first, then swap the target body, then run
PackGate + `--mixed-pack`/`--mixed-direct` for the affected paths. The stub-generator MSBuild
test rig already exists to verify each swap end-to-end.

## Finding 2 — Retire the generate-then-strip wrapper architecture

### Evidence (verified)

The generator knowingly emits uncompilable Swift, and two regex-based post-processors subtract
it afterwards:

- `build/Helpers/SwiftSourceStripper.cs:11–17` (header, quoted): *"The generator emits code for
  ALL features, including unsupported ones that produce uncompilable Swift. This class strips
  those sections so the good async method wrappers can compile."* 1,006 LOC of regex/brace
  stripping, including an **88-entry hand-maintained `PreservedProtocols` allowlist**
  (`SwiftSourceStripper.cs:22–385`) whose staleness failure mode is a runtime
  `EntryPointNotFoundException` in an unrelated test (documented in memory and in the file's own
  comments).
- The harness compile loop (`Build.BindingTests.cs:592–655`): compile → parse `swiftc` error
  lines → `StripErrorFunctions()` deletes the enclosing functions → retry, up to 3 attempts.
  The build literally uses the Swift compiler's error output as a code-deletion oracle.
- The production twin: `src/Swift.Bindings/src/Configuration/SwiftWrapperPostProcessor.cs`
  (614 LOC) strips broken blocks at generation time for real bindings, with per-sub-cause
  thresholds gated by validate (`Other=0`, `NSInvocation=0`, `InternalType=5`) *(reported)*.
- The residual is measured: `BindingTests/baselines.json:7` pins `wrapper_stripped_count: 35` —
  35 known-broken wrappers are emitted and stripped on every BindingTests run today. Per the
  test-landscape exploration, no Nuke target reads `baselines.json` automatically; the ratchet
  is enforced manually.

### Why this is decade-risk

This is an *emit-garbage-then-subtract* architecture. The subtractors parse Swift source with
regexes — inherently fragile against new Swift syntax — and the allowlist couples the build
harness to test-library contents by hand. Worst, the failure mode is **silent**: over-stripping
doesn't fail the build, it removes symbols, and the problem surfaces later as a runtime
`EntryPointNotFoundException` or a quietly weakened test. Every new contributor (human or AI)
must learn the allowlist ritual or lose hours to it; memory already carries a dedicated feedback
entry for exactly this trap.

### Overhaul shape

Invert the decision point: **what cannot compile must not be emitted.** The machinery to decide
already exists — `MemberValidationPipeline` (six ordered gates), the two-layer closure gate
(`IsSupportedClosureParameterType` / `IsCdeclCompatibleType`), `WrapperValidation` — the
strippers exist because those gates are incomplete by exactly 35 measured cases plus the
EveryProtocol conformance set.

1. For each of the 35 stripped wrappers (the stripper can log category + decl), add the missing
   generation-time gate, with the usual tombstone/skip-reason reporting. Drive
   `wrapper_stripped_count` 35 → 0 as an automated ratchet (wire `baselines.json` into the Nuke
   gate so an increase fails the build — today it is manual).
2. Replace the `PreservedProtocols` allowlist with the inverse, generation-time decision: the
   generator already knows which protocols get `EveryProtocol` conformances and which of those
   compile; the harness should not own a second opinion. (The stripper's cross-extension
   witness-dependency pre-scan is evidence of how much type knowledge the build script has had
   to re-derive that the generator already has.)
3. End state: `StripFile` becomes a **fail-closed tripwire** (anything it *would* strip is a
   hard error), then is deleted along with the swiftc-error retry loop.
   `SwiftWrapperPostProcessor` follows the same path for production bindings as its sub-cause
   counts reach zero.

### What it deletes / retires

~1,600 LOC of regex-over-Swift across two strippers; the 88-entry hand list; the
compile-error-driven deletion loop; the "new protocol test → remember the allowlist" tribal
rule; the silent-strip → runtime-mystery failure class.

### Risk & migration

Medium, but incremental by category — each stripped case is independently fixable with TDD
(red fixture first, per memory `feedback_tdd_for_regression_fixes`). No big-bang step. The
wrapper-compile gate stays as the verifying backstop throughout.

## Finding 3 — Finish the swiftinterface migration; delete `SwiftInterfaceAccessParser`

### Evidence (verified)

Two parsers exist for `.swiftinterface` text:

- **Legacy:** `SwiftInterfaceAccessParser.cs` — 5,418 LOC, 32 public methods, each re-walking
  the file with regex + hand-rolled brace counting. Known, documented defects: the
  protocol-requirement visibility heuristic (`roadmap.md:33`), the brace walkers that miscount
  on string defaults (roadmap "Latent" F5), the `@inlinable` access-control guess admitted as
  ambiguous in-source *(reported)*.
- **Replacement, already in production:** `tools/SwiftInterfaceParser` (SwiftSyntax, 5,442 Swift
  LOC) behind `SwiftSyntaxInterfaceFactsProducer`, with a clean incremental-migration design:
  `IInterfaceFactsProducer` + aggregator + per-fact `coveredFacts` signal, and a schema-version
  handshake (`kSchemaVersion = 2` ↔ `ExpectedSchemaVersion`, hard error on mismatch,
  `SwiftSyntaxInterfaceFactsProducer.cs:183–188`).
- **Coverage is already 27 of 30 fact kinds** (`main.swift:110–144` vs `InterfaceFactKind.cs`).
  Only `SpiOnlyConformances`, `ConstLiteralParameters`, and `ClosureParameterAttributes` remain
  regex-only.

The reliability problem is the fallback topology, not the migration pace:

- `BuildAutoAggregator` **silently degrades to regex-only when the staged binary is missing**
  (`BindingsGeneratorCommand.cs:1704–1731`) — two parsers with different bug surfaces, selected
  by an environmental accident. Memory documents the resulting staleness trap (stale staged
  binary + `dotnet run --no-build` = silent mis-mapping).
- The library-entry default is regex-only outright (`Program.cs:256–264`).

### Why this is decade-risk

A 5.4k-LOC regex parser for a compiler-owned text format is a standing tax: every new Swift
toolchain release can change `.swiftinterface` printing, and every change lands on hand-rolled
string matching with documented heuristic guesses. Meanwhile the *correct* parser already exists
and covers 90% of the facts — the codebase is paying for both, plus a silent-divergence channel
between them.

### Overhaul shape

1. Migrate the last 3 fact kinds into the SwiftSyntax tool.
2. Run a **parity bake**: both producers across the full validation corpus, diff every fact set.
   (Objective, cheap, and the aggregator design makes it trivial to run both.)
3. Make the SwiftSyntax producer **required** — fail loud when the binary is missing instead of
   falling back. The product already hard-requires a Darwin toolchain (`xcrun`, `swiftc`,
   `swift-api-digester`) everywhere else; a missing staged binary is a build error, not a parser
   preference. Strengthen the staleness side by fingerprinting the staged binary (see Finding 7).
4. Delete `SwiftInterfaceAccessParser`, `RegexInterfaceFactsProducer`, and the 4,292-LOC
   `SwiftInterfaceAccessParserTests.cs`.

### What it deletes / retires

~6k LOC of regex parsing + ~4k LOC of its tests; the dual-parser divergence channel; the
documented heuristic-guess bug class; one of the two sides of the schema/staleness trap.

### Risk & migration

Low–medium. The parity bake converts the risk into a measurable diff before any cutover. The
one structural cost is that the generator becomes un-runnable without the Swift tool — which is
already true of every other stage of the pipeline.

## Finding 4 — ABI-layout tripwire + pin the generated-code↔runtime contract

> **Status — tripwire shipped in 0.15.0 (2026-06-14).** Part 1 (the ABI conformance gate) landed
> in `1fc81403`: an `AbiLayoutTripwire.swift` fixture exports live `MemoryLayout`/type-metadata
> ground truth and `AbiLayoutTripwireTests.cs` asserts the C# mirrors against it on **both** the
> Mono-JIT simulator and NativeAOT device legs — existential-container sizes (arity 0–8) + inline
> buffer, VWT size/stride probed through live metadata, metadata-kind discriminators (including the
> `> 0x7ff` class heuristic), tuple element offsets, and the frozen `String` buffer size. This is the
> same tripwire elaborated below as Finding 59. A complementary cross-artifact parity gate
> (generated C# ↔ built Swift libraries: symbol existence both directions, struct-mirror arity,
> vtable parity, ratchet baseline) shipped in `40af815b`. **Still open:** part 2 as written —
> explicitly pinning the generated-code↔*managed-runtime* surface (the ~30 `SwiftMarshal.*` /
> `TypeMetadata.*` entry points) so an out-of-contract emission fails at build rather than as a
> consumer `MissingMethodException` — plus the remaining Finding 59 inventory corners (VWT flag-bit
> positions, symbolic-reference byte ranges, Optional extra-inhabitant rules, the `MaxSelfSize` /
> `MaxParamSize` calling-convention thresholds).

### Evidence (verified)

`Swift.Runtime` hand-mirrors Swift ABI layouts in ~15 C# structs (`ValueWitnessTable`,
`TypeMetadata` + tuple metadata, `ExistentialContainer0–8`, `SwiftMetadata`'s descriptor family,
closure/data carriers). A grep for any layout assertion (`sizeof` checks, `Marshal.SizeOf`,
explicit `Size=` validations) across `src/Swift.Runtime/src` returns **nothing**. Specifics:

- The VWT is reached by raw pointer arithmetic — `(ValueWitnessTable*)(*((IntPtr*)handle - 1))`
  (`TypeMetadata.cs:216`) — with no test that would catch a layout shift *(reported, consistent
  with the empty grep)*.
- `ExistentialContainerN` sizes are hardcoded as `(4+N) * IntPtr.Size` *(reported)*.
- `FieldDescriptor`/`FieldRecord` mirror `swift/RemoteInspection/Records.h` — a header that is
  **not** covered by Swift's ABI-stability guarantee *(reported)*.
- The one historical layout bug (the `AlignmentMask` width, `0x0000FFFF` → `0x000000FF`) was
  found by reading Swift headers, not by a failing test — it's memorialized as a comment in
  `ValueWitnessTable.cs:19–23` *(reported)*.
- Runtime unit tests run on desktop CoreCLR with mocked metadata; none validates live layout.

Separately, the contract between **generated code and the runtime** is ~30 entry points
(`SwiftMarshal.*`, `TypeMetadata.*`, `ProtocolWitnessTable.*`, the `ISwiftObject` statics) that
emitters reference by string. The only compatibility guard is the NuGet version range
`[X.Y, X.Y+1)` built by `RuntimeVersionRange`; an out-of-contract emission surfaces as
`MissingMethodException` on a consumer device.

### Why this is decade-risk

This is the category of failure that produces the worst weeks this project has: memory
corruption that looks like a Mono/NativeAOT bug. Over a decade of Xcode and Swift-runtime
releases, the question is not whether some mirrored internal shifts, but whether you find out
from a red CI cell or from a consumer's corrupted heap. The repo's own #1 standing rule ("ALL
runtime crashes are OUR bugs") makes drift detection disproportionately valuable: a tripwire
turns the most expensive class of investigation into a one-line diagnosis.

### Overhaul shape

1. **ABI conformance gate**: a small Swift fixture (compiled by the existing BindingTests
   toolchain) that exports, via `@_cdecl` functions, the ground truth the mirrors assume —
   `MemoryLayout` sizes/strides for existential containers of arity 0–8, VWT field offsets
   probed behaviorally (call each witness through the mirrored slot on a known type and verify
   the effect), metadata-kind discriminators, tuple-element-vector offsets. A C# BindingTests
   class asserts mirror-vs-truth equality. Runs in the everyday sim gate and `--device`; cost is
   one extra fixture file, not a new pipeline.
2. **Contract pinning**: declare the emitter-callable runtime surface explicitly (an
   `[EmittedCodeContract]` attribute or a single listing file), with (a) a runtime-side test
   that the surface didn't shrink, and (b) a generator-side test that emitted call targets stay
   within the declared surface (greppable from the emitters' P/Invoke + helper-call tables).
   This converts "emitters call whatever exists" into a reviewable diff whenever the contract
   moves, and gives `RuntimeVersionRange` semantics something real to hang off.

### Risk & migration

Low. Purely additive; no production code changes. The main design care is asserting *behavioral*
layout facts (offsets observed through real Swift values) rather than re-deriving the same
constants in a second place.

## Finding 5 — Mechanize `constraints.md`: every prose invariant becomes structure

### Evidence (verified)

`.claude/rules/constraints.md` holds ~37 trap constraints; the file self-describes as "easy to
accidentally violate, hard to discover from code alone." Verified instances of the dominant
shapes:

- **N implementations that must stay structurally identical**: three projected-key builders
  (rule 16: `IHandler.GetProjectedCSharpMethodKey`, `ProtocolSignatureHelper`,
  `DefaultParameterOverloadEmitter`, 27 call sites / 15 files) — and `roadmap.md:27` records
  that one of them has *already drifted* on `parentTypeName` parity, status unknown.
- **Manual-parity switch statements**: rule 23 ends, literally, "ProtocolProxyEmitter.Receivers
  still uses switch with `_ => null` fallback — check manually." Verified at
  `ProtocolProxyEmitter.Receivers.cs:1371, 1547, 1580, 1775` — four non-exhaustive dispatch
  sites over the 18 `ITypeProjection` kinds, while the sibling visitors are already compile-time
  exhaustive via `IProjectionVisitor<T>`.
- **Scattered-write flags counted by grep**: rule 19 — `WasEmitted = true` at 23 points across
  12 files, with the canonical count maintained as a grep command in the doc and a guard test
  pinning the number.
- **Argument-threading rules**: rule 28 — `GetPublicMethodName`'s 23 call sites across 11 files
  must all thread `propertyNames`/`parentTypeName`/`parameterCount`; the doc names a shipped
  root cause (P1-21) from one site failing to.
- Several rules are 400+ words of load-bearing detail for a single mechanism (rules 17 and 46),
  i.e., correctness that exists only as prose.

### Why this is decade-risk

For an AI-maintained codebase this file is simultaneously the best and worst artifact in the
repo: best because the knowledge is written down; worst because every entry is a defect with a
warning sign instead of a guardrail. Prose rules require every future session to (a) load them
into context and (b) comply — both probabilistic. Over hundreds of sessions, some fraction of
violations *will* land; rule 16's already-drifted builder is the existence proof. The file also
only grows: it's an append-only log of architecture debt.

This is **not** the rejected capability-record refactor (`roadmap.md:67` — centralizing
*property derivation*). This is about eliminating *duplicate decision sites* and converting
*manual parity* to compiler-checked parity — a different axis the rejection didn't evaluate.

### Overhaul shape

A standing program, not a big bang. Triage all ~37 rules into four buckets and burn down:

1. **Merge duplicates** — where N sites must be "structurally identical," there should be one
   function. The three key builders become one parameterized builder (rule 16 names the exact
   shared shape they all compute). `GetPublicMethodName`'s 7-argument threading becomes a
   context object built in one place.
2. **Make parity compile-time** — port the four `_ => null` Receivers switches to the existing
   exhaustive `IProjectionVisitor<T>` pattern (the codebase already proved this works for the
   three accessor visitors); rule 23's "check manually" clause then deletes itself.
3. **Centralize scattered writes** — `WasEmitted` (23 sites) routes through one
   `MarkEmitted(decl)` API so the invariant lives in code, not in a grep command. Same review
   for the pipeline-ordering rule (rule 20): freeze `TypeDatabase` after
   `AddModuleDatabase` except through one explicit emission-mutation API, so the temporal
   coupling throws instead of corrupting.
4. **Guard-test the rest** — anything that can't be merged or typed gets a test that fails on
   violation (several rules already have these; finish the set).

**Success metric is the file itself**: every burned-down rule is deleted from `constraints.md`.
The doc should shrink toward the handful of genuinely external facts (Swift ABI behaviors like
rules 1, 2, 12) that no code structure can enforce.

### Risk & migration

Low per item — each is a small, independently testable refactor in code that already has dense
unit coverage. The compounding payoff is the point: every deleted rule is a permanent reduction
in per-session cognitive load and violation probability.

## Finding 6 — Single-source versioning; stop regex-stamping source files

### Evidence (verified)

`build/Helpers/VersionScope.cs` transactionally rewrites **8 source-controlled files** at
build/pack time — four csproj `<PackageVersion>`s, four values in `Sdk.props`, the template
csproj's `Sdk=` attribute, `template.json`, and — most fragile — a **regex replace of a C#
constant** (`DefaultSwiftRuntimeVersion` in `BindingProjectEmitter.cs`). The `BehaviorTier`
target runs the same scope with a `0.0.0-behaviortier` stamp. Memory records the standing
failure mode: `nuke validate` leaves 8 dirty files that must be manually checked out before
committing, with a `git grep behaviortier` hygiene step.

### Overhaul shape

- One `version.json` (or `Directory.Build.props`) as the sole authority; csproj versions import
  it (MSBuild does this natively — no stamping needed).
- `Sdk.props`/template values stamped only in the **pack staging copy**, never in the source
  tree (the pack pipeline already stages content; stamp there).
- `BindingProjectEmitter` reads its default runtime version from assembly metadata
  (`AssemblyInformationalVersion`) or an embedded resource generated at build — deleting the
  regex-edit-a-C#-file mechanism entirely.

Eliminates the dirty-working-tree class of errors, the `-behaviortier` leak hazard, and the
8-file consistency rule, replacing `VersionScope`'s try/finally restore dance with "source files
are never written at build time."

### Risk & migration

Low. The one subtlety is preserving `RuntimeVersionRange` semantics in the generated csproj —
already a single shared source file with unit tests.

## Finding 7 — One staleness discipline for built artifacts

### Evidence (verified)

The harness has two philosophies side by side:

- `EnsureGeneratorBuilt()` (`Build.BindingTests.cs:481–491`) builds the generator **only if the
  DLL is missing** — a stale binary is trusted unconditionally. Memory documents the recurring
  symptom: post-patch regen emits pre-patch output even after a clean wipe.
- `BuildGeneratorIfChanged()` (`Build.Validation.cs:1710`) already does it right: SHA256 over
  the four source directories vs a `.build-stamp`.

The same trap family recurs across artifacts (all in memory as separate hard-won lessons): the
staged `SwiftInterfaceParser` binary (schema handshake catches *shape* drift but not *behavior*
drift), stale incremental AOT app builds reporting the prior run's JSONL, and platform/smoke-flag
sidecar stamps that exist precisely because earlier traps shipped
(`Build.BindingTests.cs:470–478` shows the sidecar pattern already in place).

### Overhaul shape

One rule, applied uniformly: **no consumer of a built artifact trusts it without a content
fingerprint.** Concretely: point `binding-tests` at the existing `BuildGeneratorIfChanged`;
fingerprint the staged Swift parser binary against `tools/SwiftInterfaceParser` sources; stamp a
run-id into the test app's JSONL and reject mismatched files (kills the stale-results class);
keep the sidecar pattern for flags/platform. This converts four separately-memorized traps into
one mechanism.

### Risk & migration

Low; each is a small harness change with an existing in-repo precedent to copy.

## Finding 8 — Reverse-dispatch vtables: ~10 hand-copied walks, 3 membership mechanisms, 2 key
functions — and it has already shipped a positional corruption

### ⚠ Confirmed defect (verified first-hand in shipped artifacts)

The Swift `fileprivate struct {P}_vtable` and the C# `[StructLayout(Sequential)]` mirror must
match field-for-field — Swift copies the C#-filled memory **positionally**
(`vt.pointee = uvt.assumingMemoryBound(...).pointee`, `SwiftBindingsTestLib.Wrapper.swift:2546–2548`).
For `OptionalCallbackDelegate` (an `@objc` protocol with optional members) they do not:

- **[V]** C# struct has **6 fields** (`csVTHandle`, `func_optionalLabel_get`,
  `func_didFireRequired_0`, …) — `BindingTests/output/SwiftBindingsTestLib.cs:298428–298436`;
  C# assigns only `csVTHandle` and `func_didFireRequired_0` (byte offset 16) — `:298503–298507`.
- **[V]** Swift struct has **2 fields** (`csVTHandle`, `func_didFireRequired_0`) —
  `Wrapper.swift:2524–2527`. Its positional copy therefore reads `func_didFireRequired_0` from
  byte offset 8 — the never-assigned `func_optionalLabel_get` slot, i.e. **zero** — and the
  dispatch site force-unwraps it (`Wrapper.swift:2536`).
- Net: **any reverse dispatch of the protocol's *required* member through a C# conformer is a
  guaranteed nil-unwrap crash.** Because properties are walked before methods, one
  `@objc optional` *property* anywhere in a protocol corrupts every method slot regardless of
  declaration order — and optional-member delegate protocols are the canonical Apple shape this
  feature exists for.
- **[V]** It is invisible to every gate: `OptionalProtocolMembersTests.cs` contains **zero**
  reverse-dispatch invocations (the fixture's own doc promises a Swift→C# round-trip that was
  never written), the vtable struct compiles fine on both sides, and unit tests assert struct
  *presence*, not cross-language parity.
- **[A]** 5 of 148 protocols in the shipped artifacts mismatch; the other four (`Summable`,
  `Processable`, two mixed-generic fixtures) are benign only because their Swift field list
  happens to be a strict *prefix* of the C# list. A Self-typed property declared before a live
  method would reproduce the crash.

### Evidence — the structural cause [A]

The "walk members, skip some, assign `methodIndex++`, emit slot" loop is hand-copied **~10
times across 5 files**: `EveryProtocolEmitter.cs:478–595` (Swift struct) and `:1274–1563`
(Swift extension — with the comment "This MUST happen before the global skip check to prevent
index drift (Bug #21)", documented proof this has bitten before);
`ProtocolProxyEmitter.Vtables.cs:19–95` and `:103–172` (two C# structs);
`Receivers.cs:16–94`; four assignment walks in `StaticInit.cs`; `InterfaceImpl.cs:95–130`.
Membership is decided by **three mechanisms** (ProtocolHandler skip sets for same-module;
`ProtocolVtableMembers` for cross-module parents — whose doc claims "single source of truth"
while admitting the same-module path doesn't use it; inline Swift-side filters), and slot
identity by **two different key functions** (`EveryProtocolEmitter.GetMethodKey` raw-TypeSpec
vs `ProtocolSignatureHelper.GetMethodSignatureKey` projected-with-fallback). The same-module C#
struct emitters consult none of the property skip sets (`Vtables.cs:36–43`) and skip only the
closure subset of methods (`:80`), with no `@objc`-optional arm — while the Swift side skips
optionals at `EveryProtocolEmitter.cs:556–557`. The cross-module path's doc comment
(`Vtables.cs:12–18`) describes this exact hazard; the same-module path assumed coverage it
doesn't have.

### Why this is decade-risk

Slot-offset drift is silent memory corruption keyed to protocol *shape* — no compile error, no
crash until the specific member is reverse-dispatched. Every membership-category change (the
roadmap's deferred inout-ObjC-bridgeable slot is one) currently requires a coordinated edit
across ~10 walks × 3 mechanisms × 2 key domains, with agreement enforced by prose. The history
("Bug #21") plus this shipped drift is the proof the discipline does not hold.

### Overhaul shape

1. **Immediately:** fix the same-module membership gap; add the missing reverse-dispatch
   round-trip test for `OptionalCallbackDelegate`; and add a cheap **cross-artifact vtable
   parity gate** to `--compile-only` (diff the Swift struct field list against the C# struct
   field list per protocol — the drift above was found with exactly that 20-line comparison).
2. **Overhaul:** compute one `VtableLayout` model per protocol — ordered slot records
   {member, identity key, slot index, width, membership verdict + reason} from **one**
   membership function, **one** key function, **one** width function — and make all ~10 walks
   renderers over it. Divergence becomes structurally impossible.

**Deletes:** the copied walks, `ProtocolVtableMembers` as a parallel mechanism, the
skip-set plumbing and its save/restore in `CrossModuleParent.cs:88–127`, the dual key domains.

## Finding 9 — One ABI lowering descriptor: the param/return category decision is made three
times per parameter, six times per return, and per-bridge for closures

### Evidence [A; fan-out counts agent-measured; mirror-comment pattern spot-checked V in Part I]

Every boundary-crossing parameter is categorized **three independent times** by hand-ordered
if-chains that must agree exactly:

- **Leg A** (Swift wrapper text): `CdeclParamMapper.Map` — ~16 ordered categories
  (`CdeclParamMapper.cs:34–506`), plus a parallel fourth chain `MapInout` (`:897–934`).
- **Leg B** (C# P/Invoke signature): `PInvokeSignatureBuilder.HandleArguments`
  (`PInvokeEmitter.cs:406–795`) re-derives the same categories — its SIMD arm literally carries
  "matching the Swift wrapper shape produced by CdeclParamMapper.Map" (`:445–452`).
- **Leg C** (C# call-site conversions): the sequential marshalling passes
  (`WrapperEmitter.cs:407–411`) each re-detect their categories with their own predicates.

The legs agree through **cross-file magic-name contracts** (`{csName}_w0/_w1` emitted in
`WrapperEmitter.Marshalling.cs:735–752` to match `PInvokeEmitter.cs:629–662`;
`{csName}FuncPtr/Context` likewise) and through comment-mirrored ordering on the
generic-static-dispatch paths (`MethodWrapperEmitter.cs:963`, `PropertyWrapperEmitter.cs:996`).

**ceiling 15** (RawBufferPointer: 15 files including closures ×4, thunks, demangler,
validators). The CLAUDE-level "~15 sites" estimate is the ceiling, not the norm.

Two adjacent instances of the same disease:

- **Return rendering**: classification is centralized (`CdeclReturnMapping.Classify`) but the
  per-kind rendering switch is copied **six times** — three in `MethodWrapperEmitter`
  (`:1176–1211, :1428–1446, :1463–1504`), two in `PropertyWrapperEmitter` (`:772–810`,
  `:1080–1113`, whose own comment admits "both paths must agree or … mismatched ABI"), and a
  **verbatim file-to-file clone** in `SubscriptWrapperEmitter.cs:679–716`. ClassPointer retain
  semantics currently have six homes.
- **Closure bridges**: the four bridge families (`MethodClosureBridge`, `NestedClosureBridge`,
  `GenericClosureBridgeEmitter`, `ProtocolExtensionClosureBridge`) each own a private callback
  skeleton, a private `GetCallbackParamType` table, and Swift trampoline text. The tables have
  **already diverged**: MethodClosureBridge decides Optional-of-class via TypeRecord kind
  (`MethodClosureBridge.cs:2043–2061`) while NestedClosureBridge uses
  `ClosureHandler.IsReferenceType` (`NestedClosureBridge.cs:1474–1478`) — two predicates for
  the same ABI question, where the canonical Swift side uses the latter. The
  Swift-primitive→C#-type table exists in **7+ copies**. `BuildCallbackReturnStatement` —
  constraints.md's declared "single source of truth" — is consumed only by `ClosureEmitter`;
  zero of the four bridges route through it.

### Why this is decade-risk

This is the load-bearing correctness axis of the generator: the Known-Issues "verify the C#
P/Invoke matches the Swift wrapper" failure class is *manufactured* by this structure. Every
"must match X" comment is a deferred ABI crash on device — the most expensive failure to debug.
The bridges encode the project's most dangerous hard-won knowledge (Optional ABI, reabstraction
traps, retain conventions) in N divergent copies on both sides of the language boundary, where
disjoint input domains mean divergence never collides at compile time.

### Overhaul shape

One classification call (effectively `CdeclParamMapper`'s chain — already the de-facto
authority with 17 call sites) returns a per-parameter **lowering descriptor**: category, Swift
param text + reconstruction, C# P/Invoke type(s), the shared local names, needs-unsafe flags.
Legs B and C consume the descriptor instead of re-classifying; `MapInout` becomes a flag. One
return-kind renderer (writer-form + lines-form — `GetTagOnlyEnumReturnLines` already prototypes
the dual form) replaces the six switches. For closures, extend the already-proven
`SwiftBuilder.GetSwiftCdeclParamType` pattern into a closure-ABI planner covering all six axes
(cdecl kind, C# callback type, managed delegate type, Swift cdecl type, both conversion texts,
context/lifetime plan); the four bridges become renderers. This is *not* the rejected
capability-typed projection — it is single-sourcing the category decision and the name
contract; emission stays string-template-based exactly where it is today.

**Deletes:** the category-detection halves of `HandleArguments`/`HandleReturnType` (~400
lines), five of six return switches, four `GetCallbackParamType` copies and the divergent
Optional predicates, 7+ primitive tables, the cross-file magic-name contracts. New-shape
fan-out drops from 5–15 files to ~2.

## Finding 10 — Type identity has no single home: two resolution universes with opposite
precedence, ≥9 knowledge sources, and shape-of-the-name heuristics at the leaves

### Evidence [A]

- The `NamedTypeSpec` entry points resolve through `TypeResolver.Default`'s 13 ordered
  strategies; the `SwiftTypeName` entry points bypass it for a **separate 6-arm cascade**
  (`TypeDatabase.cs:591–656`) — and the universes are *joined*: strategy #12 re-enters the
  cascade, whose first arm is the Apple supplement… which is also strategy #11. The supplement
  is consulted **twice at two different precedence positions**, with different
  `currentlyGeneratingModule` arguments held equivalent only by an INVARIANT comment
  (`TypeDatabase.cs:603–611`); `ResolutionContext.CurrentlyGeneratingModule` has **zero**
  production writers. On the raw-name path the supplement outranks everything; on the strategy
  path ten strategies outrank it. Which record you get depends on which key type the caller
  happened to hold (347 call sites, both kinds).
- `IsTypeProcessed` disagrees with `TryGetTypeRecord` (no supplement/out-of-module/`Swift.Error`
  arms, `:694–715`) — a divergence already patched *only* for the NamedTypeSpec side
  (`TypeResolver.cs:32–34`); live consumers of the divergent predicate include the parser
  handoff itself. `ModuleProcessor` has a fourth private mini-resolver (`:71–93`). The
  CF-style `Ref`-alias rewrite applies to **every** module's names (`:622–626, :859–868`).
- Knowledge sources that can claim an identity: XML module DBs, parsed module DBs, the Apple
  supplement manifest, `TypeOwnerRegistry` hardcoded seeds, `AppleFrameworkRegistry`, two
  hardcoded alias dictionaries inside `TypeDatabase`, synthetic records + literal tables in
  `TypeDatabaseExtensions`/`MarshallingHelpers`, and per-leaf literal tables
  (`TypeProjectionFactory.cs:312–332`; `ModuleProcessor.ClassifyFieldType` spells CGFloat
  twice in two files). When all of it misses, projection falls back to **name-shape
  heuristics** — `HasObjCClassPrefix` (2–3 uppercase letters ⇒ ObjC class) guarded by
  `IsKnownAppleValueType`, whose own comment documents the misfire class
  (`TypeProjectionFactory.cs:588–590`). The 7-condition guard chain is duplicated **four
  times** in the same file and held in sync with the Swift-side wrapper signature by comment
  (`:223–225`) — constraints.md rule 21 already records this pair as a manual-parity trap.

### Why this is decade-risk

"What is `X.Y`?" has at least four answers depending on entry point, and a type's projection —
its ABI shape — can depend on which fallback branch catches it. Every Apple SDK train lands new
names in the heuristic net; the counter-guard fossils show the failure→patch→counter-patch loop
has already run. Every new knowledge source or alias class must re-derive the precedence
question in 2–4 places.

### Overhaul shape

One resolution function over one canonical key: the `SwiftTypeName` overloads become adapters
into the same strategy chain; the inner cascade's arms become strategies with one declared
order; `IsTypeProcessed` is defined as `TryGetTypeRecord` success; the `Ref` rewrite is scoped
to CF-family modules. Then fold the literal tables and the prefix heuristic into a declarative
type-facts store with explicit precedence tiers, demoting the heuristic to a last-resort tier
that *records its guesses* into the binding report. Stage it: the resolver unification is
mechanical; the facts-store consolidation rides Finding 5's program. Higher migration risk than
most findings (347 call sites) — gate each stage on `nuke validate` as the canary sweep.

**Deletes:** the parallel cascades, the double supplement consult and its INVARIANT comment,
the divergent `IsTypeProcessed`, the four duplicated guard chains, the leaf literal tables.

## Finding 11 — Declare the runtime's payload-ownership contract; retire the unsound
borrowed-marshal path (real leak class)

### Evidence

- **[A]** `NewFromPayload` — the single construction funnel (`SwiftMarshal.cs:1011–1041` [V]) —
  has four per-type ownership behaviors (**Adopt** for class wrappers and SwiftUI value
  wrappers, **Copy** for frozen-as-class/non-frozen struct wrappers, **Move** for
  `SwiftString`, **Inline** for blittable), and none is declared; the runtime *detects*
  ownership after the fact by pointer comparison (`MarshalExtractedPayloadValue`,
  `SwiftMarshal.cs:390–465`), re-implemented in four places.
- **[V]** `MarshalBorrowedFromSwift<T>` (`SwiftMarshal.cs:984–1002`) constructs the wrapper,
  then suppresses **both** the wrapper's finalizer and the Payload SafeHandle's finalizer (via
  reflection). **[V]** Generated copy-semantics wrappers' `NewFromPayload` runs
  `InitializeWithCopy` into a fresh `NativeMemory.Alloc` buffer the SafeHandle owns — the
  generated bindings' own doc comments state "Without that destroy, every throw leaks"
  (`SwiftBindingsTestLib.cs:9010, :18090`; live `InitializeWithCopy` sites `:11145, :13072,
  :18811`). Suppressing that SafeHandle's finalizer forecloses the destroy: **every borrowed
  struct-argument callback invocation leaks the copy's retains plus its native buffer** unless
  an ambient `SwiftDisposeScope` happens to catch it. **[A]** The generator routes all
  non-class borrowed callback args here (`ClosureHandler.cs:1872–1875`); `SwiftString`'s
  16-byte buffer leaks per string-argument callback; and the class-shaped version of this
  unsoundness already produced a real NativeAOT use-after-free (`ClosureHandler.cs:1862–1864`),
  fixed by adding a *second* borrow convention (`MarshalBorrowedClassFromSwift`) instead of
  retiring the broken one.
- **[A]** Adjacent latent traps, reported as structure not active bugs: deinit upcalls run
  registry bookkeeping on the finalizer thread one hop past the trampoline discipline
  (`ProxyLifetimeTracker.cs:117–165, :263–317`); the boxed-vs-raw closure-context encoding is
  decided by a process-global latch set by a *different symbol's* success
  (`SwiftClosureContext.cs:37–145`) — a per-value property with no per-value bit, where
  disagreement is memory corruption.

### Why this is decade-risk

Per-frame/progress callbacks are the canonical Swift API shape; an invisible unbounded native
leak there is a production-only failure. Every new wrapper shape must be re-classified at four
heuristic sites with no compile-time signal, and every new emission site must pick between two
borrow conventions using a taxonomy that exists nowhere in the type system.

### Overhaul shape

A static abstract `PayloadConstructionSemantics` (Adopt | Copy | Move | Inline) on
`ISwiftObject`, emitted per type by the generator, consumed by **one** slot-extraction helper.
Borrowing then becomes principled per semantics (Copy wrappers: construct normally, no
suppression — the copy is owned; Adopt/Move: real +1 or non-owning + scope-detach), and
`MarshalBorrowedFromSwift` plus its reflection suppression is deleted. Make the deinit-upcall
bodies enqueue-only (the existing `Interlocked` release discipline already tolerates deferred
notify), and give the closure-context encoding a per-value tag. Add the leak to BindingTests
via the existing `LifetimeTracker` machinery (assert allocs−deallocs around a borrowed-struct
callback loop) — red first, per the TDD-for-regression-fixes rule.

**Deletes:** the post-hoc pointer-comparison detection (×4), `ISwiftMovesPayloadOnConstruction`,
`MarshalBorrowedFromSwift`, the per-site helper-selection logic, one of three closure-context
conventions.

## Finding 14 — Convert silent-failure channels to loud ones

### Evidence [A]

Four independent mechanisms whose shared failure mode is "output quietly degrades":

1. **Parser swallow:** `SwiftABIParser.HandleNode` wraps every node in
   `catch (Exception) { LogWarning }` (`:884–891`) — a bug anywhere under a TypeDecl silently
   deletes the whole type from the binding; the code is *built around* the net
   (duplicate detection by thrown-then-caught exception, `:1021`; `HandleConformance` exists
   to dodge it, `:1258–1265`). No gate measures emitted-surface loss — a regression dropping
   40 types produces greener logs.
2. **Dead-impl fabricated results:** proxies hold the user's protocol implementation weakly
   (`Receivers.cs:2020` — the strong cycle is real), but when the impl is collected while
   Swift still retains the existential, receivers **return fabricated defaults** (empty
   string/null containers, `Receivers.cs:190–198`) — silent wrong answers timed by GC
   nondeterminism, undiagnosable from a bug report.
3. **Packaging by side effect:** `AppleSupplementReferences` is a `[ThreadStatic]` collector
   *written from inside pure query APIs* (8 sites across three layers, including
   `TypeDatabase.TryGetTypeRecord` itself), manually reset per module, consumed at 11 sites to
   decide whether the consumer csproj gets a `SwiftBindings.Apple` PackageReference — so
   merely *inspecting* a type can change packaging output, and any future parallelism loses
   references silently.
4. **Mode from a data store:** "xcframework mode" — gating all `@_cdecl` emission — is
   `!string.IsNullOrEmpty(db.AsyncLibraryName)` (`WrapperValidation.cs:258–261`), consumed in
   10+ files; plus three near-identical supplement-prototype blocks in
   `BindingsGeneratorCommand` that have already drifted in error handling (one swallows, two
   fail).

### Overhaul shape

Typed node-level parse results with a reconciliation count (parsed = emitted + skipped-with-
reason + dropped-with-error) wired into the existing artifact manifest/report — the parser
analog of the skip-attribution work the project already did once; dead-impl receivers throw
into the existing error channel (or FailFast) instead of fabricating; supplement references
become provenance on resolution results aggregated from the emission manifest; an explicit
`GenerationMode` enum + context record replaces the `AsyncLibraryName` sentinel and the copied
mode branches. Quick win while in the area: delete the six dead `MethodMarshalPlan` record
types — zero references, doc comments describing a consumption topology that doesn't exist,
and a name (`PInvokeDeclarationInfo`) that shadows the *live* `PInvokeDeclaration` [A].

- **Immutable-pipeline big-bang** (freezing all inter-stage state). Disproportionate; the

> type's real Objective-C runtime name — including `@objc(CustomName)` renames and the protocol

## Finding 27 [V] — Runtime green-signal integrity: verdicts that accept absence of evidence

The harness's *machinery* (merge core, AbiGrid, ratchets) is largely fail-closed [A —

## Finding 34 [V] — No object identity model: every marshal-from-Swift constructs a fresh
