## How to run a session

1. Open fresh Claude Code in `/Users/wojo/Dev/swift-bindings` on `main`.
2. Hand it this doc + "do Session X."
3. Claude reads CLAUDE.md, this doc, and every in-scope per-bug doc
   in full (don't skim — the analyses are load-bearing).
4. Implement the fixes plus BindingTests at the appropriate layer
   (per CLAUDE.md "BindingTests are the real end-to-end gate").
5. Run the session-end gates listed below.
6. One codex-review pass — fix High / Medium inline, surface Low for
   accept-or-fix decision, commit. Do not loop codex-review.
7. `git mv` resolved docs to `src/docs/Resolved/` in the same commit.
8. Ratchet `.validation-baseline.json` if numbers improved; ratchet
   `runtime_pass_count_*` baselines if `--sim` / `--device` deltas
   are positive. Commit any baseline bumps separately.

**Resolution:** Bug 1 Cat 3 and Bug 3 Case 2 share root cause and share
the fix: a Swift-ARC-owned `_SBClosureCtx` box exported from
`libSwiftBindingsRuntime.dylib` wraps the GCHandle context, and its
deinit upcalls a C# free callback registered by
`SwiftClosureContext.EnsureRegistered`, freeing the GCHandle exactly
once when Swift releases the closure. The mechanism is restricted to
escaping closures — non-escaping closures still free in the C# wrapper's
`finally`. Symbol resolution uses `dlsym(RTLD_DEFAULT, ...)` against the
already-loaded runtime dylib (no `-undefined dynamic_lookup`). The Swift
box is `@unchecked Sendable` for Swift 6 strict concurrency. Adapter
closures explicitly capture the box via their capture list so escape
analysis cannot elide the lifetime tie. See
`src/Swift.Runtime/swift/SwiftBindingsRuntime.swift`,
`src/Swift.Runtime/src/Swift/Runtime/SwiftClosureContext.cs`,
`src/Swift.Bindings/src/Emitter/StringEmitter/ClosureContextHelperEmitter.cs`,
and the escaping-closure paths in `ClosureEmitter.SwiftWrapper.cs`,
`MethodWrapperEmitter.cs`, `ConstructorWrapperEmitter.cs`,
`PropertyWrapperEmitter.cs`, and `MethodClosureBridge.cs`. Re-enabled
tests: `LifetimeTrackingTests.TestEphemeralClosureReleasesCapturedSafeHandle`
+ four `OwnershipGCStressTests.TestBundleB_ClosureLifetime_*` (Ephemeral
repeat call, HeapAllocShapeMatrix, PropertySetterReplace,
GCPressureDuringCall).

## Session α2 — Cascade-dispatcher emitter filter

Bug-fix session carved off α1's validate gate. Two pre-existing emitter
bugs in `ErrorEnumRegistryEmitter` produced CS0234 / CS0305 in
StripeCore (`@_spi` error types referenced from the cascade
`switch (errorTypeId)` block — the C# emitter skipped them but the
registry kept them) and Alamofire / RealityFoundation
(`Outer<T>.Inner` error types rendered without a closed type
argument). Neither was caused by α1.

**Fix:** Add `IsRegisterable` filter on `ErrorEnumRegistryEmitter.CollectErrorConformingTypes`
that walks the full `ParentDecl` chain and applies the cascade-visibility
skip set to every link: `@_spi`, `@usableFromInline internal` /
plain-internal (`IsModuleInternal`), underscore-suppressed,
Apple-supplement-owned. The visibility gate is STRICTER than
`HandleBaseDecl`'s C#-emission skip set — `HandleBaseDecl` binds
`@usableFromInline internal` types because they appear in `@inlinable`
signatures, but the cascade dispatcher sits in the wrapper module whose
plain `import {Module}` resolves only `public` declarations, so a cascade
arm `as? Module.InternalType` would fail at the swift wrapper compile
(the CryptoSwift `StreamDecryptor` shape). Plus a generic-parent gate
(`typeDecl.IsGeneric` or any chain entry with `IsGeneric`). Filtered
entries fall through to the default cascade arm — untyped `SwiftException`
— which is the correct degradation. Recursion descends through public
non-error outer types so an emittable nested error inside a plain
namespace struct (e.g. `PhotogrammetrySession.Error`) still surfaces;
nested errors whose parent chain hits any filtered link drop out at the
re-walk inside `IsRegisterable`.

**Layer A:** `ErrorEnumRegistryEmitterTests` covers SPI exclusion,
module-internal exclusion, underscore-suppressed exclusion, nested-in-SPI
exclusion, nested-in-module-internal exclusion, nested-in-underscore-suppressed
exclusion, nested-in-generic exclusion, open-generic-self exclusion, plus
a recursion-descends-through-non-error-parent positive case.

**Layer B:** `BindingTests/Sources/.../ErrorHandling/CascadeRegistryFiltering.swift`
adds an `@_spi(InternalCascade)` Error enum, a generic outer struct with
a nested Error enum, an open-generic Error struct, and a
`@usableFromInline internal` Error enum (the CryptoSwift shape).
Matching runtime tests (`CascadeRegistryFilteringTests`) assert the SPI
and `@usableFromInline internal` throws each land on the bare
`SwiftException` fallthrough (id 0).

**Session gates:** `nuke compile`, `nuke test`, `nuke validate` (need
the three regressed libs back to compile-ok and the baseline ratchet),
`nuke binding-tests` (sim). No `--device` — emission shape only, no
register or marshalling change.

first was already appended to the deferred-list). The GCHandle, holder
slots, and cancellation registration would all leak. The emitter now
wraps that section in `try { ... } catch { ...cleanup; handle.Free();
throw; }` — the catch runs the same holder cleanup loop the success
path uses (`includeCancellationReg: true`) so any `SBW_CancelTask`
registration is also disposed before the handle is freed. Emitted at
`WrapperEmitter.Async.cs` (try-open) + `WrapperEmitter.Return.cs`
(catch + close).

**Session gates:** sim 1962 → 1965 (+3 from the new Dictionary fixture),
device/NativeAOT 1981 → 1984 (+3). Unit tests 11128/11129 + 554/555
clean. Earlier baseline shift Session α2 entry → exit: sim 1956 →
1965 (+9), device 1965 → 1984 (+19, 0 crashes).

## Session β — New emission infra + Hashable hardening (F + H + L)

Three medium-large fixes that share a gate profile (full set +
`--device`). Each is its own emission/runtime addition; commit per fix.

### Fix F — Full Codable round-trip (encode + decode)

**Doc:** `gap-0.10.0-codable-synthesis-dropped.md`.

**User decision (locked 2026-05-06):** ship full round-trip, JSON-only.
Custom Decoder / PropertyListDecoder explicitly out of scope; document
the limitation.

**Generated API shape (target):**

Non-generic types:
```csharp
byte[] json = weatherAlert.EncodeToJson();
WeatherAlert decoded = WeatherAlert.DecodeFromJson(json);
```

Generic types (closed-instantiation extension, matches Bundle 05's
`ConstrainedExtensionEmitter` pattern):
```csharp
byte[] json = forecast.EncodeToJson();
Forecast<DayWeather> decoded = ForecastJson.DecodeFromJson<DayWeather>(json);
```

**Fix loci:**

- Detect synthesized Codable conformance at parse time (parser already
  reports `SynthesizedCodable` skip records — flip from skip to emit).
- Per-Codable-type Swift `@_cdecl` trampolines:
  `try JSONEncoder().encode(value)` and
  `try JSONDecoder().decode(T.self, from: data)`.
- Per closed instantiation for generic types (reuse Session D's
  multispec specialization machinery).
- C#-side instance `EncodeToJson()` + static factory
  `DecodeFromJson(byte[])`. Static side on closed-extension class for
  generics.
- Typed-error path (already wired by Session D): `JSONDecoder.decode`
  throws → typed C# exception.

**Sizing:** ~1 session worth on its own. If generic specialization for
Foundation value-type returns turns out to be structurally larger than
expected (decode side allocates Swift heap value from bytes), surface
the finding and ask the user before any scope reduction.

### Fix H — Cross-module extensions

**Doc:** `bug-0.10.0-cross-module-extensions-dropped.md`.

**Scope:** Extensions on types owned by a different Swift module (e.g.
`extension StripeCore.STPAPIClient` declared in StripePayments) are
currently dropped. Per the doc, the fix synthesizes a fourth routing
path mirroring the Apple/system-module extension shape: emit `static
partial class {Type}{Module}Extensions` with `this`-prefixed instance
methods, gated on a foreign-Swift-module receiver predicate. **Sizing:
medium-large** — new emission infrastructure, but mirrors an existing
pattern.

**Impact:** ~50% of StripePayments' public client API surface plus
every multi-module Swift SDK using cross-module extensions.

### Fix L — b06 Hashable predicate composition

**Doc:** `gap-0.10.0-b06-hashable-predicate-composition.md`.

**Scope:** Per the doc, gated on runtime hardening of
`SwiftHashable.GetHashCode<T>`. Open the doc and sequence the runtime
work + generator work as needed. **Sizing: TBD** — dependent on
runtime hardening scope.

**Sizing flag:** L's runtime-hardening scope is TBD per its doc. If
the Hashable runtime work expands beyond a small-to-medium change,
surface to user and consider carving L out of β as its own session
before continuing.

**Session gates:** full standard set including `--device`. Codable and
Hashable both exercise runtime conformance paths that differ between
Mono and NativeAOT; cross-module extensions land on validate-set libs
(Stripe). Commit per fix.
