## How to run a session

1. Open fresh Claude Code in `/Users/wojo/Dev/swift-bindings` on `main`.
2. Hand it this doc + "do Session X."
3. Claude reads CLAUDE.md, this doc, and every in-scope per-bug doc
   in full (don't skim — the analyses are load-bearing).
4. Implement the fixes plus BindingTests at the appropriate layer
   (per CLAUDE.md "BindingTests are the real end-to-end gate").
5. Run the session-end gates listed below.
6. One codex-review pass — fix High / Medium inline, surface Low for
   accept-or-fix decision, commit. Do not loop codex-review.
7. `git mv` resolved docs to `src/docs/Resolved/` in the same commit.
8. Ratchet `.validation-baseline.json` if numbers improved; ratchet
   `runtime_pass_count_*` baselines if `--sim` / `--device` deltas
   are positive. Commit any baseline bumps separately.

## Standard session-end gates

Match gates to what changed (per CLAUDE.md "Final validation gates"):

| Change locus | Required gates |
|---|---|
| Generator / emitter / parser | `nuke compile`, `nuke test`, `nuke validate`, `nuke binding-tests` (sim). Add `--device` if calling conventions or marshalling changed. |
| Runtime (`Swift.Runtime`) | `nuke compile`, `nuke test`, `nuke binding-tests --skip-regen`. Add `--device` if marshalling changed. |
| Test infrastructure only | The targeted test classes only. |

Pipe slow gates to `/tmp/<name>.txt` with `tee` and `Read` the file —
never re-run a slow command to see a different slice of output.

## Session ordering and dependencies

```
A (skip-policy)        — independent
B (closure lifetime)   — independent of A; blocks C and parts of D
C (wrapper emitter)    — depends on B (shares closure infrastructure)
D (projection/conf.)   — depends on B (typed-error wrapper site)
E (Mappedin + Phase 5) — depends on A-D (final release gate)
F (full Codable)       — independent of A-E; runs last by choice
```

A and B can in principle swap. C must follow B. D leans on B's wrapper
emitter cleanup for typed-error work. E is the release gate and runs
last among the must-ships. F is pure ergonomics (Codable round-trip)
and is sequenced last so a snag there can be deferred without
unwinding the rest of 0.10.0.

## Session B — Closure / wrapper lifetime

**In scope (3 docs):**

- `bug-0.10.0-callback-trampoline-gchandle-leak.md`
- `bug-0.10.0-swift-wrapper-payload-buffer-leak.md`
- `bug-0.10.0-async-task-wrapper-leaks-existential-heap.md` (Case 2:
  closure property-setter leak — Case 1 already verified+tested in
  Bundle 03; this session covers the closure-setter half)

**Coherence:** all three need the same Swift-side destroy-thunk +
ownership-transfer infrastructure. The orchestrator's prior attempts
(B-now single-shot Free for Bug 1, defer-deallocate for Bug 2) UAFed
under lambda capture-out. The right fix is Swift-side cooperation:
Swift closure deinit cooperation calls a C# `[UnmanagedCallersOnly]`
cdecl destroy callback driven by ARC release; closure storage owns
the GCHandle.

**Fix loci:**

- `SwiftClosureMarshaller` lifetime ownership model (likely in
  `Swift.Runtime/.../Closure*`).
- Closure emitter: emit destroy thunk + ownership-transfer projection.
- Wrapper emitter: `heapAllocArgs` projects as owning
  `MarshalFromSwift<T>` (not `MarshalBorrowedFromSwift<T>`);
  SafeHandle.ReleaseHandle does VWT.Destroy + NativeMemory.Free.

**Layer C: Lifetime harness coverage required.** Extend
`BindingTests/RuntimeTestsApp/Lifetime/` (do not duplicate — the six
existing classes are the home). Repeat-call + GC-pressure +
refcount-stability assertions; mock-stress closure capture-out.

**Gates:** runtime + emitter changes — full set, including `--device`.
Closure ownership behaves differently under Mono JIT vs NativeAOT.
Mandatory device run.

## Session F — Full Codable round-trip (encode + decode)

**In scope (1 doc):**

- `gap-0.10.0-codable-synthesis-dropped.md`

**User decision (locked 2026-05-06):** ship full round-trip, JSON-only.
Custom Decoder / PropertyListDecoder explicitly out of scope; document
the limitation.

**Why last:**

- 0.10.0 release-blocking work is done by end of E. F is pure
  ergonomics — DTO workaround exists.
- Sequencing F after E means a regression in F only affects the new
  Codable surface; A–E remain validated.
- If F hits a structural snag, defer just F to roadmap without
  unwinding any prior session.

**Generated API shape (target):**

Non-generic types:
```csharp
byte[] json = weatherAlert.EncodeToJson();
WeatherAlert decoded = WeatherAlert.DecodeFromJson(json);
```

Generic types (closed-instantiation extension, matches Bundle 05's
`ConstrainedExtensionEmitter` pattern):
```csharp
byte[] json = forecast.EncodeToJson();
Forecast<DayWeather> decoded = ForecastJson.DecodeFromJson<DayWeather>(json);
```

**Fix loci:**

- Detect synthesized Codable conformance at parse time (parser already
  reports `SynthesizedCodable` skip records — flip from skip to emit).
- Per-Codable-type Swift `@_cdecl` trampolines:
  `try JSONEncoder().encode(value)` and
  `try JSONDecoder().decode(T.self, from: data)`.
- Per closed instantiation for generic types (reuse Session D's
  multispec specialization machinery).
- C#-side instance `EncodeToJson()` + static factory
  `DecodeFromJson(byte[])`. Static side on closed-extension class for
  generics.
- Typed-error path (already wired by Session D): `JSONDecoder.decode`
  throws → typed C# exception.

**Sizing:** ~1 session. If generic specialization for Foundation
value-type returns gets messy (decode side allocates Swift heap value
from bytes), consider scope-cap to encode-only and roadmap the decode
side. User-facing impact of encode-only is still meaningful (1-line
"give me Swift-format bytes").

**Gates:** generator/emitter + new C# helper API surface — full
standard set, including `--device`. Codable round-trip exercises the
typed-error pipeline under both runtime modes.
