# 0.10.0 Pre-Release Fix Plan

> Tracking doc for the 30 bug + 13 gap analyses landed in `src/docs/bug-0.10.0-*.md` and
> `src/docs/gap-0.10.0-*.md`. These were surfaced by the WeatherKit / MusicKit / SwiftUI
> consumer-experience audits (Round 5, 2026-05-05) and a parallel Codex pass over the
> same generated output. All must be resolved (fix, gate, or explicitly deferred with
> rationale) before the next release.

## Why the existing gates missed these

Sorting the 43 issues by subsystem makes the structural gap obvious:

| Category | Count | Why current gates miss it |
|---|---|---|
| Lifetime / SafeHandle / leak (heap, refcount) | ~9 | `nuke validate` is **compile-only**; refcount drift and finalizer leaks need runtime + repeat-call assertions that don't exist today. |
| ABI / calling-convention / wrong-symbol P/Invoke | ~7 | Compiles fine; only crashes when called. BindingTests covers patterns individually but not the *combinations* (cdecl-on-mangled symbol, async-on-generic, vtable-setter export, etc.). |
| Type-lowering / wrong projections (CGImage→IntPtr, nested-protocol prefix, namespace-facade-as-class…) | ~9 | Compiles and even runs; only a *consumer reading the C# surface* notices the projection is wrong. No automated "API-shape" gate. |
| Conformance lowering (Equatable, `Error`→typed exception, conditional generics, `[Obsolete]` fanout) | ~5 | Happy paths covered; conditional/derived cases aren't enumerated. |
| Skip-policy silent drops (tombstones, MultiSpec, DuplicateSig, UnsupportedClosure, optional-as-mandatory…) | ~13 | Compilation **succeeds** when entire APIs vanish. We have no "skip-surface-area" trend gate. |

**Most of these are not regressions — they are original gaps the audit revealed.**
A handful (`missingwrappersymbol-after-wrapper-emit`,
`direct-callconvswift-pinvoke-for-skipped-wrapper`) **are** recent regressions from
the wrapper-emission rework. Either way, every fix lands with a permanent regression
test, so the regression-vs-gap distinction doesn't change the workflow.

## Testing foundation — three layers, all inside BindingTests

The reason existing gates missed these is structural. Two new gate shapes are needed,
not just more cases in the old gates. **Both new shapes live inside BindingTests** —
this is the explicit long-term direction (see "Long-term: retire `nuke validate`"
below).

### Layer A — per-bug regression (existing shape, scaled up)

Every fix ships with:

1. A Swift snippet in `BindingTests/Sources/SwiftBindingsTestLib/` reproducing the
   audit pattern (the actual API shape, not a synthetic toy).
2. A C# assertion in the matching domain file in `BindingTests/RuntimeTestsApp/`.
3. A generator unit test pinning the *bound output shape* — semantic checks
   (`output contains CallConvSwift`, round-trip preserved), not exact string matches,
   per CLAUDE.md.

Non-negotiable per bug. No "covered by an existing test" unless the assertion line
can be pointed at.

### Layer B — skip-surface trend gate, on authored corpus

**Scope: skip-class regressions only.** Layer B is a count-based ratchet over
mechanically-parseable skip markers in generated `.cs`. Shape-class regressions
(wrong projection, missing interface adoption, lost default value) live in
Layer A as targeted semantic assertions, not in Layer B's trend. Trying to do
both in one gate muddles the signal.

Mechanism: parse skip markers from generated `.cs`, write
`.skip-surface-baseline.json`, diff on each run. The gate runs the generator
over a curated `BindingTests/Sources/SurfaceArea/` corpus we author and own.

- One Swift snippet per *skip-class* gap entry, minimized from the audit
  findings. Skip-class entries are those whose primary failure mode is the
  generator emitting a skip marker (or silently dropping the API). Shape-class
  entries (e.g. `swiftarray-at-api-boundary`, `asyncsequence`,
  `cgimage-projected-as-intptr`) get Layer A coverage instead.
- Markers parsed: `// Unsupported:`, `[UnsupportedSwiftType]`, silent type
  tombstones (declared in metadata cookie maps but absent from generated C#),
  `[Obsolete(... SB0001)]`, `// Skipped:` annotations.
- Baseline keyed on `(SurfaceArea-snippet, skip-reason)`.

**Ratchet semantics (explicit):**

- The baseline file `.skip-surface-baseline.json` is committed to the repo,
  same model as `.validation-baseline.json`.
- It is seeded from the *current* generated output of the SurfaceArea corpus
  the day Layer B ships — not empty, not aspirational. Initial baseline reflects
  reality, not the eventual target.
- A new SurfaceArea snippet that produces a new skip key is only allowed when the
  same commit also touches `.skip-surface-baseline.json` to add the key.
- A bundle that fixes a skip-class bug should produce a *downward* delta and
  commit that delta to the baseline.
- CI fails on any *unauthorized* upward count delta or any new key not
  accompanied by a baseline update.

**Implementation**: a post-step inside `nuke binding-tests`, gated behind
`--skip-surface` (or always-on as part of the compile gate, since it's cheap).
**Not** a separate `nuke skip-surface` target. Keeping it inside the BindingTests
flow is a deliberate investment in BindingTests as the durable gate.

**The trade vs. running over real third-party libraries**: authored corpus catches
**regressions on known patterns** but not **new pattern shapes from the wild**.
Discovery of new shapes is what `nuke validate` (and the audit cadence) is for —
see retirement criterion below. Bundle-gating CI only needs the regression check.

### Layer C — lifetime harness, extending existing infra

`BindingTests/RuntimeTestsApp/Lifetime/` already exists with seven test classes
(`OwnershipGCStressTests`, `LifetimeTrackingTests`, `DisposeScopeTests`,
`NegativePathTests`, `OwnershipTests`, `ProxyDisposeTests`,
`ProxyLifetimeTests`). Layer C **extends** this infrastructure rather than
creating it from scratch. New work:

- Add one repro pattern per lifetime bug from the audit (Bundles 1, 3) to the
  appropriate existing test class, or to a new sibling class if the pattern
  doesn't fit.
- Run patterns under a ~10k-iteration loop with `GC.Collect()` between runs.

**Assertions, in priority order:**

1. **Deterministic Swift allocation/deallocation counters** as the *primary*
   assertion. Swift fixtures expose alloc/dealloc counters (e.g. via class
   `init`/`deinit` increment/decrement of a static counter); the harness asserts
   counters return to baseline after each iteration.
2. **`CFGetRetainCount` returns to baseline** for bridged ObjC objects where
   applicable — secondary, more reliable than RSS but still subject to runtime
   noise.
3. **Process RSS does not grow past a budget** — coarse smoke check, not a
   primary signal. RSS is noisy under GC pressure.
4. No finalizer-thread exceptions logged.

**Implementation**: a new `nuke binding-tests --lifetime` flag (does not exist
today). Skipped by default for inner-loop sim runs; runs unconditionally on the
integration serial gate.

This was always going to live in BindingTests — `nuke validate` is compile-only
and physically can't host runtime assertions.

These three layers together turn the audit from "manual quarterly sweep" into a
permanent gate, **all owned by BindingTests**.

## Long-term: retire `nuke validate`

The validate flow exists because we needed a quick "are these libraries still
working?" sanity sweep while the generator was changing rapidly. The long-term
goal has always been to make BindingTests the durable, sole gate. This release
cycle is the first concrete investment toward that — but it's a *transition*
cycle, not the retirement cycle.

**For 0.10.0 specifically**: validate stays in scope as a *targeted* gate for
bundles whose bugs were found only in real libraries (Bundles 8, 9 above). It
is not a blanket per-bundle blocker, and it is not the source of bundle merge
gates for the other seven bundles. But it is also not retired this cycle.

**Retirement criterion (long-term)**: validate is officially decorative when a
full `nuke validate` run surfaces no bug that BindingTests + SurfaceArea didn't
already catch *across multiple consecutive sweeps*. We're not close to that
yet — the audits that produced the 43 docs in this plan ran against real
third-party libraries and found patterns BindingTests had no coverage for.

**Migration path:**

1. **Each skip-class fix in this plan** lands a minimized Swift pattern in
   `BindingTests/Sources/SurfaceArea/`. Each shape-class fix lands its
   regression coverage in Layer A (Swift repro + C# assertion + generator unit
   test) instead — Layer B's count-based ratchet is the wrong shape for
   semantic projection regressions. Over time SurfaceArea becomes the
   consolidated catalogue of every adversarial *skip-class* pattern third-party
   libraries have surfaced; Layer A becomes the corresponding catalogue for
   shape-class.
2. **Future audit findings** route by class: skip-class drops a new
   `SurfaceArea/` snippet as the first step of triage; shape-class adds Layer
   A coverage to the appropriate domain test class. In both cases the
   regression test lands as part of triage, not after the fix.
3. **Validate's role narrows progressively**:
   - 0.10.0: targeted per-bundle gate where applicable, discovery sweep
     pre-release.
   - 0.11.x and beyond: as SurfaceArea matures, drop targeted-validate gates
     bundle-by-bundle when their domain is provably covered by SurfaceArea.
   - Eventually: validate runs as scheduled discovery only, no merge gates.
4. **Retirement happens** when validate stops surfacing surprises that
   BindingTests didn't catch across, say, three consecutive scheduled sweeps.

**Concrete investments this cycle (beyond the bundles themselves)**:

- `BindingTests/Sources/SurfaceArea/` directory + seeded skip-class baseline.
  Bundle 7 contributes its own skip snippets; other bundles contribute their
  own skip-class snippets in the same commit as their fix.
- `--skip-surface` post-step in `nuke binding-tests` + ratchet semantics for
  `.skip-surface-baseline.json`.
- `--lifetime` flag in `nuke binding-tests`, gating new patterns added to the
  existing `BindingTests/RuntimeTestsApp/Lifetime/` test classes.
- `BindingTests/Fixtures/StaticSwift/` synthetic fixture for Bundle 8.
- `--strict` flag adoption for the per-worktree compile gate (existing flag,
  newly-required usage).
- Document the long-term retirement criterion in `roadmap.md` so it persists
  past this plan.

## Concurrency model — bundles + a single serial gate

Existing infra: independent `/tmp/` partitions per worktree (already shipped). The
remaining bottleneck is iOS Simulator + physical-device test execution.

### Per-worktree (parallel-safe, no lock)

Each bundle's worktree runs:

- `nuke compile`
- `nuke test`
- `nuke binding-tests --compile-only --strict` — fail-closed compile gate
  (regenerates bindings, hard-fails on generator non-zero exit, dependency-gen
  exit, or wrapper compilation give-up).
- `nuke binding-tests --class-filter <new-tests-only>` — runtime cases for the
  bundle's new tests. **Without `--skip-regen`**, so the runtime run uses the
  freshly-generated bindings the bundle is supposed to produce. (Runtime-only
  bundles that touch nothing in the generator may still use `--skip-regen`.)

Merges to integration branch `0.10.0-fixes` on green. Per-bundle compile-and-runtime
follows CLAUDE.md: generator/emitter changes need both compile and runtime
verification, not just one.

### Serial gate (two stages, one machine, one queue)

After every bundle merge to `0.10.0-fixes`, run in order:

**Stage 1 — fail-closed compile gate:**
- `nuke binding-tests --compile-only --strict --skip-surface` — regenerates
  across the full BindingTests + SurfaceArea corpus, fail-closes on any
  generator/wrapper failure, evaluates skip-surface baseline drift. Cheap,
  catches bundle interactions that pass independently.

**Stage 2 — full runtime gate:**
- `nuke binding-tests --sim --device --lifetime` — Mono JIT (sim) +
  NativeAOT (device) + lifetime harness.

**Stage 3 — targeted validate (only for bundles where the bug was found in a
real library):**
- Bundle 8: `nuke validate --filter Mappedin`
- Bundle 9: five separate invocations (the existing `--filter` is `name.Contains`,
  not regex/OR):
  - `nuke validate --filter Nuke`
  - `nuke validate --filter Stripe`
  - `nuke validate --filter Lottie`
  - `nuke validate --filter StoreKit2`
  - `nuke validate --filter MusicKit`
- Other bundles: skip stage 3.

This is the targeted-validate compromise (Codex round 1, High #1). Real-library
confirmation only where the bug was *only* found in real libraries; everywhere
else BindingTests + SurfaceArea is the gate. Long-term direction is still to
retire validate, but during the 0.10.0 cycle it remains the only path that
exercises certain real-world distribution shapes.

Run all stages **after every bundle merge**, not only at the end. That way
regressions blame a specific bundle instead of "something landed last week".
Bundles that fail any stage revert from `0.10.0-fixes` and re-enter their
worktree.

### `BindingTests` lock vs. the harder rule

A `flock`-wrapped step on `/tmp/swift-bindings.binding-tests.lock` is cheap and
worth doing for the cases where two worktrees genuinely need to run sim tests
locally. **But the harder rule pays for itself**: worktrees don't run `--sim` or
`--device` *full* gates at all — they run unit tests + new-cases-only filtered
runs. The full gate runs only on the integration branch, serially. Lock-free,
no contention, and the integration gate doubles as the bundle-quality signal.

## Order of operations

1. **Build BindingTests scaffolding** before any bundle lands:
   - `BindingTests/Sources/SurfaceArea/` directory.
   - `--skip-surface` post-step in `nuke binding-tests`.
   - Seed `.skip-surface-baseline.json` from current generated output of the
     SurfaceArea corpus the day Layer B ships (not empty — reflect reality).
   - `--lifetime` flag in `nuke binding-tests` (extends existing
     `BindingTests/RuntimeTestsApp/Lifetime/` test classes).
   - `BindingTests/Fixtures/StaticSwift/` xcframework fixture **plus** test
     class skeleton with the assertion `[Skip]`-attributed. The fixture is
     inert until Bundle 8's same-commit fix removes the `[Skip]` — that way
     the scaffolding doesn't block Bundles 1–7 on an intentionally-failing
     Bundle 8 regression test.
2. **Bundle 1 (SafeHandle/refcount) first.** Highest crash risk; lifetime
   patterns get authored against fixed lifetimes.
3. **Bundles 2, 3, 9** next, in parallel where possible. Bundle 2 (ABI) and
   Bundle 3 (closure/async lifetimes) are correctness gates other consumers
   depend on. Bundle 9 (`@available`) joins this tier because F-2 and F-4 are
   runtime crashes. Bundle 2 should land *before* the SB0001 portion of
   Bundle 7. Bundle 9 includes a targeted validate sweep (Stage 3 of the serial
   gate) for Family F real-library confirmation.
4. **Bundles 4–6** in parallel. They touch disjoint files; conflicts unlikely.
   Bundle 4's `ienumerable-iswiftstruct-raw-intptr-serialization` may need to
   wait on Bundle 1/3 lifetime decisions per its cross-dep note. Bundle 6's
   typed-error and existential items have explicit cross-deps with Bundles 2/3.
5. **Bundle 7** after Bundle 2 (SB0001 cross-dep). Layer B's categorical gate
   gives Bundle 7 most of its leverage. **SurfaceArea ownership**: each bundle
   owns the SurfaceArea snippets for its **skip-class** fixes (regression
   pattern lands in the same commit as the fix). Shape-class fixes land Layer
   A coverage instead, in the appropriate domain test class. Bundle 7 owns
   Layer B *infrastructure* + the SurfaceArea snippets for its own remaining
   skip-policy items only.
6. **Bundle 8** any time after the StaticSwift fixture lands. SDK detect/classify
   layer is disjoint from the emitter bundles. Includes targeted validate
   (Stage 3) against Mappedin.
7. **Final pre-release pass:**
   - Stage 1: `nuke binding-tests --compile-only --strict --skip-surface`.
   - Stage 2: `nuke binding-tests --sim --device --lifetime`.
   - Stage 3: `nuke validate` *full* discovery sweep (not filtered). Surprises
     route by class: skip-class become new SurfaceArea patterns, shape-class
     become new Layer A regression tests, runtime-crash-class blocks the
     release and gets its own bundle. Tracking docs in all cases.
   - Then merge to `main`.

## Definition of done (per bundle)

- All bugs/gaps in the bundle have a fix.
- Each has Layer-A coverage (Swift repro + C# assertion + generator unit test).
- Lifetime-class fixes contribute a pattern to the Layer-C harness in
  `BindingTests/RuntimeTestsApp/Lifetime/`.
- Skip-class fixes contribute a snippet to `BindingTests/Sources/SurfaceArea/`
  and update `.skip-surface-baseline.json` with a downward delta (committed in
  the same change).
- `nuke compile` + `nuke test` pass.
- `nuke binding-tests --compile-only --strict` passes (compile gate).
- `nuke binding-tests --class-filter <new-tests>` passes (runtime gate, no
  `--skip-regen` for generator changes).
- Integration-branch serial gate (Stages 1–2, plus Stage 3 if Bundle 8 or 9)
  passes after the bundle's merge.

## Definition of done (release)

- All nine bundles merged (or items explicitly deferred with rationale noted in
  the source bug/gap doc).
- Full serial gate Stages 1–2 passing on `0.10.0-fixes`.
- Targeted validate (Stage 3) passes for Bundles 8 and 9.
- `.skip-surface-baseline.json` accepted (downward or flat from pre-bundle
  starting point).
- BindingTests + unit test pass counts ≥ pre-bundle baseline.
- Pre-release full `nuke validate` run as discovery sweep. Non-crash surprises
  route by class — skip-class become new SurfaceArea patterns, shape-class
  become new Layer A regression tests — plus tracking docs in either case;
  runtime-crash-class surprises block the release and earn their own bundle.
- `.validation-baseline.json` `cs_compile` + `swift_compile` ≥ pre-bundle
  baseline. Note: the current `Build.Validation.cs` only writes the baseline on
  full unfiltered runs; filtered/targeted validates (Stage 3) are pass/fail
  only and do not update the baseline. The full pre-release sweep is what
  updates `.validation-baseline.json`.
