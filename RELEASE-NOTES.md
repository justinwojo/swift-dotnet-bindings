Apple SDK reach is the primary focus of 0.12.0. Several Apple frameworks that previously had missing core functionality now work end-to-end from C#:

- **MusicKit** binds cleanly across all conformers
- **CryptoKit** `HMAC<H>` and Ed25519 / MLDSA `verify` work on physical iOS — not just the simulator
- **RealityKit** class-bound existential callbacks round-trip; the three-SIMD `Transform` constructor is reachable
- **WorkoutKit** range alerts are constructible from C# without per-framework Swift glue
- **ScreenTime / FamilyControls** `FamilyActivityPicker` resolves at runtime and round-trips its selection
- **Foundation** gains `KVO` (via a new generator emitter) and `AttributedString` (via a small companion xcframework)

It also widens platform reach: bindings now resolve on `osx-x64`, `maccatalyst-x64`, `iossimulator-x64`, and `tvossimulator-x64`, so apps consumed from Rosetta or Intel Macs no longer hit `DllNotFoundException`.

Under the hood, the KeyPath subsystem foundation lands (typed `KeyPath<Root, Value>` singletons for closed conformers), and an ARC cleanup pass closes leaks on error and existential returns.

**Heads up:** `(any Error)?` no longer projects as `Nullable<AnyError>` — see [Source-breaking changes](#source-breaking-changes) below.

## Highlights
- **Real Intel-Mac / x64 RID support** — Bindings consumed on `osx-x64`, `maccatalyst-x64`, `iossimulator-x64`, and `tvossimulator-x64` now resolve a matching native wrapper slice when the source xcframework supplies an `x86_64` slice, so apps consumed from Rosetta or Intel Macs no longer hit `DllNotFoundException`. The generator emits `x86_64` SysV `@_cdecl` thunks alongside `arm64`, the runtime wires Mono x64 (Rosetta) ABI through `swiftcall` C wrappers for the six stdlib generic-collection mutating ops (a workaround for upstream issue 2 — non-blittable `CallConvSwift`), and the Mono interpreter is auto-applied for Mac Catalyst x64 consumers to work around upstream issue 4. `BindingTests` adds `osx-x64` and `maccatalyst-x64` cells.
- **MusicKit binds cleanly with concrete `ResponseAsync` specializations** — Pipeline reordering lets the async-generic-parent return rejection defer to the constrained-specialization engine when the parent is PAT-constrained, and `MusicKit` joins `wrapperImportable`; the two `FilterValue` marker protocols and `MusicLibraryRequestable` are seeded with specialization hints, emitting `response()` as `ResponseAsync` extensions across all seven closed conformers.
- **CryptoKit HMAC<H> resolves on physical device** — On NativeAOT the HMAC<H> conformance-descriptor load went straight to dyld as `@rpath/CryptoKit.framework/CryptoKit`, which a physical device cannot resolve because CryptoKit is a `/System/Library` system framework outside the app's `@rpath`. The resolver now retries a failed dyld-style load via the bare framework name (system path last, verbatim `@rpath` first so app-bundled frameworks are unaffected) and the generator emits the bare framework name for system targets. CryptoKit `HMAC<SHA256>` and `HMAC<SHA384>` incremental == one-shot now pass on both ios-sim and ios-device.
- **Concrete-overload reach into CryptoKit signatures** — Nested-type protocol conformers (e.g. `Curve25519.KeyAgreement.PublicKey`) now emit real concrete specializations instead of generic-only SB0001 stubs; the concrete-specialization preflight admits a `Foundation.Data` indirect return through the `InlineSwiftStruct` allowlist and projects it to a public `byte[]`. MLDSA65 / MLDSA87 context-string `verify` (`Bool` return) and Ed25519 sign-side surfaces bind to concrete overloads end-to-end.
- **RealityKit class-bound existentials + multi-SIMD `Transform`** — `any P` constrained to `AnyObject` or a superclass uses a compact 2-word `[classRef][witnessTable]` register ABI that the opaque 5-word existential path mishandled, so RealityKit existential-proxy callbacks (and audio render handlers) could not round-trip. Parser, generator, and runtime now route those cases through a dedicated class-bound existential path; the multi-SIMD `Transform` constructor and the `EntityTranslationGestureRecognizer.Entity` carrier-identity round-trip pass on iPhone 13 under NativeAOT.
- **WorkoutKit range alerts constructible from C#** — A value-only `Measurement<T>(value, unit)` convenience constructor in the Apple supplement package plus a new `SwiftClosedRange<Bound>(lower, upper)` runtime wrapper in `SwiftBindings.Runtime` 0.12.0 makes WorkoutKit range-alert construction reachable end-to-end without a per-framework Swift trampoline. The `SwiftClosedRange<Bound>` type bridges Swift `ClosedRange<T>` for comparable bounds as parameters, returns, optionals, and arrays.
- **ScreenTime / FamilyControls `FamilyActivityPicker` round-trip** — The SDK pipeline that builds and bundles the per-module SwiftUI bridge xcframework now resolves the picker's native library, so the picker session resolves at runtime and round-trips the selection through `JSONEncoder` / `JSONDecoder`.
- **Foundation KVO via a new generator emitter; `AttributedString` via a new Apple supplement xcframework** — `KvoExtensionEmitter` emits a single `Observe{Prop}` extension method (plus `@_cdecl` shim) per whitelisted `@objc dynamic` primitive property on `NSObject`-rooted, non-generic, non-nested Swift classes — sidestepping singleton-set explosion and closure marshalling for the KVO surface. The new `SbwKvoOptions` flags enum and `KvoToken : IDisposable` in `Swift.Runtime` back the generated observe extensions; callers write `using var token = obj.ObserveFoo(...)` and dispose the token to invalidate (the observation keeps the GCHandle live, so disposal is required). Separately, `AttributedString` ships as a hand-rolled C# `partial` over a new `SwiftBindingsAppleSupplement` xcframework with a UTF-8 byte-buffer ABI, exposing the public constructor and `LanguageIdentifier` without naming `AttributeDynamicLookup` from C# or enumerating every `AttributedStringKey` conformer.
- **KeyPath subsystem foundation** — `AnyKeyPath` / `PartialKeyPath` / `KeyPath` / `WritableKeyPath` / `ReferenceWritableKeyPath` thread through the marshaler, emitter, and runtime as a `SafeHandle`-derived wrapper hierarchy with SBW shims for `AnyKeyPath` equality / hash so dispatch stays Mono-JIT-safe; closed generic instantiations are preserved via `ILLink.Descriptors.xml` so NativeAOT keeps the explicit-interface impls. On top of that foundation, the constrained-specialization machinery emits typed `KeyPath<Root, Value>` singletons for closed PAT-constrained conformers (broadened to protocol-typed bags), with Route C per-`V` keypath-sort specialization for PAT generic parents and a `KeyPathFamily` ABI category for parent-generic methods.
- **`AnyError` is now a self-owning reference type (source-breaking)** — Swift `any Error` is a single `swift_errorRelease`-managed boxed reference, but the previous blittable `AnyError` struct never released the box's `+1` on an owned return, leaking the error on every error-existential return. `AnyError` is now a sealed class mirroring the EC1/EC2 proxy ownership model; owned-transfer sites (returns, `Optional` returns, enum-payload extraction, closure returns) adopt the `+1` and release on `Dispose`/finalize via `SBW_AnyError_Destroy`. **Source-breaking:** `(any Error)?` is no longer `Nullable<AnyError>` — see the *Source-breaking changes* section below.

## Generator improvements
- **Class-bound existential binding support** — `any P` constrained to `AnyObject` or a superclass uses a compact 2-word `[classRef][witnessTable]` register ABI that the opaque 5-word existential path mishandled. Parser, generator, and runtime now route those cases through a dedicated class-bound existential path so they round-trip through generated bindings; `IsClassBoundProtocol` / `IsNSObjectProtocolOnly` walk the full `_allProtocols` list for transitive routing.
- **Cross-module protocol inheritance via vtables** — Local protocols inheriting from a dependency-module parent had no way to reach the parent's vtable: the local witness-table getter was a same-module emission only, and cross-module parent struct slot indices drifted out of sync with the struct field layout because the filter ran before the slot-counter increment. Cross-module parents now resolve through a covariant `IProtocolProxyImpl<TInterface>` lookup, the local `@_silgen_name` WT-getter is suppressed when the parent lives in a dep module so the dep wrapper's symbol stays canonical, and the cctor mirrors the increment-then-filter ordering of the struct emitters.
- **Sibling-protocol property/subscript dispatch via per-vtable lookup** — Class-bound protocols sharing a property/subscript signature now have one owner whose body walks each sibling's vtable until it finds the populated one, instead of force-unwrapping its own (possibly nil) pointer when a smaller-sibling proxy is registered. Owner selection uses module-qualified names so cross-module groups and nested protocols don't collide on leaf name; mixed-generic protocols are filtered from the ownership plan; the owner body guards with `nil`-check + `fatalError` when filtered peers existed so a filtered-only C# implementation surfaces a diagnosable error rather than `SIGSEGV`ing through Swift cross-extension witness resolution.
- **`EveryProtocol` wrapper-emission collisions** — Three latent `swiftc` failures in the generated `EveryProtocol` `Wrapper.swift` were masked on main by the build script's strip-retry loop and surfaced whenever new `EveryProtocol`-conformed protocols were added. Property-emission ownership now lets siblings share a get-only / get+set requirement without the get+set conformance going empty, and the property-type-count and member-kind collision gates scan the union of local + cross-module-parent protocols (with cascade-drop through same-module hops) so a dependency parent and an unrelated local can no longer redeclare each other.
- **Concrete specializations for nested-type protocol conformers** — The concrete-specialization engine rejected any conformer whose module-qualified name had more than two dot segments, so HPKE key protocols whose conformers are nested types (e.g. `Curve25519.KeyAgreement.PublicKey`) only received generic stubs. Nested conformers whose C# type record resolves are now admitted, and each conformer's post-rename C# name is re-resolved at emission since the cached name predates the nested-type-collision rename pre-pass; the same re-resolution is threaded through the keypath-sort specialization path.
- **C# primitives and frozen values as generic arguments** — Every generic parameter previously received a `where T : ISwiftObject` seed, which a C# primitive (Swift `Int` → `nint`) or frozen value type cannot satisfy, so generic Swift types parameterised by `Int` / `Double` / etc. were uninstantiable from C#. The seed is now dropped when every filtered conformance resolves through the unconstrained descriptor-symbol metadata path, mirroring the PWT emitter's resolvable predicate exactly so a method-`Self`-only protocol (which still needs the seed) keeps it.
- **Constrained protocol-extension defaults accepted** — `ProtocolExtensionDefaultsIndex` used to silently drop every extension default with a `where`-clause. If Swift has already accepted `C: P`, a witness chain exists and the validator only needs to confirm "a default covers this requirement" — not re-derive Swift's where-clause logic. The skip cost GRDB's `IndexInfo.Origin` (`DatabaseValueConvertible` via the constrained extension), which dropped `IDatabaseValueConvertible` from the renamed nested type and tripped CS0311. New `BindingTests` fixture (`ConstrainedExtensionDefaultViaRename`) replicates the GRDB shape end-to-end.
- **Constructor admissibility unified** — A single shared predicate now drives constructor admissibility across emitter surfaces (parent-generic constructors via static-factory widening, bound-generic-of-parent ctors, variadic packs, return-type-only overloads), replacing the divergent in-emitter checks that produced inconsistent SB0001 surfaces.
- **CSM advancements** — Parent-only sync and async CSM lands for PAT-constrained generic parents; `Utf8Slice` round-trips end-to-end across CSM and parent-only async; the defensive conformer-constraint filter and rejection tombstones land; CSM dependent-member `SameType` is canonicalised in the where-clause filter; the engine and emitter conformer-reject paths are unified, narrowing enum reject to simple/unemittable; the per-method where-clause filter mirrors into `IsCsmAsyncEligibleForGenericParent`'s pairing loop so the predicate cannot return true on a pairing the emitter would later reject (silent-drop defense).
- **KeyPath singleton emitter** — Consolidated on a shared bag walker; broadened to protocol-typed bags; added Route C per-`V` specialization for PAT generic parents; the trampoline `@available` now includes the `Value` type's floor; unresolvable KeyPath CSM specializations are rejected and `SameType` where parsing is fixed.
- **SwiftUI bridge gating** — The generated `SwiftUIBridge.swift` unconditionally imported `UIKit`, so `swiftc` emitted no Mach-O for the `macos-arm64` slice of the bridge xcframework and MT158 fired at the consuming app step. The Swift file is wrapped in `#if canImport(UIKit)`, the generated C# bridge classes are wrapped in `__IOS__` / `__TVOS__` / `__MACCATALYST__`, and a matching csproj `Compile` condition keeps `macos`-flavored TFMs from referencing bridge types.
- **Async / throwing opaque-existential returns** — An `async -> some P` (or `throws -> some P`) return is boxed to an `any P` existential, but the async harness previously fell through to `MarshalFromSwift<IProtocol>`, which threw `NotSupportedException` — and that exception escaping the `[UnmanagedCallersOnly]` completion callback crashed as a `SIGSEGV`. The existential container is now read and wrapped in the proxy/union exactly like the synchronous `@_cdecl` return path; the async completion callback constructs the existential proxy with `ownsContainer: true`, so it releases the boxed payload's value-witness retain on `Dispose`/finalize — the same owned-return contract as the sync path. The thin `@_silgen_name` opaque-return alias for async/throwing methods is also skipped: it emits a synchronous body that cannot compile and collides on the shared `_async` symbol the harness owns.
- **`let boxed` / `var existential` in witness-dispatch getters** — Gated to prevent a Swift-side compile failure that surfaced under specific witness-dispatch getter shapes.
- **Un-synthesizable existential callbacks fail clean** — A protocol whose `Self` is pinned to a class superclass the synthesized `EveryProtocol` helper cannot subclass exports no witness-table getter from the Swift wrapper, so the C# proxy now suppresses that getter and throws `NotSupportedException` at the C#-to-Swift callback boundary instead of `EntryPointNotFoundException`. Swift-vended existentials still round-trip through their own witness table on return and accept.
- **`Foundation.Data` specializations project to `byte[]`** — The concrete-specialization preflight now admits a `Foundation.Data` indirect return through the `InlineSwiftStruct` allowlist and projects it to a public `byte[]`, emitting real concrete and generic overloads in place of generic-only SB0001 stubs.
- **`macCatalyst` availability floor lifted to iOS** — The C# `@available` attribute now mirrors what the Swift compiler accepts so `macCatalyst` floors stop being mis-projected as platform-unsupported.
- **Higher-kinded KeyPath constraints preserved** — Stripped underscore-protocol conformances are ingested through a dedicated synthesizer instead of being discarded, so higher-kinded KeyPath constraints survive into the binding.

## Runtime improvements
- **Memory management — owned-return cleanup pass**
  - **Optional / Result payload extraction with shape-aware ARC** — The open-coded heap-copy in the Optional / Result extraction paths took no value-witness retain, so reference-backed payloads were over-released or double-freed on dispose. Both routes now go through `MarshalExtractedPayloadValue`, which gates the `+1` and the cleanup branch (ADOPT / COPY / MOVE / read-by-value) on `referenceBacked = ISwiftObject && !IsValueType` — covering SwiftUI bare value wrappers without throwing on blittable value-type structs.
  - **VWT copy-out carriers** — The six value-witness-table copy-out return carriers (`Array`, `Dictionary`, `Set`, `Optional`, `Result`, `FrozenWithMemory`) copied the payload out of the Swift-owned buffer without destroying the source, leaking a retain on every returned class/ref-containing value. Each carrier now copies *then* destroys the source, with decomposed Optional's `Some`-adopt move carved out ahead of the destroy whitelist so it is never double-freed.
  - **Borrowed → owned slot copy** — Borrowed Swift slots are copied into self-owning values before they are freed.
  - **EC2+ composition existential owned returns** — Adopted and released so the boxed payload's value-witness retain is released on `Dispose`/finalize.
  - **Class `Hashable` conformances registered** — On owned existential returns so `GetHashCode` dispatches through Swift's witness.
- **Class-bound existential receiver reads** — Pull only the 1-word handle from `selfContainer` instead of the full 5-word `ExistentialContainer1`; `ProxyLifetimeTracker` uses `SwiftReleaseTrampoline.Release` instead of direct `Arc.Release` across the finalizer boundary; `NewFromPayload` preserves both class-bound existential wire words so foreign Swift/ObjC implementations round-trip through their own witness table.
- **`SwiftMarshal.ThrowSwiftError`** — Releases the Swift error pointer before the managed throw to keep the cleanup off the unwinder.
- **`SwiftFrameworkResolver` retries for system frameworks** — On NativeAOT the HMAC<H> CSM conformance-descriptor load went straight to dyld as `@rpath/CryptoKit.framework/CryptoKit`, which a physical device cannot resolve because CryptoKit is a `/System/Library` system framework outside the app's `@rpath`. The resolver now retries a failed dyld-style load via the bare framework name (system path last, verbatim `@rpath` first so app-bundled frameworks are unaffected) and the generator emits the bare framework name for system targets so the per-assembly `DllImport` resolver is consulted.
- **Mono x64 (Rosetta) `swiftcall` shims** — The six stdlib generic-collection mutating ops have `CallConvSwift` signatures that are non-blittable through .NET (upstream issue 2). `clang`-`swiftcall` C wrappers absorb the Swift calling convention, and `SwiftArray` / `SwiftDictionary` / `SwiftSet` route through them on x64. The matching `x86_64-apple-{macos,maccatalyst}` swiftinterface triples ship from the SDK.
- **SwiftUI hosting bridge `ViewController` property** — Generated bridge `Session` classes only offered a raw `IntPtr GetViewController()`; a typed `ViewController` property (iOS / tvOS / Mac Catalyst) is added so .NET MAUI / UIKit consumers can embed the hosted SwiftUI view without hand-marshalling the pointer. The peer is non-owning (`Runtime.GetNSObject`, `owns:false`) over the `+0` controller the Swift `Session` owns, so lifetime follows normal UIKit rules: embedding transfers ownership to the parent. A `BindingTests` case embeds-then-disposes to lock that contract in.

## Source-breaking changes
- **`(any Error)?` is no longer `Nullable<AnyError>`** — `AnyError` is now a sealed reference type implementing `ISwiftObject` + `IExistentialContainer` so the box's `swift_errorRelease` `+1` is released on `Dispose`/finalize. The reference-type change means `(any Error)?` projects as nullable-reference `AnyError?` rather than `Nullable<AnyError>`. Call sites that wrote `myAnyError.Value` to unwrap a struct-`Nullable` need to switch to a normal reference null check; sites that wrote `myAnyError.HasValue` need `myAnyError is not null`. The wire ABI is unchanged.

## Apple supplement (26.2.4)
- **New `SwiftBindingsAppleSupplement` xcframework** — A small Swift shim library that ships alongside the managed `SwiftBindings.Apple` package, exposing a UTF-8 byte-buffer ABI for `AttributedString`. The xcframework lands per-arch slices for `ios-arm64`, `ios-arm64_x86_64-simulator`, `macos-arm64_x86_64`, `ios-arm64_x86_64-maccatalyst`, `tvos-arm64`, and `tvos-arm64_x86_64-simulator`.
- **`AttributedString` constructor and `LanguageIdentifier`** — Hand-rolled C# `partial` in the Apple package over the new supplement xcframework, exposing the public constructor and `LanguageIdentifier` without naming `AttributeDynamicLookup` from C# or enumerating every `AttributedStringKey` conformer.
- **`Measurement<T>(value, unit)`** — Value-only convenience constructor on the Apple package's `Measurement<T>` so consumer code constructing `Measurement<UnitDuration>` etc. doesn't need a per-framework Swift trampoline (which is what makes WorkoutKit range-alert construction reachable end-to-end). The native `SBW_Measurement_*` entrypoints it dispatches to live in the core `SwiftBindings.Runtime` 0.12.0 dylib, not the supplement xcframework.
- **`AnyError` sealed class in the Apple package** — The C# `AnyError` sealed class (implementing `ISwiftObject` + `IExistentialContainer`) that backs the source-breaking ownership change lives in `SwiftBindings.Apple` 26.2.4; the `SBW_AnyError_Destroy` shim it disposes through lives in the core `SwiftBindings.Runtime` 0.12.0 dylib.

## Developer experience
- **`nuke binding-tests` x64 cells** — `osx-x64` and `maccatalyst-x64` cells run alongside the existing `arm64` matrix; the Mono interpreter is the default on `maccatalyst-x64` (works around upstream issue 4 — Catalyst x64 instability).
- **`X64PackGate` and `X64SimGate` end-to-end gates** — Two durable opt-in `nuke` targets that fail closed if a wrapper xcframework drops an x86_64 slice. `X64PackGate` verifies fat wrapper / source packaging plus Rosetta consumption on `osx-x64` end-to-end. `X64SimGate` verifies `iossimulator-x64` and `tvossimulator-x64` consumer packaging for both third-party and Apple-framework bindings. The fat wrapper is built through a shared per-arch compile + `lipo`-merge driver that degrades to the primary arch when an extra-arch fold fails rather than dropping the wrapper.
- **Apple-supplement build linearized into the Pack spine** — For NUKE strict-graph: the supplement xcframework build is a real dependency of `Pack`, so `Pack` cannot run before the supplement is staged. `PackGate` sim-slice expectations are corrected to fat universal wrapper names for the Apple-framework direct mode.
- **Generator pack cleanups** — x86_64 sim wrappers pack for Apple-framework direct mode; `PackGate` corrects sim-slice expectations; the apple-framework dep targets stop double-counting in the validation Overall tally.
