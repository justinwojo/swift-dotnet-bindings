# Critical Architectural Constraints

These are "trap" constraints — easy to accidentally violate, hard to discover from code alone.

- **BitwiseCopyable in Swift 6+**: `storeBytes(of:as:)` requires it. Classes: `Unmanaged.passRetained().toOpaque()`. Structs/enums: `initializeMemory(as:repeating:count:)` — this properly handles ARC retain/release for non-trivial types (NOT a bitwise copy).
- **Optional closures are always escaping**: In Swift, `Optional<Closure>` is always escaping (no `@noescape Optional<Closure>`). The ABI parser doesn't propagate `escaping` to closures inside Optional — check `IsOptionalClosure()` alongside `IsEscaping` for GCHandle lifetime decisions.
- **ABI nested type naming**: ObjC enums in ABI JSON use nested forms (`AVCaptureSession.Preset`), NOT flattened ObjC names.
- **ModuleEmissionContext threading**: ALL code paths creating `WrapperEmitter` in `MethodHandler` MUST pass `context.GetEmissionContext()` to avoid dedup failures. Also applies to `Utf8SliceEmitter.EmitIfNeeded`/`EmitFreeIfNeeded`.
- **Tj dispatch thunks**: Non-final class instance methods need `Tj` suffix. Gates: `!classParent.IsFinal && !methodDecl.IsFinal && !methodDecl.IsExtensionMethod`. Extension methods use static dispatch and have no vtable entry — never append Tj for them.
- **Bool P/Invoke**: All `== "bool"` comparisons use `MarshallingHelpers.IsBoolType()`. Parameter-level: `[MarshalAs(UnmanagedType.U1)]`.
- **Overload/dedup key consistency**: THREE projected-key builders must stay structurally identical — `IHandler.GetProjectedCSharpMethodKey` (:558), `ProtocolSignatureHelper.GetProjectedCSharpMethodKey` (:114), and `DefaultParameterOverloadEmitter.GetProjectedOverloadKey` (:692). All three key off the same `{GetPublicMethodName(...)}({projected,param,types})` shape and ALL must thread the sibling-`propertyNames` set — the `Foo`→`FooMethod` property-collision rename is part of the projected name, so a builder that drops it produces a key that collides with a method emitted under a different C# name. 27 invocation sites across 15 files (`grep -rn 'GetProjectedOverloadKey(\|GetProjectedCSharpMethodKey(' src/Swift.Bindings/src --include='*.cs' | grep -v 'string GetProjected'`). This is the projected-C# / fillability key domain — NOT the reverse-dispatch vtable SLOT key, which lives in a separate axis sourced from `VtableLayout` (see next entry). Don't conflate them: the vtable-slot axis keys off the label-inclusive `GetMethodKey` and must NOT collapse on the projected key.
- **Reverse-dispatch vtable slot layout has ONE source — `VtableLayout`**: Every walk that lays out or fills a reverse-dispatch vtable renders/looks up `new VtableLayoutBuilder(_typeDatabase).Build(protocol)` instead of re-deriving membership/index/width (the Finding-8 / Bug-21 overhaul). LAYOUT walks — the Swift `{P}_vtable` struct (`EveryProtocolEmitter.EmitProtocolVtableStruct`), the C# `{P}SwiftVTable` / `{P}LocalVTable` mirrors (`ProtocolProxyEmitter.Vtables.cs`), and the EveryProtocol extension body — iterate `layout.IncludedSlots` (membership + declaration order) and read `slot.SlotIndex` / `slot.Width`. FILLABILITY walks — receivers (`ProtocolProxyEmitter.Receivers.cs`), the same-module and cross-module-parent cctor assignment loops (`ProtocolProxyEmitter.StaticInit.cs`) — take the slot index from `layout.MethodSlotIndexByKey` but KEEP their own fillability filters (`_skippedMethodKeys`, `emittedRawKeys`, `emittedCSharpKeys`) to decide whether to actually FILL the slot. Slot identity is the label-inclusive, async-sensitive `EveryProtocolEmitter.GetMethodKey` — a DIFFERENT domain from the projected-C# overload key above: the layout axis KEEPS a slot for an AnyType-unprojectable member and gives each raw-distinct existential overload its OWN slot (no projected collapse). Gating layout on the projected key or the skip sets shrinks the C# struct below Swift's and shifts every later field — the slot-corruption that only SIGSEGVs on the NativeAOT device leg. Membership is one oracle: `ProtocolVtableMembers.Includes{Property,Subscript,Method}` delegate to `VtableLayoutBuilder.Classify*`. Index rules the model reproduces exactly: ctor/static/@objc-optional consume NO index (pre-skip → `SlotIndex` -1, ABSENT from `MethodSlotIndexByKey`, so the fillability walks must pre-skip the same three BEFORE the indexer lookup or it throws); non-dispatchable-closure / method-generic / Self-typed / mixed-generic methods and non-static excluded subscripts are skip-but-consume (index consumed, no field); a static subscript consumes none; a raw-key duplicate collapses onto the earlier slot. Pinned by `VtableLayoutBuilderTests`; cross-artifact field-name parity by `ArtifactParityGate` Gate 3. STILL hand-allocating this same index axis (owner-gated follow-up, NOT folded into the model — already single functions, byte-identical to it today): `EveryProtocolEmitter.EnumerateProtocolMethodsForDispatch` and `EnumerateIndexedSubscripts` (closure-thunk-naming / fan-out-plan helpers).
- **Collision-suffix override adopted-name reservation is declaration-order independent**: When a derived class overrides ONLY a collision-suffixed base overload (e.g. `process(second:)` → base `Process2`), it ADOPTS the ancestor slot's emitted name instead of recomputing from its own suffix-free context. `IHandler.PreReserveAdoptedOverrideNames` walks the type body BEFORE the main dedup loop and reserves that adopted projected key up front, so an unrelated new sibling whose own projected name would also be `Process2` is pushed to `Process22` regardless of source order. The inline reservation inside the main loop is a fallback only — relying on it alone is order-dependent: if the new sibling is declared first it claims `Process2`, the override's later `HashSet.Add` no-ops, and BOTH emit `Process2` → CS0111. Both guards on the pre-pass are load-bearing: it runs `ValidateMethodEmission` so a skipped method never reserves a key (the validation-before-dedup invariant), and it only pre-reserves when the projected key is locally unique (count == 1) so a derived class overriding BOTH overloads still self-suffixes in the main loop. A THIRD load-bearing detail: the pre-pass keys must use the SAME closure-tombstone view the main loop will take. The loop sets `IsClosureParamTombstone` (which collapses unsupported closure params to `object?` in `GetProjectedCSharpMethodKey`) only AT the dedup site, AFTER the pre-pass runs — so the pre-pass predicts it via `ClassifyOverridePrePassEmission` (which validates the method once and returns both whether it will emit AND the would-be-tombstone view) and passes `treatAsClosureTombstone: true`. Reading the bare field in the pre-pass keys a future-tombstone override off its un-collapsed Swift closure shape while the loop dedups on `object?`, so the collision the reservation exists to catch slips through (a closure-tombstone-only manifestation of the same key/name divergence as P1-21). A FOURTH detail ties the count gate to the same classifier: the local key-count multiset is built over the EMITTING partition only (`ClassifyOverridePrePassEmission` again) — a validation-skipped non-tombstone sibling that shares an override's projected key (e.g. one skipped solely for an unsupported RETURN, which the return-insensitive key still matches) must be EXCLUDED, or it inflates the count past 1 and suppresses a valid pre-reservation, letting an earlier-declared natural sibling steal the adopted slot (CS0111). BindingTests Scenario E (`CollisionOverrideDerivedSiblingFirst`) is the durable reverse-order gate; the pre-pass/main-loop key agreement is pinned by `ClosureParamTombstoneEmitterTests.GetProjectedCSharpMethodKey_PrePassTombstoneView_MatchesMainLoopFlagView`, and the emitting-partition exclusion by `ClosureParamTombstoneEmitterTests.ClassifyOverridePrePassEmission_ValidationSkippedSibling_ExcludedFromEmittingPartition`.
- **C# `@` verbatim identifiers**: `@` at START is valid, AFTER other chars is INVALID. Compound variable names need `StripVerbatimPrefix` before prepending.
- **WasEmitted flag**: Set at 23 emission points across 12 files (MethodHandler x9, PropertyHandler x3, ConcreteProtocolSpecializationEmitter.Async x2, then x1 each: ConcreteProtocolSpecializationEmitter, ConcreteProtocolSpecializationEmitter.AsyncGenericParent, AsyncMethodGenericBridgeEmitter, MethodGenericBridgeEmitter, GenericClosureBridgeEmitter, KeyPathBagValueSpecializationEmitter, MethodClosureBridge, NestedClosureBridge, ProtocolExtensionClosureBridge). Required by `HasMethodInResolvedAncestors`/`HasPropertyInResolvedAncestors`. Canonical count: `grep -rn '\.WasEmitted = true;' src/Swift.Bindings/src --include='*.cs'` — do NOT count the `bool WasEmitted = true` record-default in IMethodBridgeEmitter.cs or the `<c>WasEmitted = true</c>` doc-comment in ClosureParamTombstoneEmitter.cs (neither is an assignment). Pinned by a guard test in Swift.Bindings.Unit.Tests.
- **ProtocolExtensionEmitter pipeline timing**: MUST happen AFTER `typeDatabase.AddModuleDatabase()` and BEFORE `stringEmitter.EmitModule()`.
- **Generic protocol extension ABI**: TWO TypeMetadata per generic param (explicit T.Type + implicit trailing). `IsProtocolExtensionMethod` controls P/Invoke param ordering (self_ first). PInvokeHelperContext metadata MUST be suppressed for protocol extension methods.
- **Swift iterator Arc.Retain**: Non-mutating P/Invoke returning reference to argument needs `Arc.Retain` before the call.
- **Projection parity pattern**: When adding a new `ITypeProjection`, implement `Visit()` methods on `AccessorGetterConversionVisitor`, `AccessorSetterConversionVisitor`, and `OptionalAccessorGetterVisitor` (compile-time exhaustive via `IProjectionVisitor<T>`). Also implement `GetReturnPlan()`/`GetParameterPlan()` on the projection. PropertyHandler and SubscriptHandler are safe (visitor pattern). ProtocolProxyEmitter.Receivers still uses switch with `_ => null` fallback — check manually.
- **Mixed composition existential guard**: ObjC filtering can drop protocols -> size mismatch. Guard `filteredCount == originalCount` in 5 locations.
- **Closure two-layer gate**: Layer 1 (`IsSupportedClosureParameterType`) decides if method emits. Layer 2 (`IsCdeclCompatibleType`) decides if `@_cdecl` wrapper is generated. `.All()` not `.Any()`.
- **WitnessDispatchEmitter branch order**: String FIRST (Swift.String is a frozen+RefFields struct). Property dispatch must check `IsTypeBlittable || IsStringType` directly (NOT `IsPropertyGetterDispatchable`).
- **IReadOnlyDictionary invariance**: Element conversions in containers need explicit cast `(IProtocol)new ProtocolProxy(v)` -- unlike covariant `IReadOnlyList<T>`.
- **GetPublicMethodName name-shaping args**: signature is `GetPublicMethodName(methodName, isAsync, hasReturnValue, propertyNames, isSelfReturning, parentTypeName, parameterCount)`. `parameterCount = 0` controls the "Get" prefix, but it is NOT the only collision-shaping argument: `propertyNames` (sibling-property set → drives the `Foo`→`FooMethod`/`WithFoo` rename) and `parentTypeName` (reserved-identifier / parent-name collision) ALSO mutate the returned name. The authoritative emitted name therefore folds in a property-collision rename, a numeric collision suffix (`CollisionIndex`), AND — for a derived class that overrides only a collision-suffixed base overload — an adopted ancestor-slot name (`AdoptedOverrideCSharpName`), none of which the dedup keys or the same-module override verifier independently recompute — the P1-21 root cause. `MethodEnvironment.CSharpMethodName` is the single source of truth; recomputing the name through a fresh `GetPublicMethodName` pass (as `ExistentialBypassEmitter` once did) drops those axes. All 23 call sites across 11 files must pass `propertyNames`/`parentTypeName`/`parameterCount` consistently, not just `parameterCount` (`grep -rn 'GetPublicMethodName(' src/Swift.Bindings/src --include='*.cs' | grep -vi 'string GetPublicMethodName('`).
- **nint->int narrowing safety**: Properties ARE narrowed. Method return types are NOT narrowed (C# overload resolution prefers `int` overloads -> silent 64-bit truncation). Protocol receiver getters widen int->(nint) for 8-byte ABI; setters narrow.
- **Cross-module proxy class qualification**: Use `GetQualifiedProxyClassName()` (not `GetProxyClassName()`) when emitting marshalling code. ALL `ProjectionContext` creations must include `CurrentModuleName`. Proxy ExistentialContainer constructor is `public` for cross-assembly access.
- **IsOptionalObjCBridged parity with TypeProjectionFactory**: Must match exactly. ObjCRooted does NOT use IntPtr (uses SwiftOptional<T>). Both fallbacks use `AppleFrameworkRegistry.IsOptionalFallbackModule` + `!IsNestedType` + `!IsKnownAppleValueType` + `HasObjCClassPrefix` — must stay in sync.
- **AppleFrameworkRegistry is the single source of truth** for Apple framework heuristics: module sets (AutoBridge vs OptionalFallback), value type exclusions, ObjC prefix detection, type name remapping, pointer/nested type detection. Data loaded from `apple-frameworks.json` at startup. `TypeDatabaseExtensions.IsObjCModuleType` delegates to it.
- **XML value-type remap entries must use kind="struct"**: Types must be `kind="struct"` (NOT enum) in XML databases. Using `kind="enum"` causes the generator to emit enum member references that don't exist. Only entries that are genuine ObjC enums with `rawValueType` should be `kind="enum"`.
- **NSUnderlineStyle excluded from XML intentionally**: Adding `UIKit.NSUnderlineStyle` to UIKitDatabase.xml makes it resolvable on the SwiftTypeName path, causing tuple P/Invoke raw type mismatch. Enforced via `excludeFromXml` in `apple-frameworks.json`. Keep in `AppleFrameworkRegistry.ValueTypes` and `TypeNameRemaps` only.
- **SwiftUI two-path suppression**: SwiftUI types gated at Path A (TypeDatabaseExtensions) and Path B (MemberEmissionValidator). When adding new SwiftUI stubs: (1) create ISwiftObject stub in Swift.Runtime, (2) register in SwiftUIDatabase.xml.
- **Validation cache invalidation**: `nuke validate` caches in a branch-specific `/tmp/binding-validation-<branch>/` dir. Use `rm -rf /tmp/binding-validation-$(git rev-parse --abbrev-ref HEAD | tr '/' '-')` before full validation when generator source has changed.
- **Conditional extension constraint gates**: Consolidated in `MemberValidationPipeline` Phase 4 for methods via HandleBaseDecl. PropertyHandler retains accessor-level `HasUnsupportedProtocolConstraints` for property accessors not covered by the pipeline. `ShouldSkipConstraint` exists only in `BoundGenericsHandler`.
- **ConformanceGraph**: `IsParentSelfReference` guard -- only depth-0 generic params (`t_0_X`) resolve via graph, depth-1+ skip. `CreateTypeSpec` DependentMember fix: `node.Name == "DependentMember"` inside `kNominal` case produces `AssociatedTypeReferenceSpec`.
- **Complex enum closure heap allocation**: Must use `UnsafeMutableRawPointer.allocate` + `initializeMemory` (NOT `withUnsafePointer` -- stack pointer incompatible with `NativeMemory.Free`).
- **Protocol extension param gate lifts**: Throwing regex `(?<!\bre)throws(?!\s*\()` excludes rethrows/typed-throws. PAT and Self-requirement protocols ARE rejected for existential params. Optional recursion hardened to reject `Optional<BoundGeneric>`.
- **Throwing closure simplification**: `ThrowingClosureSimplificationEmitter` via `IMethodPostProcessor`. Gates: skip constructors, accessors, async, missing symbols, method-level generics. Dedup via `EmittedProjectedSignatures`.
- **Underscore-prefix suppression**: Structurally required `_`-prefixed types (superclass/protocol of non-`_` type) are NOT suppressed. Uses module-qualified names (`SwiftTypeName.ToString()`).
- **Closure return-marshalling parity**: `BuildCallbackReturnStatement()` in `ClosureEmitter.cs` is the single source of truth for callback return type conversion. Both `EmitEscapingClosureCallback` and `EmitThrowingClosureCallback` delegate to it.
- **`ISwiftObject` seed-drop mirrors `isResolvable`**: `GenericTypeEmitter.GetWhereClause`'s "descriptor-path-safe" (seed-droppable) set MUST exactly mirror `PInvokeHelperEmitter`'s `isResolvable = !HasAssociatedTypes && !HasSelfRequirement`. A conformance is seed-droppable iff its PWT arg routes through the unconstrained `TypeMetadata.GetTypeMetadataOrThrow<T>()` descriptor-symbol path — i.e. `HasAssociatedTypes || HasSelfRequirement`. A `HasMethodSelfTypeParams`-ONLY protocol is RESOLVABLE (neither flag) → emits `ProtocolWitnessTable.GetOrThrowAuto<T, IFoo>()` which requires `T : ISwiftObject` → seed must be KEPT (conservative). Check `HasSelfRequirement` BEFORE `HasMethodSelfTypeParams` so a protocol carrying both is treated as droppable. Dropping the seed for a method-Self-only protocol produces CS0314; the two readers of `TypeRecord.Flags` must move together.
- **Consumer-targets wrapper/bridge refs use the "will be produced" signal, not "exists now"**: `BindingsGeneratorCommand` passes `HasWrapperXCFramework = hasWrapperXcfw || wouldCompileWrapper` (and `HasBridgeXCFramework = hasBridgeSwift`) to `ConsumerTargetsEmitter` — NOT the bare `hasWrapperXcfw`/`hasBridgeXcfw` "exists now" flags. Under the SDK's two-pass flow the full-generate pass runs with `--skip-wrapper-compilation`, so neither xcframework exists when the consumer `.targets` is written; `_CompileSwiftWrapper` produces the wrapper in a later pass. Gating the `NativeReference` on "exists now" silently drops it for every third-party `SwiftFramework` binding consumed via `PackageReference` → `DllNotFoundException` at runtime. The Apple-framework path doesn't hit this because `_SynthesizeAppleFrameworkConsumerTargets` (Sdk.targets) re-emits the targets post-compile, but it only runs when `@(SwiftAppleFrameworkTarget) != ''`. The emitted refs carry an `Exists()` guard, so emitting one the deferred pass fulfills is safe.
- **Wrapper CPU-arch decision is shared, not per-call-site**: `--target-architectures` (`SwiftTargetArchitectures`) drives a fat wrapper via `TryDecideWrapperArchitectures` → `CompileWrapperForArchitectures` (primary compile + per-extra-arch `lipo`-merge). BOTH the `--compile-wrapper-only` fast path (`RunCompileWrapperOnly`) and the standalone generation path (`BindingsGeneratorCommand`) must route through these — duplicating the compile inline in one path silently ignores the option there. Three traps in the decision: (1) the `auto` primary arch must be pinned, never left null when x86_64 is involved, because a null primary defers to `SelectArchitecture`, which prefers an exact `"arm64"` and otherwise returns the slice's FIRST arch. An x86_64-*only* source must pin `primaryArch="x86_64"` (a null primary would resolve to x86_64 AND schedule an extra x86_64 pass → same-arch `lipo`); an arm+x86_64 source must pin the primary to a concrete arm arch (`"arm64"`, else the `"arm64e"` present) and fold x86_64 as the extra — otherwise an `arm64e+x86_64` slice that lists x86_64 first resolves the primary to x86_64, drops arm64e, and (via the degrade-on-fold-failure path) ships an x86_64-only wrapper; (2) base the auto decision on the **simulator** slice's archs (`ResolveAutoArchBasis`) — x86_64 only ships there, so a `--platform-target device` resolution otherwise drops it; (3) `$(SwiftTargetArchitectures)` MUST be in BOTH SDK fingerprint echoes (Sdk.targets XCFramework-mode + Apple-framework-mode) or flipping it reuses a stale arm64-only wrapper (`_SwiftWrapperSkip` keys off the fingerprint); (4) `CompileWrapperForArchitectures` moves the built primary wrapper aside before `lipo`-folding extra arches — that aside→merge→restore dance MUST `try`/**`catch`**/`finally`: the `finally` restores the primary on disk, and the `catch` SWALLOWS the extra-arch failure (logs a warning, does NOT rethrow) so the method returns the **non-null primary** `compilationResult`. Restoring the disk is not enough on its own: the SDK `--compile-wrapper-only` caller (`RunCompileWrapperOnly`) wraps the call in its own `try/catch`, so a propagated exception leaves `compilationResult` null and then computes `hasWrapperXcfw` off that null — recording `_SwiftBindingHasWrapperXCFramework=False` even though the restored wrapper sits on disk, which drops the consumer `NativeReference` for EVERY arch (arm64 included → `DllNotFound`). Returning the primary result keeps metadata truthful: a failed x86_64 fold degrades to a primary-only wrapper (consistent with the SDK's existing `sdkMode` warning-not-fatal contract for a primary wrapper failure), not a dropped wrapper.
- **Stale generator binary masks your edit**: `nuke binding-tests` AND `nuke validate` invoke the generator from the prebuilt `GeneratorDll` — `src/Swift.Bindings/src/bin/Debug/<tfm>/Swift.Bindings.dll` (`Build.Validation.cs:24`). `EnsureGeneratorBuilt` (`Build.BindingTests.cs:481`) only builds when that dll is **missing** (`!File.Exists`) — it never rebuilds a *stale* one. So after editing generator source, the gates silently run the OLD compiled generator. Symptom: post-patch regen emits pre-patch output even after a clean `output/` wipe, and the bug looks like your patch "didn't take." Fix: `dotnet build src/Swift.Bindings/src -c Debug` before running the gate (or check the Debug `.dll` timestamp) — don't debug the patch logic first. `nuke compile` builds the whole solution and also refreshes it.
- **Emission-time symbol promotion lives on a side table, never on `MethodDecl.MangledName` (AF13)**: `MethodDecl.MangledName` is `init`-only (`Model/TypeDecl/MethodDecl.cs`) and is the **immutable parser ABI fact** — the `@_silgen_name` symbol. Emission must NEVER mutate it; reverting it to `set` re-opens the in-place mutation channel this refactor closed (pinned by `MethodEmissionSymbolSideTableTests.MangledName_IsInitOnly`, which asserts the compiler-generated setter carries `IsExternalInit`). The emission-time *promoted* symbol (cdecl-wrapper / dispatch-thunk / async-bridge steering symbol) lives on `MethodEnvironment.EmissionSymbol` (`Marshaler/IEnvironment.cs:99`), defaulted to the decl's silgen symbol **at env construction** and re-targeted via `internal PromoteSymbol(symbol)` (`:108`), which returns the previous value so the former `save MangledName → mutate → restore-on-fallback` protocol becomes a **local value round-trip** (`var saved = env.PromoteSymbol(x); … env.PromoteSymbol(saved);`) with no shared-decl mutation to leak across methods. ~33 `PromoteSymbol` call sites across the emitter handlers (`grep -rn 'PromoteSymbol(' src/Swift.Bindings/src --include='*.cs' | grep -v 'internal string PromoteSymbol'`). **Two reader classes — choose the right source when adding emission code:** readers of the *promoted* symbol read `env.EmissionSymbol` (the P/Invoke `EntryPoint` via `PInvokeEmitter`, the `NameProvider.GetPInvokeName` hash that names the C# extern, the `@_cdecl` symbol emitted into the wrapper, the `MethodGenericBridgeEmitter`/`AsyncMethodGenericBridgeEmitter` P/Invoke + async-callback field/method names, closure invoke-thunk keys); readers of the *original silgen* symbol (dispatch-thunk resolution, native-thunk internals, demangling, diagnostics) KEEP reading `methodDecl.MangledName`. Picking the wrong source silently shifts a symbol name and surfaces as a runtime `EntryPointNotFoundException`/`DllNotFound`, not a compile error. **Env-less cross-emitter consumers** (e.g. `ConcreteProtocolSpecializationEmitter`, which builds a per-overload hash but has no `MethodEnvironment`) read the promoted symbol from the `ModuleEmissionContext` per-method side table — `GetMethodEmissionSymbolOrMangled(method)` (`ModuleEmissionContext.cs:1169`), populated at the base-handler post-emit hook `RecordMethodEmissionSymbol(methodDecl, env.EmissionSymbol)` (`IHandler.cs:538`, gated identically to `EmittedCSharpName`, i.e. only for emitted methods). That dictionary is keyed by **reference identity** (`ReferenceEqualityComparer.Instance`, `:1148`) because `MethodDecl` is a `record` — value equality would let a `with`-cloned or value-equal sibling resolve to the wrong method's promoted symbol — and falls back to `methodDecl.MangledName` when unrecorded (an un-promoted method correctly reads its silgen symbol). The recorder and the consumer MUST share the same `ModuleEmissionContext` instance (threaded via `context.GetEmissionContext()`). Behavior-preserving: the whole diff was bake-verified byte-identical against pre-refactor generated output.
